# UI/UX 设计师职责说明

当产品指出桌面界面的问题或给出新的产品目标时，本角色把目标转成可讨论、可检查的布局与操作方案，让产品、客户和实现者看到用户如何完成任务。

职责包含桌面布局、交互路径与状态、HTML 设计原型、设计规范和产品联合评审。具体交付见 [feature-map.md](feature-map.md)；文档和原型属于本角色自己的 `docs/design/`，后续变更与问题记录分别使用 `docs/change/`、`docs/fix/`。

产品提供目标、用户任务、优先级和产品评审依据；设计师提供独立设计判断和可验收口径；项目管理协调分歧、主持会议并审核跨角色影响；桌面应用等实现角色按客户确认的方案接入正式产品。整体协作以[项目架构](../项目管理/docs/architecture.md)为准，本角色不改其他角色资料。

本角色没有业务源码或运行时 API 的主属主权。正式界面的代码位置与能力应在具体设计中核对后只读引用；初始角色定义不预填未验证实现事实。原型使用演示数据，浏览检查只能验证原型，不能证明业务链路通过。

当前已交付 [ANS 页面设计 v2](docs/design/2026-10-13_design_ans-uiux-interaction-v1.md)，聚焦对话优先、辅助抽屉边界与角色当前工作。浏览器检查由PM执行并已回传实际覆盖；产品第二轮意见已在本固定上下文修订为v2，产品推荐设计方向；全部原型动作均为本地模拟。

客户授权实施后，本角色按[实现验收清单](docs/design/2026-10-13_design_ans-uiux-implementation-acceptance.md)核对实际界面。候选版本、离线/真实环境及证据覆盖分别记录；发现缺陷交PM协调属主修复，本角色不改生产实现。

客户要求重新验收当前页面时，本角色对照实际候选、v2和真实体验独立记录差距；接受局部参数取舍不等于认可整体完成度。当前见[提交9e50aac重验收](docs/design/2026-10-13_design_uiux-reacceptance.md)，源码缺口与实际视觉/交互观察分别记录。
