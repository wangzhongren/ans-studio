# 查看工作和资料时，仍能继续对话

用户先读助手答复，再决定是否展开执行记录；点击角色资料时先看到这位角色正在处理和排队的内容，职责全文留在下面按需展开。资料覆盖部分历史，但输入、发送、停止始终保留。这里提出设计方案；撰写时正式应用未实施、未测试、未部署。该设计经客户授权实施后，两批改动（按设计对齐、虚拟行锚点修复）形成的最终候选已于 2026-10-14 经本角色独立复核通过，见文末「2026-10-14 增补」。

[打开当前 v2 HTML 原型](2026-10-13_design_ans-uiux-prototype-v1.html)。当前版本为 v2；为避免误引用，原型与说明沿用首稿的 `-v1` 稳定文件路径，以页面顶部、标题及本文版本为准。原型是单文件，CSS/JS 内置，不读取项目数据，不调用业务/API，不发起模型任务，也不写 `.env`。顶部独立条明确「设计原型 / 模拟状态」，全部数据与动作只属于本地演示。原型中的确认不授权任何治理变更。

## 布局与交互的三个决定

### 1. 抽屉底边与 composer 的上边对齐

原有两栏保留：左栏 272px，聊天区为剩余宽度。两枚资料/Pi 入口仍在右上标题栏。抽屉为非模态覆盖层，不占 grid 列、不挤压聊天，不遮挡输入区。打开抽屉后用户仍可以输入、发送和停止；关闭不产生聊天消息。

| 部位 | 1360×860 | 960×620 |
| --- | --- | --- |
| 标题栏 | 高 36px | 高 36px |
| 左栏 | 272px | 272px |
| 聊天列 | 1088px | 688px |
| 聊天头 | 高 66px | 高 66px |
| composer 区 | 底部 100px | 底部 100px |
| 覆盖抽屉 | 宽 360px；top 36px；bottom 100px | 相同，保留 328px 未覆盖历史宽度 |
| 抽屉头 | 高 66px；单标题、单关闭 | 相同 |
| 抽屉内容 | 独立滚动；可用高度 658px | 独立滚动；可用高度 418px |

360px 抽屉足以单列呈现四个 Pi 字段，代价是窄窗打开时遮住较多历史；保留覆盖式骨架的前提下，清晰关闭、Esc 和不中断输入是主要补偿。原型不以整窗横滚补宽度，长路径自动换行，代码仅容器内横滚。外部原型画布缩放属于演示条功能，不是正式应用方案。

Pi 仅一个「Pi 配置」标题和一个关闭按钮。保存位置放在正文次级独立行；保持 `ANTHROPIC_AUTH_TOKEN`、`ANS_PI_BASE_URL`、`ANS_PI_MODEL` 和高级 `ANS_PI_CONTEXT_WINDOW` 原字段名。保存说明与「保存到 .env」按钮保持设置上下文；「配置已齐备」不表述连接验证通过。单纯关闭不保存。

### 2. 常规执行记录折叠，异常作为分组边界

用户消息、助手答复、交互卡为主体；相邻的同角色、同轮常规活动进入「查看执行记录 · N 条活动」。N 指原活动条数，不是成功次数，不假定调用与结果一一配对。展开后保留原始顺序、操作名、目标和真实状态，不展开文件正文或大输出。

组在用户消息、助手答复、失败、拒绝、未决卡和角色变化处结束。异常直接留在原对话位置，两侧可以是不同常规组。未知回放显示「状态未记录」，折叠入口额外说明含未知状态；调用发起仅写「调用发起」。示例中的退出码、读取返回、文件不存在只有在模拟数据明确提供可靠结果时才展示，不从 accepted 或文件路径推断。

工作中没有可靠当前动作字段时只写「正在工作」。轮末常规组默认收起；用户打开的组在实时更新和轮末保持展开。普通助手追问仍是助手文字；只有真实未决事件产生确认卡和既有定位入口。停止本地演示后只保留记录和停止状态，不制造最终助手答复。

### 3. 角色抽屉只有一份工作列表，资料展开态按角色保留

顺序是角色名 → 当前工作 → 排队 → 折叠角色卡/边界/变更/文档。空闲只有「无进行中或排队消息」一条，空态不保留两份列表。角标计数是进行中与排队条目数，点击直达同一个列表。

排队保持位次、来源、摘要与入队时间；仅摘要未容纳完整内容时显示全文。仅未投递客户消息有撤回按钮；进行中、派发和回交不显示不可用撤回控件，不邀请用户尝试禁止动作。请求处理中条目保留，返回失败时仍保留，成功返回后更新同一快照和角标。本地演示用显式模拟返回控制成功/失败，不能代替真实接口验收。

每角色独立保存聊天状态、工作/队列、未决与已答选择、活动展开、资料/全文、草稿、聊天与抽屉阅读位置。侧树同时显示非当前角色的真实演示快照，后台工作与等待确认不会因切换而消失。角色资料和全文的阅读态按角色保存；切换角色后标题、列表和角标更新为这一角色的本地快照。模拟刷新实际新增一条「状态未记录」的回放活动，重新生成聊天、角色资料与侧树视图，并恢复展开、全文和草稿；使用当前可见内容锚点恢复聊天位置。不会仅用提示文字假装快照更新。角色卡示例内容只为检查资料容器；正式应用应继续使用真实完整正文，不删资料。

## 交互状态表

| 触发 | 默认呈现 | 用户动作 | 动作后 | 失败或未知 |
| --- | --- | --- | --- | --- |
| 进入聊天 | 抽屉关闭；普通答复直接可读 | 打开记录 | 同位置展开原活动 | 未知状态明确写状态未记录 |
| 同轮常规活动到达 | 合入连续组；一条可靠当前动作或正在工作 | 主动展开 | 后续同组保持展开 | 不从调用/accepted 猜成功 |
| 轮末 | 默认收起常规组 | 阅读答复 | 保持用户当前位置 | 不改助手原文，不造完成卡 |
| 失败/拒绝事件 | 原位置独立可见 | 阅读原因 | 前后分组不跨异常 | 保留目标、原因/退出码 |
| 正式未决事件 | 原位置可见确认卡，保留定位入口 | 确认/暂不调整 | 依真实返回更新；原型仅模拟 | 原型不代表授权或真实投递 |
| 点资料图标 | 当前角色工作先显示 | 点图标/×/Esc | 关闭，草稿保留，焦点回图标 | 不改聊天宽度和阅读位置 |
| 点 Pi 图标 | 单标题、次级路径、原字段 | 保存到 .env | 依真实返回反馈；原型只显示模拟保存 | 未验证连接不写连接通过 |
| 非空队列 | 1 当前 + 3 排队；资料折叠 | 查看客户消息全文 | 就地展开，不复制队列 | 短项无全文按钮 |
| 未投递客户消息 | 撤回可见 | 撤回 | 请求中保留；成功后删除并更新位次/角标 | 失败保留条目，可重试 |
| 正常快照刷新 | 同角色信息更新 | 保持阅读 | 资料/全文/草稿/位置保留 | 切角色不沿用上一角色条目 |
| 空队列 | 单行空说明 | 展开角色卡 | 完整资料按需读 | 空闲不代表全部验收完成 |
| 工作时停止 | 输入区发送左侧停止可见 | 停止 | 只结束当前轮次，三条队列、资料/全文和草稿保留；角标4→3 | 不自动生成未存在的最终答复；空闲隐藏停止 |

## 视觉与键盘规范

- 背景：左栏 `#F4F4F2`，聊天白色，抽屉 `#FCFCFA`；主文字 `#242624`，次级文字 `#737773`，细线 `#E5E7E3`。异常为浅红底+文字原因，未决为浅暖底+明确按钮，不只依赖颜色。键盘焦点环 `#42745E`（focus-visible 2px、offset 3px；窗口边缘按钮因裁切保留内嵌环）——2026-10-14 增补纳入本取色表。
- 正文 14px，行高 1.9；标题 14–15px；次级 11–12px。聊天主内容最大 760px，外侧 24–30px 留白。辅助资料保持单列，没有装饰图、阴影卡片或常驻指标。
- 使用现有线框文档、设置、图片、发送、停止语法；收纳用同一种小箭头，异常依文字而非堆图标。
- 抽屉是非模态，不锁住焦点；开时焦点可到关闭按钮，关时回原图标，Esc 可关闭。输入持续可达。执行/资料用原生 details 支持键盘展开。Enter 发送、Shift+Enter 换行，isComposing 不发送，正式 IME 保护沿用当前能力。
- 圆角仅用于按钮、输入胶囊和客户消息；助手正文与资料不做厚重卡片。

产品第二轮认为 R1–R3 闭合，推荐本设计方向；接受960px档360px覆盖抽屉、剩328px历史的取舍。PM以两轮会议收口，不增加讨论轮次。推荐仅针对设计，不等于客户实施授权。

本次没有执行真实Electron、模型项目、生产接口或真实增量事件测试。原型浏览器观察不能覆盖未操作的键盘、发送、撤回成功接口及所有组合状态，也不能证明长会话虚拟渲染的锚点准确性。

后续真实实现仍须验证：body/.app scrollWidth；抽屉开关列宽；长路径/宽表/代码；真实队列返回与位次；两角色快照一致性；实时/回放分组一致；150 行以上虚拟窗口的展开高度、滚动锚点与未决定位；IME、发送/停止能力不回归。模拟刷新新增本地活动并重渲染，用于检查保留阅读态；不能证明真实业务事件链路。

2026-10-14 增补：以上除「真实队列返回与位次」（受控假数据）与「真实业务事件链路」外，其余各项已在最终候选上由离线受控夹具与独立回归覆盖（两档无横溢出、抽屉列宽、长内容换行、两角色快照、实时/回放分组、锚点 14 条含开合零漂移、IME 回归）；真实模型/网络与真机操作仍不在覆盖内。覆盖明细见[复核记录](2026-10-14_design_uiux-final-acceptance.md)。

本角色没有指定未经验证的 CSS 根因，未变更生产接口，也未取得业务实现权限。桌面应用为后续主要实现属主；必要事件字段缺口由 PM 协调对应属主。第二轮独立回应：认同产品指出的停止清队列、全局聊天状态串角色和仅toast刷新问题；这些问题会让用户误判队列与后台工作，已在v2本地原型修正。布局方向保留。会议推荐与客户实施决定分别记录。PM已完成上述v2本地原型检查，实际覆盖和限制按本节记录。

## 2026-10-14 增补：四项澄清裁定（实施后一次裁清）

按客户「按照 UI设计来改，改完了让 UI，和产品复核」的实施完成后，本角色对最终冻结候选（renderer `402e49a7…`、styles `69b2ea02…`、index `9b542de1…`、tool-rows `9ffda4bf…`、ui-labels `9f344ebf…`）独立复核通过（[复核记录](2026-10-14_design_uiux-final-acceptance.md)）。（2026-10-14 晚补签：renderer 经第二版窄修复取代为 `47703d0b…`，视觉零变化、本四条裁定不受影响；见复核记录补签节。）本文档实施状态随之更新为「已实施并复核」。四项此前交回的澄清裁定自本日起生效：

1. **助手说话人行（原型 `.speaker`）：确认不需要。** 聊天头常显当前角色名、会话按角色隔离、用户/助手已有对齐与气泡区分；逐条说话人行只增加流内噪声与行模型成本。若未来出现同一会话内多说话人（如跨角色转录合并），再以新设计补说话人标识。
2. **纵向节奏以统一 16px 行距表达：确认达成设计意图。** 原型的分段 margin（30/12/22 等）是静态整页的像素调法；正式实现的行模型按「行高＋行距」完整记账，流内垂直 margin 无法入账（见桌面UI 锚点修复记录的 S2 口径）。层次与转折在两档图像上可读，不要求逐段间距，不新增返工。
3. **焦点环 `#42745E` 纳入取色表**（见上文「视觉与键盘规范」）；窗口边缘按钮内嵌环为登记例外。
4. **抽屉「此角色的工作」小标题：确认不需要。** 其设计意图（工作列表的分组语境、与下方资料区区分）已由抽屉标题（含角色名）、「当前工作／排队」两个自明小标题与空态单行文案达成；再叠加第三层命名属冗余。Pi 抽屉「保存位置」保留同款小标题样式（该处仍需语境）。
