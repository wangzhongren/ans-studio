客户反馈（逐字）：「现在这个页面感觉太轻飘飘的感觉，不稳定的感觉，是否有办法优化呢。」→「没有企业那种稳定的感觉。」

本轮为**设计提案与可检查原型**，不实施正式应用。交付[单文件 HTML 原型](2026-10-17_design_enterprise-stability-prototype.html)。未改 `app/`、`src/`、`test/`、其他角色或客户项目；未读 `.env`、未跑凭据/网络命令、未 git 提交。设计稿不等于实施授权；A/B 的选择、基线修订与实施范围由客户确认，经 PM 审核后交实现角色。

## 一、问题诊断

### 1.1 实测基线（1362×862，只读现实现与真机截图）

证据：`09-current-ui.png`（整页）、`08-table-rendered.png`（正文/表格）、`05-s1-count-fixed.png`（空态/治理记录）；样式读数来自 `app/renderer/styles.css` 当前生效段（含文件末尾 V2 覆盖）。

| 量 | 实测 | 视觉后果 |
| --- | --- | --- |
| 视口 | 1362×862 | — |
| 左栏 | **208px**，底色 `rgb(238,241,235)`（`--bg-side` #eef1eb） | 与中栏之间**无 1px 分隔**，只靠色差；边界软 |
| 中栏 | **1154px**，纯白 | 大面积白底无任何结构线 |
| 正文列 `.chat-pane` | **800px 居中**，左右各约 **177px** 空白 | 内容列窄、留白宽，重心散 |
| 输入区 `.composer` | **通栏 1154px**；内部胶囊/脚注 800px 居中，**与正文列左缘对齐** | 通栏容器无上边框、白底白面，胶囊像“漂”在页面底部；缺贴底信号 |
| 顶栏 | 36px；下方会话头 72px | 标题栏与内容区之间无强分隔；会话头内容左缘 32px，不与 800px 内容列对齐 |
| 边框 | 左/中之间 **0**；标题栏下边线 `#dde2dc` 极淡；输入区上边线 **0**（`border-top:0`） | 三个区域没有被“框”住 |
| 阴影 | 全局 **0**（抽屉/菜单有少量） | 没有承重面 |
| 字号 | 基础 **13px/1.55**；消息 **15px/27px**；标签 11–12px | 字号本身不轻，但缺少线、对齐与对比支撑 |
| 表格 | 单元格 1px `#dde2dc`，表头 `#f5f6f2`，字号 12.5px | 表格边界与正文边界同淡，读起来“浮” |

### 1.2 结论

“轻飘飘”不是字体或颜色单点问题，而是**结构缺失**：

1. **没有框**：三个主要区域（左栏 / 内容 / 输入）缺少分隔线与承重面，视线没有停靠点。
2. **没有网格**：正文与胶囊同为 800，但输入区通栏 1154、会话头内容自 32px 起排——800 内容列、1154 容器、32px 头部三条可见边界没有统一到一条内容列；用户无法感到“同一个版面”。
3. **没有贴底**：输入区与页面同色、无上边线、无阴影，视觉上不属于页面底座。
4. **重量不足**：结构线、控件边框、次级文字对比都低于“企业工具”的常规值；圆角偏大、表格边界不完整。
5. **稳定性未表达**：顶栏/输入区虽在 flex 流中固定，但缺少视觉固定信号；流式内容改变高度时，用户感知不到“哪些不动”。

## 二、设计原则

1. **框优先于装饰**：先用 1px 分隔线、实底表面和贴底容器建立结构；不使用渐变、纹理、彩色大面积。
2. **一条内容列**：标题、消息、输入区共享同一最大宽（900px）与同一左右边距；线可以通栏，内容必须同列。
3. **上下固定，中间滚动**：顶栏与会话头不滚；输入区贴底；只有消息区滚动，保留现有滚动锚定与虚拟窗口。
4. **重量来自对比，不来自尺寸**：文字/边框对比提高一档；字号体系基本不动，避免推翻已验收的 15/27 正文。
5. **状态靠文字 + 形状 + 位置**：颜色仍是辅助；忙碌、错误、等待确认不靠颜色单独传意。
6. **极轻阴影**：仅在“浮起”的层级（输入区、菜单、抽屉、确认卡）使用，避免卡片海。

## 三、两档方案

### 方案 A：轻量加固（推荐，可分步实施）

保留现有 IA：36px 标题栏、208/176 左栏、72px 会话头、单列消息、底部输入区、424px 抽屉。只做四件事：

- **框**：左/中 1px 分隔；标题栏下边线加深；会话头下边线；输入区上边线 + 实底贴底 + 极轻上阴影。
- **网格**：内容列 800 → **900px**；会话头内容、消息列、输入胶囊、脚注统一到同一列；线仍通栏。
- **重量**：结构线 `#d7ddd4`、控件边框 `#8a968b`（3.08:1）、次级文字 `#55625b`、三级文字 `#6a756e`（4.8:1）；圆角 10/7 → 8/6；表格表头实底 + 完整外框；卡片/输入区极轻阴影。
- **贴底与稳定**：维持 `.col-mid` 纵向 flex；`.chat` 唯一滚动容器；会话头与输入区不进入滚动；保留 `overflow-anchor`、虚拟窗口与底部跟随。

**实施分三步**（可单独验收、单独回滚）：

| 步骤 | 内容 | 文件 | 预期观感 |
| --- | --- | --- | --- |
| A1 结构 | 三条分隔线、输入区实底贴底、内容列 900、标题/输入同列 | `styles.css`（无需改 HTML） | 页面立即“站住” |
| A2 重量 | 边框/文字对比、圆角收敛、表格、极轻阴影 | `styles.css` | 企业工具的密度与清晰度 |
| A3 密度 | 统一间距刻度、标签收紧、正文保持 15/27 | `styles.css` | 细节一致，不改阅读契约 |

**推荐理由**：A 直接命中“轻/散/不稳”的四个成因；不改 IA、不改交互契约、不动 `renderer.js` 的行模型；以 CSS 为主，回归面小；可分步让客户逐步确认“重量”幅度。

### 方案 B：企业化重构（更大改动，本轮不推荐）

在 A 的基础上再做结构性调整：

- **常驻顶栏**：保留 36px 标题栏，在其下新增 **44px 应用顶栏**，承载项目 / 当前角色 / 引擎 / 连接状态；窗口控制仍在标题栏右端。
- **底部状态栏**：**28px**，横贯全宽，显示引擎、上下文恢复、写入边界、角色计数等稳定信息。
- **卡片化内容**：消息区底色改为浅灰画布（`#f4f6f2`），助手消息、报告、工具组、确认卡成为白色卡片（1px 边框、8px 圆角、极轻阴影）；表格随卡片。
- **会话头瘦身**：角色与引擎上移到应用顶栏后，会话头 72 → **56px**，只保留“当前会话”与动作。

**收益**：更像“组织级控制台”，上下边界非常明确。
**代价**：IA 改变；垂直 chrome 净增约 **56px**（+44 顶栏 +28 底栏 −16 会话头），消息视口 587.4 → 531.4px（原型实测）；需重做多轮截图/测试锚点；与已验收 V2 视觉基线冲突更大。**建议在 A 落地并被客户认可后，再单独评估是否进入 B。**

### 推荐

**A（A1 → A2 → A3）**。若客户希望“一眼就是企业系统”，可在 A 验收后把 B 作为下一轮独立提案，而不是与本轮混做。

## 五、布局与稳定性

### 5.1 三栏与内容列

```
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 36px（通栏）                                           │
├──────────────┬───────────────────────────────────────────────┤
│ 左栏 208px   │ 会话头 72px（内容 900 居中，线通栏）           │
│              ├───────────────────────────────────────────────┤
│              │ 消息滚动区（唯一 scroll 容器）                 │
│              │        ┌──────── 内容列 900 ────────┐          │
│              │        │ 消息 / 表格 / 工具 / 确认卡   │          │
│              │        └──────────────────────────────┘          │
│              ├───────────────────────────────────────────────┤
│ 底部入口     │ 输入区（贴底、上边线、实底；内容 900 居中）     │
└──────────────┴───────────────────────────────────────────────┘
```

- 1362×862：左 208（含 1px 右边线）；中 1154；内容 900 → 左右各约 **127px**（现左右各约 177px）。输入胶囊/脚注同 900。
- 1280×800：左 208（含线）；中 1072；内容 900 → 左右各约 **86px**。
- 960×620（应用最小）：左 176（含线）；中 784；内容 = `784 - 24(左) - 14(右) - 10(滚动条)` = **736px**，随窗口流式收缩，无横向页面滚动。
- 会话头/消息/输入统一规则：`.chat-pane`、`.capsule`、`.compose-note` 用 `max-width: var(--content-max); margin-inline: auto;`；会话头/状态行的横向内边距用 `padding-inline: max(32px, calc((100% - var(--content-max)) / 2))`（窄档 base 24），使它们的 900 内容盒与 `.chat` 的 900 内容盒同左缘。
- **滚动条沟槽补偿（现状已有，保留即可）**：`.chat` 的横向内边距是 **左 32 / 右 22**，加上 10px 滚动条后，内容盒左右各 32；会话头/输入区是 **左 32 / 右 32**。三者内容盒宽度相同，因此**胶囊本来就和正文左缘对齐**（原型 before 实测 0.0px），“输入区与正文不对齐”指的是**通栏容器**没有边界，而不是胶囊错位。改列宽时保持这个关系：`.chat { padding-right: calc(32px - var(--scrollbar-w)); }`（窄档 `calc(24px - var(--scrollbar-w))`），**不要**给会话头/输入区额外加滚动条宽度——那会反向错位。若滚动条宽度变化，只改 `.chat` 的右内边距。
- 输入区贴底：`.composer` 背景/边线通栏，内部胶囊与脚注 900 居中；上边线 + 极轻上阴影 + 浅底共同表达“固定在底部”。

### 5.2 固定与滚动

- 结构保持：`.col-mid { display:flex; flex-direction:column }`；`.chat-head`、`.session-notice`、`.composer` 为 `flex:0 0 auto`；`.chat { flex:1 1 auto; overflow:auto }`。
- **不**把会话头/输入区做成 `position:sticky`（它们本来就在滚动容器外）；避免 sticky 与虚拟窗口/抽屉的层叠冲突。
- `.chat { overscroll-behavior: contain; overflow-anchor: auto; scrollbar-gutter: stable; }`；保留滚动条沟槽，防止内容宽度跳动。
- 不启用全局 `scroll-behavior: smooth`；定位待确认卡等显式跳转可保留一次性平滑。
- 滚动锚定：沿用现有机制（虚拟行 + spacer + 底部跟随）。流式内容只改变消息区高度，不改变会话头/输入区几何；用户上滚阅读时新内容不抢位置。
- 输入框自动增高：只压缩消息视口高度，不改变消息列宽；贴底容器随高度上移，滚动锚定保持底部内容可见。
- `session-notice` 出现/消失会改变消息视口高度；建议仅在状态变化时切换，且最多一行、高度可预测（约 28px），不在流式过程中反复增删。

### 5.3 表格与长内容

- 保留 `.msg table { display:block; width:max-content; max-width:100%; overflow-x:auto }`；宽表在容器内横向滚动，不撑破内容列。
- 增强：表头 `background: var(--bg-soft)`、`border-bottom: 1px solid var(--border-strong)`；外框 `1px solid var(--border-strong)`（可用 `outline`/包装层实现，避免 `border-collapse` 与 `display:block` 冲突）；单元格 1px `--border`；字号 13/20；内边距 6×10。
- 长路径/命令：`overflow-wrap:anywhere`；`pre` 保持横向滚动与 320px 最大高。
- 空态：保持居中图标 + 标题 + 说明；A 方案下空态也落在 900 列内，不额外加卡片。
- 加载/错误：沿用现有文字行与语义色；不新增骨架屏或彩色徽章。
- 抽屉：424px 覆盖层不变；仅同步圆角/边框/阴影 token。

### 5.4 640–1440px

- 正式桌面窗口 `minWidth:960`、`minHeight:620`（`app/main.ts`），960–1440 为实际支持范围；本方案在 960/1280/1362/1440 检查。
- 640–959 仅作为“设计健壮性”口径：左栏 176 或收成图标轨、内容列流式、无页面横向滚动。**正式应用当前不开放该尺寸**，本轮不改窗口最小尺寸；若未来开放，需单独验收。

| 左树角色项 | 默认：透明底、13px 名称、11px 子行；悬停 `--bg-hover`；选中 `--bg-selected` + 内侧 2px `--success` 竖条 + 名称 600；忙碌：12px SVG 弧线转轮 + “工作中”；错误：`--danger` 文字 + 图标；等待确认：静态“1 待办”文字徽标（**不加忙碌动效**）；停止/空闲：中性灰。焦点 2px 环。 |

| 工具行 | 组摘要 22–26px；活动行 42px 网格（时间 / 目标 / 状态）；运行中转轮；失败/未知 `--danger` 文字；截断状态在折叠摘要可见；行 hover 弱底。 |
| 表格 | 表头实底 + 强下边线；单元格 1px；数字/状态左对齐；宽表容器内横向滚动；无横向页面溢出。 |
| 确认卡 | 等待：静态边框 + “等待确认”文字；选项无默认选中；提交在未选择时禁用；拒绝/取消为默认焦点（fail-closed）；已答/失效：文字说明，按钮禁用；**零忙碌动效**。 |
| 输入区 | 空态：28px 文本行 + 占位；聚焦：胶囊边框变 `--success` + 2px 焦点环；未选角色：发送禁用；忙碌：停止按钮可见；多行：高度增长，宽度不变；附件行在胶囊上方。 |
| 顶栏/会话头 | 项目未导入：路径位显示“尚未导入项目”；角色未选：标题“未选择角色”；引擎禁用：降级底色；状态：连接/恢复/错误用文字，不用色点单独传意。B 的底栏同规则。 |

## 七、可访问性

- **对比度**：正文 14.4:1、次级 6.4:1、三级 4.8:1、强调 7.0:1、错误 6.2:1、未决 5.8:1；控件边框 3.08:1；焦点环 7.0:1。均按白底计算，浅底上不低于 4.5:1。
- **焦点**：所有可交互元素保留 `2px solid var(--focus-ring)` + `outline-offset: 3px`；不因“更企业”而移除焦点环或改成低对比阴影。
- **键盘**：左树 Tab 进入、方向键移动（沿用现有）；会话头动作可按 Tab 到达；确认卡默认焦点在拒绝/取消；Esc 关闭抽屉/确认卡；输入区 Enter 发送、Shift+Enter 换行。
- **文字缩放**：会话头由 `height:72px` 改为 `min-height:72px`，允许 200% 文字时增长而不裁切；消息/输入容器不使用固定高度。
- **动效**：仅“工作中”转轮动画；`prefers-reduced-motion` 下变为静止弧；等待确认/恢复卡零动效。
- **窗口范围**：960–1440 为正式范围；640–959 仅设计健壮性，需另行开放与验收。

## 十、验收口径（可测量）

在 1362×862 与 1280×800 上，用只读 DOM 几何/计算样式测量：

1. **同列**：`.chat-pane`、`.capsule`、`.compose-note`、会话头内容区左缘两两差 ≤ **1px**；内容宽度均 ≤900 且 >880。
2. **框**：`.col-left` 右侧 1px 边框存在；`.titlebar` 下边线 ≥1px；`.composer` 上边线 ≥1px 且背景非 `#fff`（或与消息区可区分）。
3. **贴底**：滚动 `.chat` 前后，`.chat-head` 与 `.composer` 的 `getBoundingClientRect().top/bottom` 不变（±0px）。
4. **不跳动**：切换消息/追加一条消息时，`.chat-head`、`.composer`、`.chat-pane` 宽度不变；`document.documentElement.scrollWidth == viewport 宽`（960/1280/1362/1440 四档）。
5. **对比度**：正文 ≥7:1、次级 ≥5:1、三级 ≥4.5:1、焦点环 ≥3:1、控件边框 ≥3:1。
6. **表格**：8 列宽表在 900 列内不产生页面横向滚动；表格容器 `scrollWidth > clientWidth` 时可横向滚动；单元格边框完整。
7. **键盘**：Tab 可依次到达左树、会话头动作、消息内按钮、输入区；焦点环可见；确认卡默认焦点为拒绝/取消。
8. **动效**：仅“工作中”转轮有动画；`prefers-reduced-motion: reduce` 下 `animation-duration ≤0.01s` 且 iteration ≤1。
9. **窗口**：960×620 / 1280×800 / 1362×862 / 1440×900 无页面横向溢出；640–959 仅记录、不作为本轮通过条件。

## 十一、风险、取舍与待客户决策

### 风险与取舍

- **基线修订**：800px 内容列、10/7 圆角、#dde2dc 边框、无阴影均为 V2 已验收值；本提案有意修订，旧截图断言将不再适用。需客户确认这是基线变更。
- **“更重”可能被感知为“更硬”**：控件边框 3:1 与结构线加深会牺牲一点“轻”。建议先 A1 看结构，再加 A2 看重量，避免一次性过重。
- **900 列**：1362 下正文两侧留白由约 177 收到约 127，阅读行宽增加；若担心行长，可降到 880（仍满足 880–920 建议）。
- **输入区实底/浅底**：与白色消息区形成分层；若客户偏好纯白，可只保留上边线 + 阴影，仍能贴底。
- **B 的净高**：顶栏 +44px、底栏 +28px、会话头 −16px = 净增 56px，1362×862 消息视口 587.4 → 531.4px；需重新评估“可见行数”。
