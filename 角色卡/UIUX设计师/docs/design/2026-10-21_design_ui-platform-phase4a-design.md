# Phase 4A 设计附录：引擎选择、三引擎设置、角色资料、工作概览与队列抽屉

Phase 4A 已获客户授权。本附录把旧渲染器已经实现、但新 React 渲染器仍缺的四块界面写成可执行的设计契约：**真实引擎选择与缺配提示、三引擎设置面板、角色资料/文档抽屉、工作概览与队列抽屉**。产品行为、文案语义、每引擎独立会话/草稿/待办、失败如实呈现都不变；只把界面落到 Nova × 深色石墨的组件、令牌、状态与焦点规则上。

**状态：仅设计。** 本文件与配套原型是设计证据，**未实施、未测试、未部署**；未改 `app/`、`src/`、`test/`、其他角色资料或历史文档；未运行模型或网络。4A 的实现由桌面UI 按 PM 派发执行；4B 的范围见 §九。

设计依据：[Nova × 深色石墨规范](2026-10-21_design_ui-platform-nova.md)、旧功能说明 [在桌面选择引擎并管理自己的会话与配置](../../../桌面UI/docs/feature/runtime-choice.md)、旧实现与截图（`app/renderer/renderer.js`、`engine-selector.js`、`runtime-ui.js`、`styles.css`，2026-10-14 运行时设置/角色抽屉/工作概览证据）。旧版文案与语义是基线，本附录不新造业务能力。

## 一、引擎选择器真实状态

### 1.1 入口与基线行为

- 位置：会话头右侧，`工作概览`/`角色资料` 之前；触发器沿用 `EngineSelect` 的 `role=combobox`/`aria-haspopup=listbox` 契约，尺寸 **104×32**，菜单 **180px**，placement 8px 边距/6px 间距/上下翻转。
- 默认与优先：首次启动/无已保存显式值 ⇒ **Claude**；已保存或显式恢复的 runtime 优先于默认值。三个引擎各自保留会话、历史、草稿、附件、待办与确认请求；切换只改变当前查看和下一次发送目标，后台任务继续。
- 未导入项目：触发器禁用（如实文案「导入项目后可选择引擎」）；导入成功（含无角色项目）后可选择三引擎。
- 配置摘要：每次切换引擎后、打开设置抽屉时、每次设置保存成功后读取当前引擎的 `getRuntimeConfig(engine)`；菜单打开时按需读取（可并行读三引擎一次）并缓存；**不在项目导入/恢复时预取**。缺必填项显示缺项条；读取失败如实显示失败；字段齐备收起缺项条，但**不代表凭据或远程服务已验证**。
- 跨引擎草稿：按 runtime×role 在内存保留；成功发送、显式移除或切换项目时清除；不持久化；切引擎/切角色/重开抽屉不丢。设置面板内未保存字段草稿另按 §2.3 处理（关闭抽屉丢弃）。
- 迟到结果：旧引擎/旧项目/旧请求的异步结果不得覆盖当前视图；按 projectRoot/runtime/roleId 显式匹配。

### 1.2 三引擎配置状态

设计**不在项目导入/恢复时预取三引擎**；菜单打开时按需读取（可并行读三引擎一次），引擎切换/设置保存后读取并缓存为只读状态；不阻塞当前会话。完整预取/缓存优化留 4B：

| 状态 | 来源 | 菜单/抽屉文案 | 颜色 |
| --- | --- | --- | --- |
| 已配置 | `missingKeys.length === 0` | 「已配置」 | `--text-3`；不传意为「已验证」 |
| 缺配置 | `missingKeys.length > 0` | 「缺配置」+ 缺项键名（抽屉/缺项条） | `--warning` |
| 配置未知 | 读取失败/未返回 | 「配置未知」 | `--text-3`；不是「缺配置」 |
| 检查中 | 读取进行中 | 「检查中…」 | `--text-3`，12px 文本，不用无限动画 |

- 缺配置的引擎**仍可选择**（旧行为：切过去后由主进程实际配置决定会话能否开启；UI 不抢先禁用）。选择后缺项条/设置入口立即出现。
- 设置保存失败不回写成功状态：菜单/缺项条继续按最近一次成功读取的真实配置显示，失败只在设置抽屉内报错；不把「已保存」说成「已连接」。
- 菜单选项状态不靠颜色单独传意：每行都有文字状态；当前项用勾选 + 前景色。

### 1.3 触发器状态矩阵

| 状态 | 触发条件 | 视觉 | 键盘/行为 |
| --- | --- | --- | --- |
| disabled | 未导入项目 | 32px，`--input` 边框，文字/chevron 降为 `--text-3`，opacity .45 | 不可聚焦；`aria-disabled` |
| default | 已导入项目 | 104×32，`--input` 边、`--background` 底；当前引擎名 12.5 + ChevronDown 12/1.5 | Enter/Space/↓ 打开；↑/Home/End 从选定项/首尾打开 |
| hover | 指针 | 底 `--hover` | — |
| focus-visible | Tab | 2px `--ring` + 3px offset | — |
| open | 菜单展开 | `aria-expanded=true`；菜单 180px，`--popover` + `--border-strong` + `--shadow-popover` | ↑↓/Home/End 移动 active；Enter/Space 选中；Esc 关闭回触发器；Tab 离开 |
| switching | 已选新引擎、正在切换视图/读配置 | 触发器显示新引擎名 + 12px `LoaderCircle` 转轮（0.9s linear，唯一允许的工作转轮）；`aria-busy=true`；菜单关闭 | 不重复提交；切换完成后恢复；失败保留新视图并显示配置/会话错误，不自动回退旧引擎 |

- 切换过程：保存当前草稿/阅读位置 → 切换视图（每引擎独立 pane）→ 更新触发器 → 读取新引擎配置 → 缺项条 → 选择角色并开启/恢复会话。加载期间聊天区显示「正在开启与角色…」/「正在载入会话历史…」；失败用 `sys-config` danger 行，不伪造成功。
- 文案沿用旧实现：「会话引擎，当前 Claude」「Pi 配置不完整，缺：…。请补齐后保存。」「读取 Pi 配置失败，请打开设置检查或重试。」「打开 Pi 设置」「正在读取 Pi 配置…」。

- 当前项只靠勾选+前景色，不只靠底色；缺配置用文字，不用红点单独传意。

## 二、三引擎设置面板

### 2.1 入口与抽屉

- **入口 A**：左侧栏底部「设置」（现有槽位；Phase 2 起为禁用占位）→ 打开右抽屉「引擎设置」，默认当前会话引擎。
- **入口 B**：缺项条「打开 X 设置」→ 同一抽屉，直接选中当前引擎。
- 不新增会话头设置图标；旧右上角设置图标不恢复（已由底部稳定入口取代）。
- 未导入项目：「设置」禁用，title「导入项目后可配置引擎」；导入后启用，不要求已选角色。
- 抽屉：沿用 424px 模态 Sheet；背景聊天 inert；Esc 关闭；焦点回入口；不改变聊天列宽。

### 2.2 面板层级

```
424 抽屉
├─ 头 64：标题「引擎设置」 + 关闭 28
├─ 引擎 Tabs 32：Pi / Codex / Claude（当前会话引擎标记；每项 aria-label 含配置状态）
├─ 当前会话/配置说明（11 text-3）
├─ 滚动内容（20/24）
│  ├─ 保存位置（mono 路径卡）
│  ├─ 说明（保存到仓库根 .env，只修改本引擎字段；application 文案）
│  ├─ 缺项/读取失败 Alert（按状态）
│  ├─ 必填字段（3/2/1 个）
│  ├─ 可选字段（选择/文本）
│  └─ 高级（Pi：上下文窗口/看护检查时限，折叠）
└─ 底部固定保存条 64：保存到 .env（primary 32） + 状态（11.5，aria-live）
```

- 标题 18/650；Tabs 32；字段间距 12/16；保存条 border-top `--border`、背景 `--card`；正文滚动，保存条不滚。固定 64px 保存条须真实 Electron 1360/960（可行时含 200%）验证；不可用则 4A 内回退流末保存并复核。
- 抽屉宽 424；字段单列堆叠，输入吃满整行；960 档同宽，不横向溢出。

### 2.3 引擎 Tabs 与配置切换

- Tabs 只切换**配置视图**，不切换当前会话引擎；顶部说明「配置只影响所选引擎；不会切换当前会话」。
- 默认 tab = 当前会话引擎；当前 tab 有 6px 状态点 + 一行状态文本「Claude · 已配置 / 缺配置 / 配置未知」；状态文本是主，点只是辅助。
- 切换 tab：保留该抽屉会话内每个引擎的未保存字段草稿（本地 state，按 engine 分开）；关闭抽屉丢弃未保存草稿（旧行为，不新增确认框）。
- 保存某个引擎只影响该引擎；若它就是当前会话引擎，保存后重新读取当前配置并更新缺项条；若否，当前会话的缺项条不因其他引擎保存而消失。

### 2.4 字段与分组

字段全部来自 `getRuntimeConfig(runtime)` 的 metadata（`key/label/required/secret/choices/choiceLabels/control/help/fallbackKeys/source/value/isSet`）；渲染侧只做布局，不硬编码引擎字段。唯一分组规则：**`control:"range"` 的字段进「高级」，其余必填在前、可选在后**。

| 引擎 | 必填（主区） | 可选（主区） | 高级（折叠，默认收起） |
| --- | --- | --- | --- |
| Pi | 访问令牌（机密，`ANTHROPIC_AUTH_TOKEN`）、API 地址（`ANS_PI_BASE_URL`）、模型（`ANS_PI_MODEL`） | 推理强度（`ANS_PI_REASONING_EFFORT`，关/低/中/高/极高，留空=平台默认） | 上下文窗口（7 档：系统默认 500k/32k/64k/128k/256k/500k/1M）；看护检查时限（系统默认 5min/1/2/5/10/15/30min） |
| Codex | API 密钥（机密，`CODEX_API_KEY`；回退 `OPENAI_API_KEY`）、模型（`ANS_CODEX_MODEL`） | API 地址（`ANS_CODEX_BASE_URL`，留空=OpenAI 官方）、推理强度（低/中/高/极高） | 无 |
| Claude | API 密钥（机密，`ANTHROPIC_API_KEY`） | 模型（`ANS_CLAUDE_MODEL`，留空=SDK 默认）、API 地址（`ANTHROPIC_BASE_URL`）、推理强度（关/低/中/高/极高） | 无 |

- 字段标签：`label · 必填/可选` + 机密 `Badge`「机密」；字号 11/12，`--text-2`。
- 帮助行：`KEY · 来源` + help；来源用 `文件/环境/回退（KEY）/默认/未设置`；10.5 `--text-3`；不隐藏回退键。
- 输入：Input 32，`--input` 边框，`--background`/`--card` 底；focus 2px ring + 3px offset；disabled 只读降透明。
- Select：32，选项 `留空（平台默认）` + `choiceLabels`；当前值不在 choices 时追加原值选项并保留（如实显示，不静默改写）。
- 高级摘要：32 行，Lucide ChevronRight 12/1.5，open 旋转 90°（瞬时，无 transition）；默认收起；高级字段均可留空 = 默认。

### 2.5 机密字段

- 值**绝不预填**；`input type=password`，value 恒空。
- placeholder：`isSet` ⇒「已设置，留空则不修改」；未设置 ⇒「未设置」。
- 行尾 `显示/隐藏` ghost 28；只显示**用户本次输入**，不读取/回显已存值；切换 tab/保存成功/关闭抽屉后清空。
- 保存时空 ⇒ 不下发该键（保留原值）；非空 ⇒ 下发新值。
- 帮助行继续显示 `source`/`fallbackKeys`；不暴露任何密钥内容。

### 2.6 高级滑块（上下文窗口/看护检查时限）

- 仅 Pi 的两个 `control:"range"` 字段；7 个离散档位，不是连续数值输入。
- 结构：label + 原生/组件 Slider（轨道 4、thumb 14）+ `output` 标签（11，min-width 96，tabular-nums）+ 可选帮助行。
- 默认档 = 空值 = `choiceLabels[0]`（系统默认）；保存时空串 = 清除该键 = 平台默认。
- 键盘：←/→ ±1 档，Home/End 首尾；`aria-valuetext` 同步标签；focus ring 2/3。
- 当前保存值不在预设档位：**回退文本 Input + amber 提示**「当前值不在预设档位；改为预设档位后保存」，不静默覆盖；保存由主进程按 choices 校验。
- 高级字段留空不下发；不新增任意数值/自由滑杆能力。

### 2.7 保存状态矩阵

| 状态 | 触发 | 面板 | 状态文案 |
| --- | --- | --- | --- |
| loading | 打开/重读 | 字段骨架不伪造；Save 禁用 | 「正在读取配置…」 |
| ready-complete | 读取成功、无缺项 | 字段可编辑；Save 可用 | 「必填配置已齐备。下一次开启会话时应用。」（按 application） |
| ready-missing | `missingKeys>0` | 缺项 Alert；字段可编辑 | 「Pi 配置不完整，缺：…。请补齐后保存。」 |
| saving | 点击保存 | Save 禁用、文案「保存中…」 | 「正在保存…」 |
| saved-complete | 保存 ok + 重读无缺项 | 清空机密输入；字段刷新；Save 可用 | 「已保存到 .env（改动键：…）。必填配置已齐备。<application>」 |
| saved-missing | 保存 ok + 重读仍缺 | 保留字段；缺项 Alert | 「已保存到 .env（改动键：…）。必填配置仍缺：…」warning |
| save-error | 保存/异常 | 保留全部输入（含机密本次输入）；Save 可用 | 「保存失败：…」danger |
| read-error | 读取失败 | 字段清空/禁用；「重试读取」ghost | 「读取配置失败：…」danger |
| no-project | 未导入 | 抽屉不打开或空态 | 「导入项目后可配置引擎」 |

- 保存成功才清空机密输入；失败保留，允许重试。
- 文件保存、必填完整性、应用时点分开说：不把「已保存」说成「已连接/已验证」，不把「下一次会话应用」说成「当前生效」。
- `application` 文案沿用旧 `applicationLabel`：当前配置已应用 / 下一次开启会话时应用 / 当前轮次继续使用原配置，结束后下一次输入应用新配置。

### 2.8 缺项条（会话头下）

- 仅当前会话引擎缺项/读取失败时显示；已导入项目才显示；字段齐备即收起。
- 结构：一行 32px（可两行 wrap），左文案 + 右「打开 X 设置」ghost 28；amber（缺项）/danger（读取失败）；不遮聊天、不抢焦点。
- 文案：「X 配置不完整，缺：A、B。请补齐后保存。」/「读取 X 配置失败，请打开设置检查或重试。」
- 不把缺项条做成模态；用户可继续看历史/切角色，但发送/开会话失败会按主进程实际结果如实提示。

## 三、角色资料抽屉

### 3.1 抽屉与层级

- 424px 模态 Sheet，标题「<角色> · 角色资料」，关闭 28；背景聊天/左栏 inert；Esc 关闭；焦点回触发「角色资料」。
- 与工作概览同级：二者是右抽屉的两个顶层视图，同一时刻只开一个；文档阅读/队列是同一抽屉的子视图（带返回）。
- 不因打开抽屉改变聊天列宽/滚动/草稿/角色/引擎。

### 3.2 角色头与两节

| 区域 | 内容 | 尺寸/状态 |
| --- | --- | --- |
| 角色头 | Avatar 36（首字）、角色名 18/650、权力/职责副标题 12 `--text-3`、状态 Badge（空闲/工作中/等待你确认/错误，文字+图标） | 始终可见；不重复会话头副标题 |
| 资料 | 四个 Collapsible：角色卡（Markdown）、边界条目（表）、变更记录（Markdown）、文档（路径索引）；每个摘要行 32，右侧 ChevronRight；默认收起，按角色记住开合 | 角色卡/变更记录走受控 Markdown；边界表只读；文档索引不含正文 |
| 待办 / 队列 | 待办列表（待确认/待选择 + 定位）与队列预览（前 3 条 + 「查看全部队列（N）」）；数字 Badge | 与工作概览同一真实快照，不另造数据；空态「无进行中或排队消息」 |

- 「资料」各节内容滚动/长文限制在抽屉内；`边界条目` 用 kind 线型（目录实线/条件虚线/文件细线）+ path/purpose，不改变权限。
- 文档索引底部固定「查看已列文档」ghost 按钮，打开文档子视图；不自动读第一份文档。
- 无角色：空态「选择角色后查看资料」+ 说明；无待办/队列：中性文案，不显示 0 角标。

### 3.3 文档只读阅读子视图

- 子视图标题「<角色> · 来源文档」，返回「← 角色资料」；列表说明「以下是当前项目中该角色已列出的可读文档，请选择要阅读的文件。」
- 列表行：label 13/600、relativePath 11 `--text-2`、右侧「阅读」28；不可读/scope 不符禁用；空态「该角色当前没有已列出的可读文档」；底部「刷新已列文档」ghost。
- 阅读态：相对路径 11 mono、状态行 11 `--text-3`（只读文档 · N 字节/正在读取/错误）、正文 13/1.8 或 Markdown（同一受控管线）；错误按既有 `documentError` 文案，可重试/返回；长文横向/纵向在抽屉内滚动。
- 交互：显式选择才读；不按报告路径猜文件；返回列表保留滚动/选中；返回角色资料保留原入口；关闭抽屉回触发；Esc 回上一层或关闭（先子视图返回？定义：Esc 在阅读态回列表，再 Esc 关闭抽屉；返回按钮同级）。
- 不改文档读取 API/权限/256KiB/UTF-8/二进制限制；缺 grant/平台/范围/编码/大小/变化如实显示。

## 四、工作概览

### 4.1 入口与角标

- 会话头「工作概览」按钮；抽屉标题「<角色> · 工作概览」；424 模态，与角色资料同级。
- 角标按 PM §十二 裁定拆分（修正旧 F7「排队+待确认混计」）：
  - **工作概览角标 = 待确认/待选择数**（`--warning`，仅 >0 显示）；回答「什么在等我决定」。
  - **角色资料角标 = 当前工作 + 排队数**（`--text-2` 中性 Badge，仅 >0 显示）；回答「这个角色有多少活」。
  - 两者不合并；工作概览内部各节仍有自己的数字。
- 角标文字/aria-label 完整：「工作概览，N 项待处理」「角色资料，N 项进行中或排队」；99+ 封顶。

### 4.2 行结构

| 节 | 行 | 操作 |
| --- | --- | --- |
| 待处理 N | `待确认/待选择` Badge + 请求标题 12.5 + 「定位」28 | 定位：关闭抽屉、滚到原卡、聚焦卡（不默认作答）；无待处理：「无待处理请求」 |
| 当前工作 | 「进行中」11 + 来源 10.5 + 时间 10.5 + 摘要 12.5；可展开全文 | 「全文/收起」24；**不可撤回**；无当前工作不显示本节 |
| 排队 N | 「第 N 位」11 tabular + 来源 10.5 + 时间 10.5 + 摘要 12.5；全文 | 「全文」24；仅客户消息且非进行中显示「撤回」28；就地回执；超过 3 条显示「查看全部队列（N）」 |
| 最近回交 | 聊天流已有 handback 行：报告声明 12.5/600 + 摘要 12/1.6（最多 2 行） | 4A 只呈现聊天流 handback 行；不打开完整报告、不读取/补存 persistence；完整报告/persistence 留 4B；只列当前 project/runtime/role，同 reportId 只列一次；空态「暂无回交报告」 |

- 行距 8/12；section 间距 16；section 标题 12/600 + 数字 `--text-3`；`Separator` 1px。
- 撤回：`撤回中…` 禁用；成功就地「已撤回排队消息：…」；失败「撤回无效：…」+ 系统行；不做乐观移除；位次由 role-state 刷新。
- 定位：不切角色/引擎；不默认选中；焦点到原卡；原卡在虚拟窗口外时先滚到锚点。

### 4.3 空态/加载

- 无角色：「选择角色后查看工作概览」。
- 无待处理/无队列/无回交：各自中性空态，不用 0 角标/彩色徽章。
- 加载：读取 role-state/history 时显示 11.5 `--text-2`「正在同步工作状态…」，不显示假行；失败 `sys-config` danger + 设置/重试入口（若与配置相关）。
- 普通聊天不产生报告：最近回交空态保留；不根据工具 stdout/助手正文造报告。4A 的最近回交只呈现聊天流 handback 行，完整报告、来源文档阅读与 persistence 留 4B。

## 五、队列抽屉

### 5.1 定位

- 同一 424 抽屉的子视图，标题「<角色> · 队列」，返回「← 工作概览」/「← 角色资料」（按来源）；不新增第四个会话头图标，不新增独立窗口。
- 入口：工作概览「查看全部队列（N）」、角色资料「待办 / 队列」的「查看全部队列」。
- 关闭抽屉回触发；返回子视图回原视图并恢复滚动/焦点。
- **4A 只做抽屉队列**；QUEUE_VIEW/operator 排队聚合属 4B。队列体 DOM 契约：`#right-queue-body` 唯一，不新增第二个队列容器/独立窗口；长队列虚拟化留 4B。

### 5.2 内容与状态

| 区域 | 内容 | 操作 |
| --- | --- | --- |
| 当前工作 | 进行中的队列项（「进行中」+ 来源/时间/摘要/全文） | 全文；不可撤回 |
| 排队 | 第 1..N 位；来源（客户消息/系统/su 派发/回交投递）、时间、摘要 | 全文 24；仅客户消息且未投递「撤回」28；就地回执 |
| 空态 | 「无进行中或排队消息」 | — |

- 撤回状态：默认 → 撤回中…（禁用）→ 成功就地「已撤回排队消息：…」/失败「撤回无效：…」；失败另落系统行；不留下假条目，位次由真实快照刷新。
- 只在客户消息且未投递时显示撤回；派发/回交/系统只读；不提供批量撤回/重排/合并。
- 960：抽屉保持 424，内容单列、来源/时间允许换行或上下排；撤回 28 保持可点；页面无横向溢出；背景聊天 inert；关闭后回原触发，角色/引擎/草稿不变。**4A 必须真实 Electron 960 复测**（截图、无横向溢出、焦点/Esc/inert、可行时 200%）；不可读则 4A 内调整并复核；长队列虚拟化留 4B。

### 5.3 与工作概览/角色资料的关系

- 工作概览是「行动视图」：待处理 + 当前 + 队列预览 + 最近回交；队列抽屉是「全量队列视图」。
- 角色资料是「角色上下文视图」：资料 + 待办/队列预览；两者使用同一真实快照，不复制/合并数据。
- 三处数字一致；不因视图切换改变队列/待办。

- 不引入第二套动画库；CSS 只做颜色/背景/边框/opacity 微状态。

- 不把「已请求停止」说成「已停止」、不把「已入队」说成「已执行」、不把「已保存」说成「已连接」。
