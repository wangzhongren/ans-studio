# UI/UX 设计师交付约定

本角色没有程序导出或业务 API。本文件说明设计产物如何交给产品、项目管理与实现角色，具体方案产生后补充实际设计版本和检查证据。

| 项目 | 约定 |
| --- | --- |
| 输入 | 产品目标、当前真实界面与任务状态、产品评审意见、客户约束及任务议程 |
| 布局与交互说明 | 说明用户任务、适用窗口、信息层次、关键操作和成功/失败/空态；区分观察、推断和建议 |
| HTML 原型 | 落本角色 `docs/design/`；说明打开入口、演示数据、可检查交互、模拟能力与未接入部分，素材在同目录范围内 |
| 设计规范 | 交付任务所需的尺寸、间距、颜色、组件状态、文案与焦点/键盘行为及验收口径 |
| 联合评审 | 在独立固定角色上下文贡献设计意见，由项目管理记录纪要与客户实际决定 |
| 实现交接 | 引用具体方案版本、检查证据、尚待验证状态与属主；由项目管理审核后交客户确认实施范围 |
| 权限变化 | 返回项目管理并由 Governance 处理，不由设计师自行扩大范围 |

当前交付 v2（沿用-v1稳定文件名）：[说明](docs/design/2026-10-13_design_ans-uiux-interaction-v1.md)与[单文件 HTML](docs/design/2026-10-13_design_ans-uiux-prototype-v1.html)。演示条切换受控窗口/对话/队列状态，页面不接真实数据或接口。v2脚本语法检查已完成；PM已完成v2两档本地浏览器检查，活动刷新/停止/切角色/撤回失败覆盖与截图见说明；未做精确滚动像素断言，不宣称锚点完全通过，运行时接入、业务测试和部署均未进行。角色创建与原型交付不自动授权业务代码改动。

实现验收阶段输入：PM提供最终候选及变更范围、正式renderer/真实Electron的运行方式、两档窗口截图和受控操作证据。输出为[UI/UX验收记录](docs/design/2026-10-13_design_ans-uiux-implementation-acceptance.md)中逐项观察、缺陷和证据不足；不代写产品判断，不向真实模型发送任务。当前只有清单，尚无实现通过结论。

验收触发精化：显式跨/同角色点击使用既有U-1最新/未决优先；普通刷新/增量/记录展开或折叠/抽屉/回放保持当前位置。资料/全文/草稿附件按角色保存。正文实现允许沿既有13.5px/1.65/680px，最终按实际可读性判断；不以原型演示字段授权新增导航行为。
