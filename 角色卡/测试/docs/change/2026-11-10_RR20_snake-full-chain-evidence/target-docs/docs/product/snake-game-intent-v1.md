# 2D 贪吃蛇小游戏 — 产品意图（v1）

- intentId: `snake-2d-game`
- flowId: `snake-game`
- 版本: v1（本文件为版本化新文件，不原地修改；后续变更另出 v2/v3…）

## 1. 背景与目标用户

**目标用户**：需要在桌面浏览器上快速获得一段短时休闲游戏体验的终端用户（客户本人及其直接分享对象）。

**使用场景**：用户双击/直接打开本地 `index.html`，无需安装、无需网络、无需启动任何服务，即可立即开始一局贪吃蛇；关闭页面后最高分仍在，下次打开继续挑战。

**要解决的问题**：交付一个零依赖、零安装成本、可直接运行且玩法完整（控制、计分、增长、碰撞判负、最高分持久化、重开）的小游戏，作为本项目可验收的交付物。

**产品目标**：以最少的交付面（单页 + 少量静态文件）覆盖完整可玩闭环，任何验收人用浏览器打开即可在 1 分钟内自行核对全部验收标准。

## 2. 范围

范围内（In Scope）：

1. 纯前端单页游戏，入口 `index.html`，样式与逻辑拆分为若干 `.css` / `.js` 文件，无第三方依赖（不引用 CDN、不引入 npm 包或框架）。
2. `HTML5 Canvas` 渲染的游戏棋盘，深色背景 + 可见网格线。
3. 蛇的移动控制：**方向键** 与 **WASD** 两套按键均可控制上/下/左/右。
4. 食物机制：蛇头吃到食物 → 分数 +1、蛇身长度 +1、食物在棋盘上重新生成。
5. 碰撞判负：蛇头撞墙（越出棋盘边界）或撞到自身蛇身 → 本局游戏结束。
6. 分数展示：界面同时显示**当前分数**与**最高分**。
7. 最高分持久化：最高分写入并读取浏览器 `localStorage`，刷新/重开浏览器后仍保留。
8. 重新开始：游戏结束后，按 **R 键** 或点击界面上的**重新开始按钮**，开始新一局（分数归零，最高分保留）。
9. 界面风格：简洁，深色背景，网格棋盘清晰可辨。

范围外 → 见第 4 节「非目标」。

## 3. 验收标准（逐条可检验）

> 每条均由验收人在普通桌面浏览器中直接打开 `index.html` 手工执行并观察判定，不需要任何测试框架或服务端。

- **AC-1 直接打开可运行**：不启动本地服务器、不执行构建命令，用浏览器直接打开 `index.html`，页面正常渲染出游戏棋盘与分数区，控制台无阻断性报错。
- **AC-2 无第三方依赖**：交付目录内所有 `index.html` / `.js` / `.css` 引用均为本地相对路径；不存在任何 CDN、外链脚本/样式、包管理器清单（如 `package.json`）或框架 bundle；断网状态下打开与游玩不受影响。
- **AC-3 深色背景 + 网格棋盘**：棋盘区域背景为深色，存在可见的网格线，得分信息清晰可读。
- **AC-4 方向键控制**：游戏中按 ↑ ↓ ← →，蛇相应改变移动方向且不出现反向自撞（即不可 180° 直接掉头）。
- **AC-5 WASD 控制**：游戏中按 W / A / S / D，效果与 AC-4 的四个方向一致。
- **AC-6 吃食物加分变长**：蛇头接触食物后，当前分数恰好 +1，蛇身长度恰好 +1，食物在棋盘内其他位置重新出现；连续吃 k 个食物后分数与长度均累计 +k。
- **AC-7 撞墙/撞自身结束**：蛇头越过棋盘任一边界，或蛇头进入自身蛇身所占格子时，本局立即结束并给出明确结束提示（如「游戏结束」文字）。
- **AC-8 当前分数与最高分**：界面始终显示当前分数；当本局分数超过已记录的最高分时，最高分同步更新；最高分写入 `localStorage`，刷新页面或重开浏览器后最高分仍在；新一局开始时当前分数归零而最高分保留。
- **AC-9 重新开始**：游戏结束状态下，按 R 键可开始新一局；点击界面上的「重新开始」按钮同样可开始新一局；两种方式均使游戏恢复正常可游玩状态。
- **AC-10 交付说明完备**：实现与测试完成后，交付方须向客户说明产物文件路径与运行方式（如何打开、如何操作、如何重开），说明内容与 AC-1 ~ AC-9 的实际行为一致。

（AC 编号供后续提案/验收文档引用；若验收以抽样方式执行，须至少覆盖 AC-1、AC-2、AC-6、AC-7、AC-8。）

## 4. 非目标

- 不做后端服务、账号体系、登录/注册、云端存档。
- 不做在线排行榜、社交分享、任何联网能力。
- 不以移动端触屏/手势操作为交付要求（桌面键盘操作为准）。
- 不做音效/音乐、皮肤/主题系统、多关卡、障碍物、道具、加速难度曲线等扩展玩法。
- 不做多人/对战模式。
- 不引入第三方库、构建工具、包管理器或框架。
- 不做与玩法无关的营销页、埋点统计、运营后台。

## 5. 约束

**交付形态约束**
- 纯前端：全部逻辑在浏览器端运行，无服务端参与。
- 零第三方依赖：不得使用 CDN、外链资源、npm 包或 UI/游戏框架。
- 可直接打开：产物为静态文件，无需构建、无需本地服务器；双击 `index.html` 即可游玩。

**技术约束（产品级，不规定实现细节）**
- 棋盘渲染基于 `HTML5 Canvas`。
- 最高分仅持久化在本地浏览器 `localStorage`，不做跨设备同步。
- 游戏状态与渲染在单一页面内完成，不跳转、不刷新页面。

**流程约束**
- 客户要求每一步出卡确认：**意图、提案、角色与团队、验收**等关键节点均须提交客户确认后才推进；未经客户确认不得视为已批准。
- 实现与测试完成后，须向客户说明产物路径与运行方式。

## 7. 关键产品取舍（供客户确认时审阅）

- **以「可直接打开」为硬约束**：因此不做模块化打包、不使用 ES module 跨文件 import 之外的重型方案，也不依赖本地服务器；这牺牲了一部分工程化便利，换取零安装体验。
- **键盘双套控制而非可配置键位**：方向键 + WASD 已覆盖绝大多数桌面用户，键位自定义列为非目标，避免扩大交付面。
- **最高分只存本地**：不做账号与云端，明确写入非目标，避免验收时被误解为缺陷。
- **移动端与音效等排除在外**：客户原始要求未提及，列入非目标以防范围蔓延；如客户需要，应作为新需求另出 v2。
