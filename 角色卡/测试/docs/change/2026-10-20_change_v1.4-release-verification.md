## 三、来源与 manifest 一致性（本地独立复算）

- **Tag 未移动**：`git ls-remote --tags origin v1.4.0` → `880ab4dac24c1e8a1bdb99d4e0808c248874a73a refs/tags/v1.4.0`（annotated tag object）；`git rev-parse v1.4.0^{}` → `83eec7ed1966b215d81035cac33d7dda80013f05`。GitHub API `git/ref/tags/v1.4.0` 与 `git/tags/880ab4da…` 同证：tag object `880ab4da` → commit `83eec7e`。与 provenance/manifest 的 `sourceSha` 一致，tag 仍指向冻结源。
- **overlay 选择可复算**：`git diff --name-only 83eec7e 879eddd` 得 30 条变更；按 `src/common/装配/release-policy.mjs` 的 `selectOverlay` 规则本地复算 → **12 selected / 18 excluded**，与 provenance 的 `overlayPaths`、`excludedChanges` 用 `diff -u` 比对**逐字一致**。
- **overlay.patch 可复算**：以 `git diff --binary 83eec7e 879eddd -- <12 paths>` 本地重生成 → 与发布 `overlay.patch` **字节级相同**（`cmp` 无差异），sha256 = `2f6d6f76…` = provenance `overlayPatchSha256` = GitHub digest。备注（非缺陷）：`release-prepare.mjs` 的改动清单用 `-c core.quotePath=false`，而 patch 字节用的是裸 `git diff`（默认 quotePath=true，中文路径带 octal 引号）；复现字节一致须用同样默认引号方式，语义与 `git apply` 兼容性不受影响。
- **actualTree 可复算**：在 `83eec7e` 建临时 detached worktree，`git apply --index --binary` 应用发布 `overlay.patch` 后 `git write-tree` → `07d210ee800c4f19a279b2bc0f3cb3d4dd9e8463`，与三份 manifest/provenance 的 `actualTree` **完全一致**；临时 worktree 已移除，主工作树未受影响。
- **三份 manifest 同源**：仅取 `sourceRef/sourceSha/overlaySha/actualTree/overlayPaths/overlayPatchSha256/excludedChanges/runUrl` 规范化后计算 sha256，3 份 manifest 与 provenance **四者相同**（`0a857a51…`）：`sourceRef=v1.4.0`、`sourceSha=83eec7e…`、`overlaySha=879eddd…`、`actualTree=07d210e…`、`overlayPaths` 恰 12 条、`overlayPatchSha256=2f6d6f76…`、`excludedChanges` 18 条、`runUrl` 指向上述绿跑。
- **平台与构建面**：`darwin/arm64`、`darwin/x64`、`win32/x64` 三份一一对应；`node=v24.14.0`、`npm=11.9.0`、`builder=26.15.3` 三平台一致；`lockSha256=4a671376…` 与本地 `git show 879eddd:package-lock.json | shasum -a 256` 一致；`unsigned=true`。
- **smoke**：三份 manifest 均 `smoke.ok=true`、`isPackaged=true`、`version=1.4.0`、`process.code=0`；`checks` 七项 `dom/preload/ipc/importDisabled/missingConfiguration/settings/envPathMatches` **全为 true**。
- **无密钥泄漏**：对 manifest/provenance 的字段名与值做模式扫描（`token/secret/key/password/credential/auth/cookie` 字段名、`sk-*/ghp_*/AKIA*/Bearer` 值形态）——除 `smoke.missingKeys` 仅登记**期望的环境变量名**外无命中；`smoke.envPath` 仅为 runner 临时目录路径；未见任何凭据值。

## 五、证据边界

- **未在本机下载/解压/启动三个 ZIP**（合计 1.2GB+）；「三平台实际启动」的证据来自 CI 原生 runner 的打包 smoke（`release-verify.mjs`：解压、禁入私有数据扫描、SDK 导入探针、`--ans-packaged-smoke` 实际启动并把 `checks` 写入 manifest），本角色只核对 manifest 记录与发布资产的一致性，**未复跑该 smoke**。
- 本机为 macOS arm64；Windows 包与 macOS x64 包未在本机运行验证。
- ZIP 的 sha256 取自 GitHub 上传时计算的 asset digest（与 SHA256SUMS、manifest 三方对齐），本角色**未从零重算 ZIP 字节**（未下载整包）。
- 未验证构建可复现性（ZIP 含时间戳等天然不可复现因素）；验证到的是「冻结源 + 可字节复算的 overlay.patch ⇒ actualTree」这一来源链。
- tag object 未签名（GitHub API `verification.reason="unsigned"`）；来源信任依赖 GitHub 平台与 manifest/SHA256 链。

## 六、残余风险

- **未签名、未公证**（manifest `unsigned=true`）：macOS Gatekeeper 可能拦截、Windows SmartScreen 可能告警；README 与发布说明均已提示先核对 SHA256。
- Windows 包仅有 CI 原生 runner 的启动证据，本机不可复验；Windows 暂不支持内置受限来源文档阅读（发布说明已写明）。
- 构建依赖 CI 环境与锁文件（Node 24.14.0 / npm 11.9.0 / electron-builder 26.15.3）；若需长期可复现，仍需另行固化构建镜像。
