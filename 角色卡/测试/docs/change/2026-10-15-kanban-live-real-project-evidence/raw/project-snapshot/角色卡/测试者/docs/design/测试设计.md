# 测试设计（测试者）

- 项目：kanban-live ｜角色：测试者（独立验证）｜日期：2026-10-15
- 目标：以**零第三方依赖**、可重复、可自动退出的方式，独立判定实现是否满足需求 1–10 与冻结契约。

## 1. 分层策略（按“离 IO 越远越先测”）

```
01-core   纯领域逻辑（零 IO）        → 快、确定、可注入时间
02-store  单文件 JSON 存储（fs）      → 临时目录隔离
03-http   HTTP 接口（端口 + fs）      → 临时端口 + 临时文件
04-corrupt 损坏恢复（fs + HTTP）
05-atomic 原子写（并发 + mock fs）
06-static 文本安全 / 零依赖 / 界面静态断言（源扫描）
```

分层依据：底层失败会放大到上层；先锁死 `core` 再做集成，定位更快。

## 2. 隔离设计

- **时间**：`core` 层用可注入的 `now`（`createTask(input, now)` / `updateTask(task, patch, now)`）做确定性
  时间断言；HTTP 层无法注入，则用 `await delay(12~15ms)` 拉开 `createdAt`/`updatedAt`。
- **路径**：每例 `fs.mkdtempSync(os.tmpdir(), 'kanban-*')`，绝不使用项目 `data/`。
- **端口**：`port: 0` 由系统分配，避免端口冲突。
- **清理**：统一 `t.after` 关闭服务 + 递归删临时目录，保证无残留、无常驻进程。
- **隔离断言**：`03-http` 用显式 `dataFile`，`/api/status` 的 `dataFile` 必须等于该绝对路径。

## 3. 关键技巧

- **rename 失败注入**：`t.mock.method(fs, 'renameSync', () => { const e=new Error(...); e.code='EACCES'; throw e; })`，
  利用 `store.js` 通过 `require('node:fs')` 动态取方法的特点，在同一模块对象上打桩；`node:test` 自动还原。
  断言“原文件逐字节不变 + 无 `.tmp-` 残留”。
- **并发原子性**：一个持续读取协程（`existsSync` + `readFileSync` + `JSON.parse`）与 30 个并发 `POST` 并行，
  收集任何解析错误；任一“半截 JSON”都会让 `JSON.parse` 抛错并被记为失败。
- **损坏恢复**：预置非法内容 → 断言 `warning`、备份文件 `tasks.json.corrupt-*` 内容**逐字节等于原文**、
  原路径已被改名（`existsSync===false`）、且后续写入成功后 `warning` 仍保持。
- **文本安全**：接口侧做特殊字符存取（`<script>`、`&<>"'`、`<img onerror>`）三处读回（列表/导出/新 store）；
  静态侧扫描 `src/public/**` 的注入点与外链。
- **两层拒绝**：接口侧穷举空白/缺失/非字符串标题；界面侧用**结构性静态断言**
  （在 `submitCreate` 片段内断言 `if (!title)` 出现在 `api('/api/tasks'` 之前 + `preventDefault`）。

## 4. 断言取向

- 只依据 `README.md` 与三模块导出契约；不采信实现者自查结论。
- 对“文档承诺”与“实现行为”分别断言，必要时拆成两条用例：
  - 安全性质（不得落库）→ 断言行为（始终为绿）；
  - 契约响应码（413）→ 断言文档承诺（修复前红，作为缺陷证据；2026-10-15 修复后已转绿）。
- 非冻结的扩展行为（`{task,warning}`、标签截断、`ok` 恒真）**记录实测值**而非强判对错，列入待裁定口径。

## 5. 不做什么

- 不引入 jsdom / supertest / 任何第三方库（零依赖约束）。
- 不修改 `src/**`、`README.md`、`package.json`、`data/**`、`test/实现者/**`。
- 不做浏览器端真实渲染测试（以静态源扫描替代）。
