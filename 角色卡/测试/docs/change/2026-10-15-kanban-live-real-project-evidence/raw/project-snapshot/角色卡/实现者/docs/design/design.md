# 设计说明（design）

项目：kanban-live（离线中文任务看板） ｜ 角色：实现者 ｜ 版本：v1.0.0（2026-10-15）

## 1. 设计目标与约束

| 目标 | 约束落地方式 |
|---|---|
| 完全离线 | 零依赖：只用 `node:http` / `node:fs` / `node:path` / `node:crypto`；页面零外链 |
| 数据不丢 | 单文件 JSON + 原子写（临时文件 + `rename`）；损坏时先备份再继续，绝不静默清空 |
| 本机安全 | 只监听 `127.0.0.1`（常量，不可由环境变量放开） |
| 契约稳定 | `core/store/server` 导出名冻结；HTTP 错误体统一 `{error:{code,message}}` |
| 可测 | 领域逻辑与 IO 分离，时间可注入（`createTask(input, now)`），`createServer` 支持 `port: 0` |

## 2. 分层

```
HTTP 层  src/server.js   —— 路由、查询参数解析、错误码 → 状态码、静态资源、启动/退出
领域层   src/core.js     —— 纯函数：校验、规整、创建、更新、筛选、排序、统计（无 IO、无时间副作用）
存储层   src/store.js    —— 加载/修补/备份、内存列表、原子持久化
呈现层   src/public/*    —— 原生 HTML/CSS/JS，textContent 渲染，同源 fetch 调 API
```

分层收益：`core` 可被测试直接调用且零副作用；`store` 可脱离 HTTP 单测（含损坏场景）；
`server` 的 `port: 0` 让测试可并发起服务而不抢端口。

## 3. 关键设计决策

### 3.1 为什么用「函数即模块导出 + 同名属性」的双形态导出

`module.exports = createStore; module.exports.createStore = createStore;`
既满足契约里 `const { createStore } = require('./store')` 的用法，也容忍
`require('./store')({...})` 的写法。导出名一个没改，只是多了一层兼容。

### 3.2 为什么写文件用「临时文件 + rename」

`fs.rename` 在同一文件系统内是原子替换：读者要么看到旧文件、要么看到新文件，不会看到半截 JSON。
临时文件落在**同目录**（`data/`），确保与目标同分区（跨分区 `rename` 会退化为拷贝并失去原子性）。
每次写入前 `fsync`，降低掉电后「文件名已更新、内容未落盘」的风险。

### 3.3 损坏处理的边界

| 输入 | 判定 | 处理 |
|---|---|---|
| 文件不存在 / 空串 | 正常 | 空列表 |
| JSON 解析失败 | 损坏 | 备份 + 告警 + 空列表 |
| JSON 合法但非数组、也非 `{tasks:[]}` | 损坏 | 备份 + 告警 + 空列表 |
| 数组中有非法条目（如缺标题） | 条目级 | 跳过该条，其余保留（不备份整文件，避免误伤） |

保守策略：宁可多备份一次（数据仍在），也不做「解析失败就当空数据」这种静默清空。
`warning` 采用进程内**粘性**（写入成功也不清除），确保用户不会漏看告警。

### 3.4 前端安全渲染

所有来自服务端的字符串（标题、标签）只经 `document.createTextNode` / `element.textContent` 落到 DOM；
节点结构用 `createElement` 手工搭建。这样 `<script>`、`<img onerror=…>` 之类都只是文本。
错误提示、确认弹窗同样使用纯字符串拼接（不进入 HTML 解析）。

### 3.5 状态与优先级的中文映射

英文枚举入存储与接口（`todo/doing/done`、`low/medium/high`），中文标签（待办/进行中/已完成、低/中/高）
只在前端 `STATUS_LABELS` / `PRIORITY_LABELS` 里做展示映射，并通过 `core.STATUS_LABELS` 单点共享，
避免「存储层出现中文枚举」导致后续国际化/迁移困难。

### 3.6 排序与筛选放服务端还是前端

放**服务端**（`core.filterTasks` / `core.sortTasks`，由 `/api/tasks` 暴露）。理由：契约已把
`status/tag/q/sort/order` 定义为接口参数；前端只负责把控件值组装成查询串，保证「接口能做到的，
页面就能做到」，也便于测试者直接用 curl 验证。

## 4. 已知取舍

1. 写入失败（磁盘满/权限）时，内存镜像可能领先于文件，HTTP 返回 500 让客户端看到失败；不做事务回滚（v1）。
2. `warning` 粘性：进程内不自动清除，重启后按文件实际状态重新判定。
3. 单进程单写者模型，无文件锁；同一数据文件被两个进程同时打开时后写者覆盖先写者（离线单机场景可接受）。
4. 无鉴权：只监听 `127.0.0.1`，不做认证（本机单用户）。
