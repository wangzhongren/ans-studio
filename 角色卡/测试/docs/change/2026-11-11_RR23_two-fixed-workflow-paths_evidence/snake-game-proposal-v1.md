# 贪吃蛇游戏 · 方案 v1

- 依据产品意图：`docs/product/snake-game-intent-v1.md`（intentId: `snake-game`，version 1，客户已确认 committed）。
- 配套文档：模块清单 `docs/proposals/snake-game-modules-v1.md`、名单 `docs/proposals/snake-game-roster-v1.md`、架构契约 `docs/contracts/snake-game-architecture-v1.md`（均为 v1）。

## 1. 目标

交付一个可玩、可人工验收的贪吃蛇小游戏：玩家用键盘控制蛇移动、吃食物计分，撞到边界或自身即结束本局，可随时重开再来一局。质量档位为「可玩 MVP / 演示级」，四项核心能力完整可用，不做生产级打磨。

## 2. 范围（本期）

只实现四项核心能力，与意图 v1 一致：

1. **键盘控制**：方向键与 WASD 改变方向，蛇按固定节拍持续前进，不允许直接反向。
2. **计分**：吃到食物后蛇身 +1 格、每食物 +10 分，当前分实时显示。
3. **重开**：本局结束后按 R 或点击「重开」按钮立即开新局，无需刷新页面，不做二次确认。
4. **边界碰撞**：蛇头撞墙（不穿墙）或撞到自身时本局立即结束，展示本局分数与最高分。

运行形态：浏览器单文件网页（HTML5 Canvas），离线双击可玩，除该文件外不依赖服务端或网络请求。

## 3. 已确认行为口径

| 项 | 本期口径 |
| --- | --- |
| 运行形态 | 单文件 `index.html`，内联 HTML/CSS/JS，离线双击可玩，无 CDN、无外链、无网络请求 |
| 输入键位 | 方向键 + WASD；P 暂停/继续；R 重开；禁止直接反向 |
| 速度 | 初始 7 格/秒（意图「约 6–8 格/秒」内）；每吃 5 个食物提速 1 格/秒；上限 12 格/秒 |

## 4. 实现口径（意图未细化、由本方案约定的细节）

以下为实现细节，不改变意图范围与验收标准：

- 首局为待开始状态：页面打开后显示开始提示，按方向键/WASD/空格开始；此前蛇不移动。
- 初始蛇身 3 格，位于网格中央附近、朝右；食物随机生成在非蛇身空格。
- 方向输入在每帧内最多缓冲一个有效方向，于下一个节拍生效；直接反向被规则层忽略。
- 游戏节拍由固定步长累加器驱动，渲染由 `requestAnimationFrame` 驱动；单帧追赶步数设上限，避免卡顿后出现明显突跳。
- 盘面被填满（无空格生成食物）时按结束处理并展示结算，不单独做胜利界面。
- localStorage 仅保存最高分整数，不保存任何玩家个人信息；存储不可用（如受限环境）时降级为内存值，不报错、不崩溃。
- 重开在待开始、进行中、暂停、结算各状态均可用，均按「清零当前局、保留最高分」执行。

## 5. 模块划分

共 8 个模块（`project-modules/v2`，见 `docs/proposals/snake-game-modules-v1.md`）：`env-resources`、`entry-index`、`game-state`、`game-loop`、`input`、`render`、`score`、`app-shell`。职责与依赖方向：

- 规则与数据（`game-state`）、节拍（`game-loop`）、输入（`input`）、渲染（`render`）、计分与持久化（`score`）相互解耦，由 `app-shell` 统一装配。
- `entry-index` 交付自包含单文件 `index.html`，由 env-bootstrap 按固定顺序内联各模块源码；`env-resources` 约束无网络依赖的静态资源边界。
- 模块写入根互不重叠，支持「一模块一任务」派生独立写集；接口以架构契约 v1 为准。

## 6. 验收方式（A1–A9）

按意图 v1 frontmatter 的 A1–A9 逐条人工试玩核验：

- A1：断网/离线双击 `index.html` 可开玩，无网络请求。
- A2：固定节拍前进；方向键与 WASD 均可改变方向；直接反向无效。
- A3：吃到食物长度 +1、+10 分，分数面板实时更新。
- A4：撞墙或自撞立即结束，展示本局分数与最高分。
- A5：结算后按 R 或点击「重开」开始新一局，无需刷新。
- A6：重开后当前分清零、蛇身与速度复位，最高分保留（刷新页面后仍保留）。
- A7：完整流程「开始→移动→吃食物→撞边界/自身→结算→重开」在目标浏览器无控制台报错。
- A8：单局帧率不低于 30fps，节拍不因卡顿出现明显突跳。
- A9：单人本地体验，无账号、无联网、不收集个人信息。

## 7. 约束与已确认边界

- 从空目录起步，无既有仓库与产品/技术资产；不引入构建工具链，纯原生 HTML/CSS/JS。
- 单人本地游玩，不依赖服务端、不收集个人信息。
- 不做：音效与背景音乐、移动端触摸/响应式、排行榜/昵称/账号、障碍物/关卡/多食物/道具、多人对战、多语言、生产级美术与动画打磨。

## 8. 风险与依赖

1. **单文件交付与模块化的张力**：模块按写入根拆分开发，最终由 env-bootstrap 内联装配成单文件；`entry-index` 需在其他模块完成后重新装配，派发顺序上应置于末位或安排二次装配任务。
2. **file:// 下 localStorage 行为**：Chrome/Edge 对本地文件页面的存储行为可能受策略影响，A6「刷新后最高分保留」需在目标浏览器实测；不可用时按内存降级且不阻断 A7。
3. **A8 人工判定**：帧率与节拍突跳依赖观测方法；验收时固定浏览器版本与观测窗口，按固定步长上限设计避免明显突跳。
4. **默认值来源**：意图 v1 正文第 8 节仍将部分细节标为「待客户确认」，而本阶段派发确认了上述默认值；本方案按派发确认口径执行。若后续意图出新版本，按新版本修订方案，不回溯篡改本文件。

## 9. 不在本方案内的事项

不创建招聘/任命卡、不实现代码、不写角色卡、不派发下游任务；角色卡与实现在名单与方案确认后由对应流程推进。
