## 1. 验收对象与交付形态

- 最终验收对象为项目根目录的**自包含单文件 `index.html`**（内联 HTML/CSS/JS），以 `file://` 双击打开运行；验收不以 `src/` 分模块文件或开发服务器为准（架构 v1 §1、§5）。
- 验收时由 A12b 记录该单文件的完整 OID/版本标识（按任务指定）与文件大小；实现内容与本标准对应关系以该指定版本为准，候选漂移或内容变更后须重新验收。
- 本标准覆盖意图 A1–A9 全部条目；架构 v1 第 6 节的验收行为口径为各条在架构层的保证依据。

## 2. 验收环境与前置条件（所有标准共用）

1. **浏览器**：桌面版 Chrome 或 Edge 最新稳定版（与意图/方案「桌面 Chrome/Edge 最新版」一致）。执行前在 `chrome://version` 或 `edge://version` 记录**精确版本号**及操作系统版本；全部 P0 核对须在同一版本下完成，未记录版本视为证据不完整。
2. **窗口与缩放**：窗口不小于 800×600，页面缩放 100%，使用干净配置（必要时禁用扩展），避免插件干扰网络与存储观察。
3. **打开方式**：把最终 `index.html` 复制到独立空目录（脱离 `src/`、`assets/`），双击打开，确认地址栏为 `file://` 协议；全程不使用本地服务器。
4. **离线条件**：A1/A2/A18 相关核对在断网（关闭 Wi-Fi/有线或系统飞行模式）下执行；其他标准可在断网状态下一并执行，以避免网络干扰。
5. **初始存储基线**：涉及最高分的标准（AC-8、AC-9、AC-13、AC-14、AC-18）须先用 DevTools → Application → Local Storage 记录或清理键 `snake-game.highScore.v1` 的基线值并写入操作记录；不得用猜测值替代实测。
6. **调试与截图**：除 AC-15（Console）、AC-16（启动参数/存储）、AC-17（FPS 观测）、AC-18（Network/Storage）必须使用 DevTools 外，其余截图保持页面主体可见、不叠加无关调试浮层；不得为验收修改实现代码或向页面注入会改变业务行为的脚本（AC-16 的存储禁用环境除外，且须记录注入/启动方式）。
7. **单项独立**：每条标准独立执行并单独记录结果；前一标准失败不阻断后续标准的执行与记录。

## 3. 证据规范

- 每项标准的证据由**人工操作记录**（必填）与**截图/控制台导出**（按各条要求）组成。操作记录须含：标准编号、执行时间、浏览器精确版本、前置状态、实际操作步骤、可观察到的实际结果（含数值）、附件路径与结论（通过/未通过/insufficient evidence）。
- 证据文件存放在 `docs/verification/snake-game/`，命名建议 `AC-<n>-<short-name>.md`（操作记录）与同名 `.png`（截图）；截图由验收者真实运行获取，不得使用示意图或实现者提供的伪造图。
- **P0 证据**：对应标准的操作记录须为可复核文本文件，并在同目录生成 `<artifact>.meta.json`（schema `evidence-meta/v1`），字段至少含 `schema`、`artifact`、`sha256`、`bytes`、`lines`、`generatedAt`、`acIds`；`acIds` 必须包含该标准 id。`sha256`/`bytes`/`lines` 由应用或工具实际计算，**不得手写或伪造**，且与文件当刻字节一致；证据修改后须重新生成 sidecar。
- 截图作为辅助证据：在操作记录中登记其项目相对路径与由应用计算的 sha256；若将截图单独作为某项标准的 P0 artifact 引用，同样须按 `evidence-meta/v1` 提供 sidecar。
- 证据中不得包含玩家个人信息；存储导出仅记录 `snake-game.highScore.v1` 的键名与整数值。
- A12b 报告写 `docs/quality/snake-game-report-v1.md`，逐条汇总本文件 AC 编号、实测结果、证据路径与 hash 引用；缺证据的条目如实写 insufficient evidence，不得以描述文字代替证据。

## 4. 逐条验收标准

### AC-1（A1，P0）单文件 index.html 可 file 协议双击离线打开并开始游戏

- **前置条件**：交付物为项目根目录单个 `index.html`；系统处于断网状态；已记录浏览器精确版本。
- **操作步骤**：① 将 `index.html` 单独复制到新的空目录（不带 `src/`、`assets/` 等）；② 双击该文件，确认地址栏为 `file:///.../index.html`；③ 观察页面是否渲染游戏区、分数面板与开始提示；④ 按方向键开始并操作约 10 秒。
- **可观察期望结果**：页面正常渲染 20×20 游戏区、当前分/最高分面板与开始提示；按方向键后蛇开始移动并可操作；无白屏、无卡死、无阻断性错误弹窗；不依赖任何同目录其他文件。
- **证据方式**：操作记录（含绝对路径、`file://` URL、浏览器版本、开始前后截图路径）+ 页面截图；P0 操作记录附 `evidence-meta/v1` sidecar。

### AC-2（A1，P0）运行期无网络请求且无外部脚本样式字体图片引用

- **前置条件**：同 AC-1；断网状态；DevTools 已打开 Network 面板并勾选 Preserve log，先清空记录。
- **操作步骤**：① 从双击打开到开始、移动、吃食物、结束、重开，观察 Network 面板；② 在 DevTools Sources/编辑器检索单文件中 `http://`、`https://`、`<script src`、`<link rel="stylesheet"`、`fetch(`、`XMLHttpRequest`、`WebSocket`、`@font-face`、外链 `url(` 等引用；③ 检查是否存在 CDN、外链字体或图片。
- **可观察期望结果**：Network 面板无任何网络请求（主文档 `file://` 加载本身不计）；单文件内无外部脚本、样式、字体、图片引用；断网不影响任何功能。
- **证据方式**：Network 面板截图（显示 0 请求）+ 源码检索结果记录 + 操作记录；P0 操作记录附 sidecar。

### AC-3（A2，P0）开始后蛇按固定节拍持续前进

- **前置条件**：页面处于开始前提示状态；断网；已记录版本。
- **操作步骤**：① 按方向键开始游戏，之后不再按方向键；② 连续观察至少 3 秒，记录蛇头每秒前进格数与节拍均匀性；③ 截图 2–3 个时间点。
- **可观察期望结果**：开始后蛇无需继续按键即持续前进；前进为固定节拍（初始约 7 格/秒，与架构 v1 §3 的速度口径相符，允许人工观测误差，但不得明显忽快忽慢或停止）；不会一次跨越超过 5 格（架构单帧追赶上限）。
- **证据方式**：操作记录（秒表/计时观测值与截图时间点）+ 截图序列；P0 记录附 sidecar。

### AC-4（A2，P0）方向键与 WASD 均可改变方向

- **前置条件**：新开一局；选择盘面中央附近安全位置，避免直接反向与撞墙。
- **操作步骤**：依次用 ↑、↓、←、→、W、A、S、D 改变方向；每个键至少验证一次；每次转向后观察至少一个节拍并截图/记录实际方向。
- **可观察期望结果**：8 个键均能改变蛇的移动方向；方向与按键一致；转向在下一个节拍生效且不导致异常结束；两种键位可混合使用。
- **证据方式**：操作记录逐键结果表 + 截图（关键转向）；P0 记录附 sidecar。

### AC-5（A2，P0）直接反向输入被忽略且不改变方向

- **前置条件**：新开一局，蛇朝向已确认（如向右）。
- **操作步骤**：① 蛇向右时按 ←/A（直接反向），观察至少一个节拍；② 待转向成功后按 ↑ 再立即按 ↓，观察；③ 快速连按两个相反方向键，观察。
- **可观察期望结果**：直接反向输入被忽略，蛇保持原方向前进，不结束、不倒退、不自撞；反向输入不进入方向缓冲并在之后生效；多次反向不累积造成异常。
- **证据方式**：操作记录（每个反向用例的实际方向与是否结束）+ 截图；P0 记录附 sidecar。

### AC-6（A2/方案 §3，P1）P 键暂停与继续且暂停期间蛇不前进

- **前置条件**：游戏进行中，蛇正常移动。
- **操作步骤**：① 按 P，观察 2 秒并截图状态区；② 期间尝试按方向键，观察是否恢复/改向；③ 再按 P，观察恢复前进。
- **可观察期望结果**：按 P 后状态区显示「已暂停」一行，蛇位置冻结、节拍不再推进；暂停期间不出现位移；再按 P 后从原位置恢复移动，无位置跳变；暂停/继续不结束本局、不改变分数。
- **证据方式**：操作记录（暂停起止时间、位置是否变化）+ 暂停与恢复截图。

### AC-7（A3，P0）吃到食物当前分加 10 且蛇长加 1

- **前置条件**：清理/记录最高分基线；开始一局；记录吃食物前的当前分与蛇身长度（初始 3 格）。
- **操作步骤**：① 控制蛇头吃到第一个食物，记录吃前/吃后的当前分与可见蛇身格数；② 再吃第二个食物重复记录；③ 观察食物是否重新生成在非蛇身空格。
- **可观察期望结果**：每吃一个食物当前分正好 +10（第一个食物后为 10，第二个后为 20），无额外加成；蛇身长度每次 +1（3→4→5，按可见格数或占位确认）；食物重新生成且不与蛇身重叠；分数只增不减。
- **证据方式**：操作记录（吃前/后分值与长度数值）+ 截图；P0 记录附 sidecar。

### AC-8（A3，P0）当前分与最高分面板随吃食物实时更新

- **前置条件**：记录最高分基线 H；开始一局。
- **操作步骤**：① 吃至少 2 个食物，逐次观察面板当前分文本；② 当当前分超过 H 时观察最高分文本；③ 全程不刷新页面。
- **可观察期望结果**：当前分在吃到食物的当拍由面板更新（数值与 AC-7 一致）；最高分在当前分超过原最高分时同步更新；面板无需刷新或额外操作即反映最新值。
- **证据方式**：操作记录（每次吃食物前后的面板读数）+ 截图序列；P0 记录附 sidecar。

### AC-9（A4，P0）撞墙立即结束并展示本局分与最高分

- **前置条件**：开始一局，记录本局当前分与最高分 H。
- **操作步骤**：① 控制蛇朝边界持续前进直至撞墙；② 观察撞墙瞬间与结算区文本；③ 撞墙后继续按方向键，观察是否会恢复移动。
- **可观察期望结果**：蛇头到达边界外时本局立即结束（不穿墙、不继续移动）；节拍停止、蛇冻结；结算区显示本局分数与最高分各一行；若本局分高于 H，最高分更新；结束后方向键不恢复本局。
- **证据方式**：操作记录（撞墙前坐标/分数、结束时刻、结算文本）+ 结算截图；P0 记录附 sidecar。

### AC-10（A4，P0）撞到自身立即结束并展示本局分与最高分

- **前置条件**：通过吃食物使蛇长至少 5 格；记录当前分与最高分。
- **操作步骤**：① 在远离边界的区域用连续转向构造蛇头进入自身蛇身的回环（如右→下→左→上），避免撞墙；② 观察进入蛇身格瞬间；③ 另测试「咬尾」场景（蛇头进入即将移走的尾格），记录是否结束。
- **可观察期望结果**：蛇头进入自身蛇身格时本局立即结束并冻结；结算区展示本局分数与最高分；咬尾且尾格将在同拍移走时按架构口径不判自撞（记录实际行为）；结束后不可恢复本局。
- **证据方式**：操作记录（构造路径、结束时刻、结算文本、咬尾用例结果）+ 截图；P0 记录附 sidecar。

### AC-11（A4/架构 §3，P2）盘面填满无法生成食物时按结束处理并展示结算

- **前置条件**：长期对局，蛇持续吃食物；记录盘面占用情况。
- **操作步骤**：持续游玩直至蛇身占满 400 格（20×20）或无可生成食物的空格；观察最后一格被吃后的行为。
- **可观察期望结果**：无空格生成食物时不崩溃、不无限等待；按结束处理并展示结算（本局分与最高分），不出现空白食物或异常坐标。
- **证据方式**：操作记录（占用格数、结束现象）+ 截图。若 A12b 观测窗口内无法到达该状态，如实记录未覆盖/N/A，不伪造。

### AC-12（A5，P0）R 键与重开按钮均可重开且无需刷新页面

- **前置条件**：完成一局并处于结算状态；记录页面 URL 与可见状态。
- **操作步骤**：① 按 R，观察新局状态；② 再结束一局，用鼠标点击「重开」按钮，观察；③ 全程不刷新页面，记录地址栏 URL 是否变化。
- **可观察期望结果**：R 键与「重开」按钮均立即开始新一局（按实现为 ready/playing，但蛇回到初始状态、可继续操作）；无二次确认弹窗；URL 不变、无整页刷新；按钮在页面中可点击且命中区域正确。
- **证据方式**：操作记录（URL 前后、触发方式、新局初始状态）+ 截图；P0 记录附 sidecar。

### AC-13（A6，P0）重开清零当前分蛇长速度并保留最高分

- **前置条件**：一局中吃到至少 5 个食物，使当前分 ≥50、蛇长显著增长、速度提升至下一档；记录当前分、可见蛇长、节拍速度与最高分 H。
- **操作步骤**：① 通过 R 或「重开」按钮触发重开；② 观察当前分、蛇长、初始速度；③ 观察最高分；④ 重开后开始移动，确认从初始状态运行。
- **可观察期望结果**：当前分清零为 0；蛇身恢复初始长度（3 格）与初始位置；速度恢复初始约 7 格/秒（不保留已提升档位）；最高分仍为 H 不被清零；重开后无残留暂停/结算提示。
- **证据方式**：操作记录（重开前后数值对比）+ 截图；P0 记录附 sidecar。

### AC-14（A6，P1）最高分在刷新页面后保留或按实测记录降级行为

- **前置条件**：记录浏览器版本与 `file://` 下存储可用性；将最高分提升到一个可辨识值 H（H>0）并结束一局以确保写入；记录操作记录。
- **操作步骤**：① 按 F5 刷新页面（或关闭标签后重新双击 `index.html`）；② 观察最高分面板与当前分；③ 用 DevTools → Application → Local Storage 查看 `snake-game.highScore.v1` 的值与类型。
- **可观察期望结果**：最高分刷新后仍为 H 且正常显示；当前分恢复为 0/待开始；存储键存在时其值仅为最高分整数，无其他个人信息。若目标浏览器策略禁止 `file://` 存储，如实记录实际可观察降级行为（如刷新后最高分重置）及浏览器版本，并在报告注明环境限制。
- **证据方式**：操作记录（刷新前后面板与存储值）+ 刷新前后截图 + 存储面板截图。

### AC-15（A7，P0）完整流程无未捕获异常且控制台无报错

- **前置条件**：DevTools Console 打开并清空；Network 面板可同时观察。
- **操作步骤**：执行完整流程「打开→开始→移动→吃至少 2 个食物→撞墙或自撞→结算→按 R 重开→再移动→P 暂停/继续→再结束」；全程保持 Console 可见，结束后检查所有消息。
- **可观察期望结果**：流程每一步均可完成；Console 无 error 级消息、无 uncaught exception、无资源加载失败；页面不白屏、不冻结、不弹出错误对话框；重开后流程可重复。
- **证据方式**：Console 截图/导出（含时间与消息级别）+ 操作记录；P0 记录附 sidecar。

### AC-16（A7/A9，P1）localStorage 不可用时降级为内存且不崩溃

- **前置条件**：准备一种可复核的存储不可用环境并记录方式与浏览器版本，例如：① 以 `--disable-local-storage` 启动参数打开 Chrome/Edge 后加载 `index.html`；或 ② 在页面脚本执行前通过 DevTools 注入使 `window.localStorage` 访问抛错的 shim（记录注入内容）。
- **操作步骤**：① 在该环境下打开页面；② 完整玩一局（吃食物、结束、重开、再玩）；③ 观察控制台与页面行为。
- **可观察期望结果**：页面正常启动、可开始与游玩；无未捕获异常、无崩溃、无白屏；当前分与最高分逻辑以内存值工作（同一会话内最高分仍可显示与更新）；刷新后最高分不保留属预期降级，须记录实际可观察行为；不得出现阻断流程的错误提示。
- **证据方式**：操作记录（启动参数/注入方式、实际观察）+ 控制台截图 + 页面截图。

### AC-17（A8，P1）单局帧率不低于 30fps 且无超过追赶上限的突跳

- **前置条件**：桌面 Chrome/Edge 最新稳定版，记录 `chrome://version`/`edge://version` 的精确版本号、操作系统与窗口尺寸（≥800×600）；关闭其他高负载程序；打开 DevTools，使用 `Ctrl+Shift+P` → `Show frames per second (FPS) meter` 显示帧率表（或使用 Performance 面板的 Frames 轨道）；若实现自带 FPS 显示，记录其数值并与 DevTools 交叉核对（实现未提供 FPS 显示不影响本项判定）。
- **操作步骤**：① 开始一局并持续操作（移动、转向、吃食物）至少 60 秒（单局不足 60 秒则累计多局至 60 秒，暂停时间不计入）；② 在观测窗口内记录平均 FPS 与最低 FPS（截图 FPS meter）；③ 同时观察蛇的移动是否有单帧超过 5 格的跳变或明显突跳。
- **可观察期望结果**：观测窗口内平均 FPS ≥30（FPS meter 持续显示在 30 以上，允许瞬时抖动但不得持续低于 30）；无单帧蛇位移超过 5 格（与架构 v1「每帧最多追赶 5 步」一致）；节拍不因卡顿出现明显突跳。
- **证据方式**：FPS meter/Performance 截图（含浏览器版本与窗口信息）+ 操作记录（观测起止时间、平均/最低 FPS、是否观察到突跳）。

### AC-18（A9，P1）无账号无联网不收集个人信息且存储仅最高分整数

- **前置条件**：断网；DevTools Network 与 Application → Local Storage 面板打开。
- **操作步骤**：① 完整玩一局并刷新一次，观察 Network 有无外部请求；② 查看 Local Storage/Cookies/Session Storage 内容；③ 检查页面是否存在登录、账号、昵称、邮箱或其他个人信息输入项；④ 检查有无第三方脚本、统计或遥测。
- **可观察期望结果**：无账号/登录入口与个人信息输入项；Network 无外部请求；存储中仅 `snake-game.highScore.v1` 一个整数值（或按 AC-16 降级时为空）；无 Cookie、无第三方脚本、无遥测/上报；不收集任何玩家个人信息。
- **证据方式**：Network 与 Application 面板截图 + 操作记录。

## 5. 判定与汇总口径（供 A12b 使用）

- A12b 按冻结的本文件（version 1，status final）与任务指定的最终完整 OID 对应实现执行核对；实现内容变更或候选漂移后，本标准不再直接适用，须重新确认版本与指定 OID 后重验。
- 每条标准按第 4 节的「可观察期望结果」给出通过/未通过/insufficient evidence；缺证据或仅有实现者描述的一律记 insufficient evidence，不得推断通过。
- P0 标准应全部通过；P1 未通过须在报告中列为缺陷并说明对 A1–A9 的影响；P2 为观察项，未覆盖或 N/A 须如实记录，不伪造通过。上述汇总用于 A12b 报告与返工建议，**不构成客户业务验收结论**；最终业务选择按固定路径流程由客户/幕僚收口。
- 任何标准执行中出现未捕获异常、控制台 error、白屏或流程阻断，均须连同 Console 原文与截图如实记录，不得以「可玩」描述覆盖失败证据。
