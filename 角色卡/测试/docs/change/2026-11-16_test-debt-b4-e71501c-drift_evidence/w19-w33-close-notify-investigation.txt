# W19/W33 close 通知语义调查（B4，产品候选——未改产品、未改断言）

## 结论（一句话）
`closeCreatedTask`（legacy 直能力）**从不调用** `notifyDirect`；`notifyDirect` 生产者只挂在
`activateRoleDocuments` / `completeTeamPlan` / `selectRunChange` 上。消费侧（队列 + trunk 分类）
完整实现了 close 通知的 information-only 退化，但**生产侧缺失**。W19/W33 因此 3/3 稳定红。
→ 判定为**产品缺口/回归候选**（不是测试期望过时）。按协调者裁定：停手、不改产品、
不改 W19 相关断言，先报告。

## 最小恢复建议（供协调者/owner 裁决，未实施）
在 `createDirectRoleRuntime.closeCreatedTask` 成功返回后复用同一 `notify(receipt)`：
```ts
}, closeCreatedTask: async (request, signal) => {
  if (signal?.aborted) return { … };
  const receipt = await service.closeCreatedTask(request, input.actorRoleId);
  const pending = await notify(receipt);
  return pending ? { ...receipt, ...pending } : receipt;
},
```
- notify() 已含幂等键（operationId+targetDigest+action+recipient）与 pending-recovery 语义；
- 队列的 `classifyClosedTaskNotice` 会把精确 close 事实退化为 information-only，不启动模型轮次
  （与注释「must not start unrelated model turns」不冲突；W19 :1505/:1533 即断言无新模型提示）；
- 需同批复跑 W19 + W33；W33 另有 /^run-docs-/ → /^run-hub-/ 的命名漂移（当前产品 hub 分支
  在 src/service/trunk/impl/apply-journal.ts:3841 生成 `run-hub-<hash>`），待 close 通知修复后
  可一并更新。
