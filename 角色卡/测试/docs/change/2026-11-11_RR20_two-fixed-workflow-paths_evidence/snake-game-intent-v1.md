# 贪吃蛇游戏 产品意图 v1

## 1. 目标用户与场景

单人本地娱乐的玩家（开发者本人、团队内部演示/试玩），在桌面电脑浏览器中打开即玩。单局时长几分钟，无需账号、无需联网、无需安装。

## 2. 要解决的问题

从零提供一个最小可玩的贪吃蛇：玩家用键盘控制蛇移动、吃食物得分、撞墙结束并可立即重开。核心价值是让玩家在零安装、零联网条件下快速完成「开始 → 吃分 → 撞墙 → 重开」的完整闭环，验证玩法成立。

## 3. 客户原话与约束

客户原话要点：「做一个贪吃蛇游戏」，四项需求：1) 键盘控制；2) 计分；3) 重开（重新开始）；4) 边界碰撞（撞墙判定）。

约束：
- 本 v1 仅覆盖最小可玩版本，不默认扩范围。
- 界面形态、计分权重、美术音效、排行榜、移动端等不确定项列入第 5 节非目标或第 8 节待澄清项，需客户澄清后另出版本。
- 交付形态为本地可直接打开的网页单页；不引入联网服务与第三方在线依赖。

## 4. 范围（v1 必须交付）

- **键盘控制**：方向键与 WASD 均可改变蛇的移动方向；禁止 180° 原地反向（反向输入被忽略）；蛇只能沿上/下/左/右四方向移动，不出现斜向。
- **计分**：初始分数为 0；每吃到一个食物分数增加（默认每个食物 +1 分）；当前分数在游戏画面中实时可见。
- **重开**：本局结束后按 R 或空格可开始新一局；新一局分数归 0、蛇回到初始长度与位置、食物重新生成。
- **边界碰撞**：蛇头碰到任一游戏区域边界即本局立即结束，界面显示「游戏结束」与本局最终分数，蛇停止移动与计分。
- **基本呈现**：单一游戏区域内以网格呈现蛇与食物，蛇按固定节拍移动；食物随机生成在区域内的空格上。
- **可直接运行**：本地浏览器打开即可游玩，无需联网、无需账号、无第三方在线服务依赖。

## 5. 非目标（v1 明确不做）

- 联网、多人对战、在线排行榜；账号、云端存档
- 美术素材、音效、动画特效
- 移动端触控与响应式适配
- 穿越边界（wrap）、暂停、加速等级、障碍物、关卡系统
- 蛇自撞作为结束条件的强化规则（自撞是否结束本局列入待澄清，v1 仅以撞墙作为结束条件）
- 最高分持久化、历史记录
- 高 DPI、可访问性等交付级打磨

## 6. 验收标准

- **AC1 键盘控制**：按方向键或 WASD 均能改变蛇的移动方向；按与当前方向相反的键时蛇不反向（该输入被忽略）；蛇始终沿四方向之一移动，不出现斜向移动。
- **AC2 计分**：开场分数为 0；每吃到一个食物分数 +1；分数在游戏画面中实时可见；本局结束后分数保持显示直至重开。
- **AC3 重开**：撞墙结束并显示结束信息与最终分数后，按 R 或空格可开始新一局；新一局分数归 0、蛇回到初始长度与位置、食物重新生成，游戏可正常继续。
- **AC4 边界碰撞**：蛇头接触任一边界时本局立即结束，蛇不再移动、不再计分；界面明确显示结束状态与本局最终分数。
- **AC5 可玩闭环**：在无安装、无联网的本地浏览器环境中，玩家能完成「开始 → 移动 → 吃到食物 → 撞墙 → 重开」的完整流程，过程无崩溃。

## 7. 质量档位

v1 按「可玩原型 / 内部演示」档：逻辑正确、操作可感知、无崩溃、界面可读；不要求美术、音效与交付级打磨。若客户后续要求交付级质量（视觉/音效/移动端等），通过新版本意图升级处理，不在 v1 内追加。

## 8. 待澄清项（不阻塞 v1 受理，客户确认后可在后续版本调整）

- 界面形态：默认浏览器单页；若客户希望终端字符界面或其他形态，需另行确认。
- 计分权重：默认每个食物 +1 分；是否随蛇长/速度加权待确认。
- 最高分持久化：v1 不做，是否需要由客户后续决定。
- 蛇自撞：v1 不作为结束条件，是否纳入由客户后续决定。
- 移动速度/节拍：v1 采用固定节拍，具体快慢可在验收试玩时微调。
