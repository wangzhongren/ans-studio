# 贪吃蛇游戏 · 产品意图（snake-game-core v1）

## 一、背景与客户原话

客户需求（原话摘要）：贪吃蛇游戏，支持键盘控制、计分、重开、边界碰撞（撞墙即结束）。

本意图只定义「做什么、做到什么程度」，不定义实现方案。方案与名单由策划在后续阶段产出，不在本文档范围内。

## 二、目标用户与场景

- 目标用户：希望快速上手、即开即玩的小游戏玩家；以及需要对交付物进行功能验收的项目参与者。
- 使用场景：在桌面电脑的现代浏览器中打开游戏，无需安装、无需构建、无需联网，即可开始一局；随时关闭页面结束使用。
- 使用门槛：无需注册登录，无需教程即可理解方向键、分数与重开操作。

## 三、要解决的问题

当前没有可玩的贪吃蛇交付物。本版要解决的是：提供一个零依赖、可快速打开、规则完整且可重复验收的贪吃蛇小游戏，覆盖「移动—进食—计分—撞墙结束—重开」的完整闭环。

## 四、范围与非目标

### 范围内

1. 键盘方向键（含 WASD 可选）控制蛇移动。
2. 食物生成；蛇头吃到食物后分数增加，蛇身增长，并生成新食物。
3. 边界碰撞：蛇头撞到游戏区域边界（墙）即游戏结束。
4. 游戏结束后可重开：分数归零，蛇与食物回到初始状态。
5. 基础游戏画面：游戏区域、蛇、食物、当前分数、结束提示。
6. 运行方式：单文件、浏览器直接打开即可运行。

### 非目标（本版明确不做）

1. 不做网络多人对战、联机或观战。
2. 不做持久化排行榜、账号体系或历史成绩存档。
3. 不做移动端触控、虚拟摇杆或手柄支持。
4. 不做音效、复杂动画与美术资源。
5. 不做后端服务、数据库与用户数据采集。
6. 不做暂停、加速等级、穿墙模式、障碍物等扩展玩法。

## 五、运行方式取舍与理由

**选择：单文件浏览器方案**——交付一个 `index.html`，HTML/CSS/JS 全部内嵌，双击或用现代桌面浏览器直接打开即可运行，无构建步骤、无包管理、无网络依赖。

理由：
- 零依赖、零安装，最容易被客户和验收者直接打开验证，符合「即开即玩」。
- 无需探测或绑定本机工具链，交付与验收不受环境差异影响，结果可复现。
- 单文件便于完整审阅与分发，范围小、风险低，与本版质量档位匹配。

不选择终端程序或桌面应用，是因为它们要求特定运行环境与额外启动步骤，验收成本和环境不确定性更高，而本版不需要这些能力。

## 六、功能规则（本版口径）

- 蛇在网格上按固定节奏移动；初始方向向右，初始分数为 0。
- 方向键控制：按上/下/左/右改变蛇的移动方向。**不允许 180° 直接反向**：若输入方向与当前前进方向相反，则忽略该输入，避免瞬间反向自杀；同方向或垂直方向输入正常生效。
- 计分：蛇头进入食物所在格时，分数增加固定值（本版为 10 分），蛇身增长一格，食物在未被蛇占据的格子重新生成。
- 结束：蛇头越出游戏区域边界（撞墙）即判定游戏结束，停止移动与计分，显示结束提示与最终分数。
- 重开：结束状态下通过重开操作（如「重开」按钮或 R 键）开始新一局；分数归零，蛇回到初始位置与初始方向，食物重新生成。
- 本版不处理「蛇头撞到自身」的判定；该行为不列入本版范围与验收。（如后续需要再立项变更。）

## 七、验收标准（可验证）

- **AC1 能启动运行**：在现代桌面浏览器中直接打开 `index.html` 即可开始游戏，无需安装依赖或构建；页面加载后无阻断性脚本错误，可见游戏区域与初始分数 0。
- **AC2 键盘控制与禁止反向**：按方向键后，蛇在下一移动节拍沿对应方向移动；与当前前进方向相反的输入被忽略，蛇不会立即 180° 反向。
- **AC3 吃食物加分**：蛇头到达食物所在格时，分数增加（本版 +10），蛇身增长，并在空位生成新食物。
- **AC4 撞墙即结束**：蛇头越过游戏区域边界时，游戏立即结束，显示结束状态与最终分数，之后方向输入不再改变游戏状态。
- **AC5 重开且分数归零**：结束状态下执行重开操作后开始新一局，分数显示为 0，蛇回到初始位置与初始方向，可再次正常操作。

验收方式：在桌面浏览器中按上述场景逐项实际操作核对，五项全部满足即视为本版验收通过。

## 八、客户原话与约束

- 客户原话摘要：贪吃蛇游戏；键盘控制；计分；重开；边界碰撞（撞墙即结束）。
- 约束：
  1. 运行方式采用单文件浏览器方案（见第五节）。
  2. 无外部依赖、无构建、无网络请求。
  3. 不采集、不上传任何用户数据。
  4. 功能以本文档范围为限，超出部分按非目标处理。

## 九、质量档位

本版质量档位为**基础可玩（功能完整、可复现验收）**：

- 必备：上述 AC1–AC5 全部通过，规则行为确定、可重复验证。
- 必备：零依赖、可直接打开运行，交付物可被完整审阅。
- 不要求：生产级健壮性、跨浏览器兼容矩阵、性能压测、无障碍与视觉设计深度、自动化测试体系。
- 结论口径：以实际操作为准，不用主观「体验好」替代 AC 判定。

## 十、待确认事项

- 若客户对运行方式（单文件浏览器）或计分分值（10 分）有不同要求，需在意图确认阶段澄清后出新版本，不原地修改本版。
- 「蛇头撞自身」本版不纳入范围；如客户要求，需走变更出新版本。
