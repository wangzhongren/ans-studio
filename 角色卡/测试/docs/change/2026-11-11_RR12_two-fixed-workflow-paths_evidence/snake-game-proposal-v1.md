# 提案：贪吃蛇游戏（snake-game）v1

> 本文件为 A5 方案阶段的提案建议，依据已确认的产品意图 `docs/product/snake-game-intent-v1.md`（v1，intentId=snake-game）。
> 提案本身不构成客户批准；方案卡由幕僚呈报客户确认，确认后才进入实现与验收。本文件不做客户未授权的范围扩张。

## 1. 意图对齐

- 意图文档：`docs/product/snake-game-intent-v1.md`（`schema: project-intent/v1`，version 1）。
- 意图入口：`docs/intents/snake-game.md`（intentId=snake-game）。
- 目标：交付可单机游玩的贪吃蛇游戏——键盘（方向键/WASD）控制、吃食物计分并显示、撞墙结束、结束后重开整局重置。
- 范围与充分性：本提案覆盖意图四项核心能力；意图非目标（联网/多人/排行榜/账号、服务端与持久化、移动端触控、最高分/音效/暂停/难度/皮肤）一律不纳入本期。
- 意图留待方案阶段确定的细节（技术选型、交付形态、计分增量、重开触发、结束反馈、场地与速度参数）在本提案第 3、4 节给出具体建议，均不违背意图验收标准。

## 2. 方案概述

### 2.1 技术选型与交付形态（方案建议）

- 技术栈：原生 HTML + CSS + JavaScript（ES2015+），画面使用 Canvas 2D 绘制；不使用第三方框架与构建工具。
- 交付形态：单页静态站点，**零构建、零依赖安装**；本地用浏览器直接打开项目根目录的 `index.html` 即可游玩（`file://` 协议可运行），不依赖网络、服务器、后端或持久化存储。
- 运行前提：桌面浏览器（Chromium 内核浏览器、Edge、Firefox 等现代浏览器）；不使用任何需要网络加载的 CDN 资源。
- 理由：与意图「单机本地运行、不依赖网络与后端」及「交付形态由方案阶段决定」一致；零构建形态最小化环境风险与交付成本，适合本规模游戏。

### 2.2 质量档位（方案建议）

- 建议档位：**可用级**（意图界定的「原型级→可用级」区间的上端）。
- 含义：功能完整、可直接游玩、无阻断性缺陷，含基本自检说明；不要求生产级性能优化、跨浏览器兼容矩阵与自动化测试套件，但需按验收标准 A1–A4 提供可观察的验收证据。
- 最终档位以客户在方案卡的确认结果为准。

### 2.3 模块与属主（详见模块清单与名单）

- 固定环境/入口：`env-bootstrap` 角色持有 `env-resources`（`README.md`，category=env）与 `entry-index`（`index.html`，category=entry）。
- 游戏实现：`game-implementer` 角色持有 `game-core`（`src/core/`）、`input-controller`（`src/input/`）、`renderer`（`src/render/`）、`game-shell`（`src/app/`）。
- 模块划分与属主以 `docs/proposals/snake-game-modules-v1.md` 与 `docs/proposals/snake-game-roster-v1.md` 为准；本提案不复述其字段。

## 3. 功能设计（对应意图 A1–A4）

### 3.1 游戏参数（方案建议）

- 场地：20×20 网格，网格线可见。
- 蛇初始：长度 3 格，位于场地中部，初始向右移动。
- 移动节拍：固定约 8 格/秒，不随分数加速（速度加速不纳入本期）。
- 食物：随机生成于空格子；同一时刻场上 1 个食物；被吃掉后立即在空格子中重新生成。
- 计分：每吃到 1 个食物 +1 分；吃到食物时蛇身增长 1 格（增长为常见玩法细节，非意图强制项，仅在提案中确定）。
- 自撞：按意图假设，蛇撞到自身**不结束本局**（本期不纳入强制规则，也不作为验收项）；如需纳入，应在后续版本或意图变更后处理。
- 重开：本局结束后可重开；重开后蛇、分数、食物与移动时钟全部回到初始状态，不残留上一局状态。

### 3.2 键盘控制（A1）

- 方向键（↑↓←→）与 WASD（W/A/S/D）等价生效，分别映射上/下/左/右。
- 每次按键改变下一次 tick 的移动方向；同一时刻只保留一个待生效方向。
- 与当前运动方向反轴的输入被忽略（避免瞬间反向自撞），不改变当前方向。
- 不依赖鼠标、触控或其他输入即可完成全部控制。

### 3.3 计分显示与增长（A2）

- 页面固定区域（画布上方信息栏）实时显示「分数：N」，初始为 0。
- 吃到食物后分数 +1 并即时刷新显示；未吃到食物时不变化。

### 3.4 撞墙结束与结束反馈（A4）

- 判定：蛇头下一步移动到网格边界之外（越界）时，本局立即结束；本 tick 之后不再推进蛇身。
- 反馈：画布上叠加结束遮罩，显示「游戏结束」、本局得分与「按 Enter / Space 或点击「重开」按钮重新开始」提示；同时停止移动循环，忽略方向输入。

### 3.5 重开（A3）

- 触发方式：结束后按 Enter 或 Space，或点击界面上的「重开」按钮（两种方式均支持，键盘方式保证无需鼠标）。
- 行为：分数归零、蛇恢复初始长度与位置方向、食物重新随机生成、移动循环重启；重开后立即可继续游玩。
- 运行中不提供中途重开（避免与本意图验收口径混淆）；如需中途重开，属后续扩展。

## 4. 非功能与实现约束

- 单机离线：所有资源本地加载，无网络请求、无后端、无持久化（含无最高分持久化）。
- 代码组织：按模块清单的目录边界分离核心规则、输入、渲染与调度；核心规则不直接依赖 DOM/Canvas，便于独立校验。
- 可观察性：分数、结束状态、重开结果均可由界面直接观察，满足人工试玩验收；实现方需在 `README.md` 记录运行方式与操作说明。
- 兼容与性能：以现代桌面浏览器为目标；单机游戏规模，无额外性能指标要求。

## 5. 与意图验收标准 A1–A4 的映射

| 意图验收 | 方案承接 |
| --- | --- |
| A1 键盘控制 | `input-controller` 将方向键/WASD 等价映射为方向；`game-core` 按方向推进；全程无需鼠标。 |
| A2 计分显示与增长 | `game-core` 进食判定与计分；`renderer` 实时显示分数；未进食不变。 |
| A3 重开可用 | `game-shell` 处理结束后的重开触发；`game-core.reset` 整局重置；重开后可立即继续。 |
| A4 撞墙结束 | `game-core` 越界判定使本局立即结束；`renderer`/`index.html` 呈现结束遮罩与提示。 |

正式的 `ans-criteria/v1` 验收标准块不在本提案写区（规范路径 `docs/acceptance/`），按分工由验收/验证责任方依据本提案与意图产出；本提案仅提供上述映射建议。

## 6. 实施步骤（建议顺序）

1. 环境与入口：`README.md` 运行说明、`index.html` 页面结构与脚本装配（env-bootstrap）。
2. 核心规则：`src/core/` 状态机（移动、食物、计分、越界、重置）。
3. 输入与渲染：`src/input/` 键位映射、`src/render/` Canvas 绘制与结束遮罩。
4. 调度装配：`src/app/` 主循环串联与重开触发。
5. 自检与验收：按 A1–A4 逐项人工试玩自检并留存可观察证据；由独立验证方按验收标准核对。

## 7. 风险与待确认（不代替客户决定）

- 技术选型/交付形态（原生 JS + Canvas、双击 `index.html` 运行）为本提案建议，须经客户在方案卡确认；若客户指定其他形态（桌面可执行、命令行、框架/构建链），需升提案版本并重定模块划分。
- 质量档位「可用级」与需求方/客户确认结果不一致时，按确认结果调整验收深度。
- 玩法细节（场地 20×20、8 格/秒、每食物 +1 分、增长、自撞不结束、Enter/Space/按钮重开）为方案阶段裁量项；如客户有其他偏好，在不违背意图验收标准的前提下调整并升版。
- 自撞、音效、暂停、最高分等属意图非目标或未强制项，本期不实现；将其写入本期会扩大已确认意图范围，须走意图变更而非在本提案内扩张。
- 无构建工具链意味着无自动化测试基线；可用级档位下以人工试玩 + 可观察证据为主要验收方式，验收标准落盘分工需上游确认。
