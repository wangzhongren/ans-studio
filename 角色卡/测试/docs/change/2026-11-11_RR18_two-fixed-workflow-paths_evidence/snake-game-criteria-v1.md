## 一、适用环境与前置

1. 环境：Windows 桌面，现代桌面浏览器（Chrome 或 Edge 任一即可），**直接双击 `index.html`** 以 `file://` 打开；不启动本地服务器、不做构建、不安装依赖、不联网。
2. 前置：实现已按契约落盘 `index.html` 与 `src/game.js`、`src/render.js`、`src/input.js`、`src/style.css`；A12b 任务会给出被验的最终完整 OID，验收只针对该 OID 的内容。
3. 允许的辅助手段：浏览器开发者工具（Console / Network / Elements）观察、代码走查。不引入任何测试运行时依赖，不得改变交付形态。
4. 实测为主、走查为辅：每一条 AC 至少有一次真实浏览器操作观察；不得以代码推断替代实测通过。

## 二、验收强度（质量档位）

- 档位：**最小可玩版**——四项功能（AC1–AC4）完整可用、无阻塞性缺陷（无法开局 / 崩溃 / 分数错乱 / 重开失效），操作响应无明显延迟（按键到方向生效在视觉上即时，不出现持续 0.5 秒以上的无响应）。
- 调节的是核对深度，不是如实性：缺证据一律记 `insufficient evidence`，不判通过、不代造证据。

## 三、逐条验收方法

### AC-1 键盘控制与反向拦截（P0）

依据：意图 AC1；契约 §2 `setDirection`、§4 输入层、§6.1–§6.2；架构「初始方向向右」。

判定步骤（V 为可独立勾选的观察步骤）：

- V1.1 打开 `index.html` 后不做任何输入，蛇按固定节拍自行向右持续移动，未立即结束。
- V1.2 按 `↑`：蛇改变为向上并持续移动（观察至少 3 个步进）。
- V1.3 按 `←`：蛇改变为向左并持续移动。
- V1.4 按 `↓`：蛇改变为向下并持续移动。
- V1.5 按 `→`：蛇改变为向右并持续移动。
- V1.6 反向拦截（至少三组组合，每组一次）：
  - 向右移动时按 `←`；
  - 向上移动时按 `↓`；
  - 向左移动时按 `→`。
  观察：蛇不调头、不立刻自杀，仍按当前方向继续移动。
- V1.7 同一 tick 内快速连按两个不同方向（如向右行进中先按 `↑` 再按 `↓`），蛇不得出现 180° 反向，只接受合法方向。

通过条件：V1.1–V1.7 全部符合。不通过条件（任一即失败）：方向键无响应、蛇不移动或停止、反向输入导致调头/自杀、方向改变后不持续移动。

观察项（不单独判定 AC-1 失败，记入 P1.2）：方向键是否会滚动页面（契约要求 `preventDefault`）；WASD 等附加键位是否存在（可选，非必需）。

### AC-2 计分与增长（P0）

依据：意图 AC2；契约 §6.3–§6.4；架构「初始分数 0、每食物 +1」。

- V2.1 开局时 `#score` 文本为 `0`。
- V2.2 控制蛇吃到第 1 个食物：记录吃前截图（分数、蛇长），吃后 1 个 tick 内食物消失、`#score` 变为 `1`、蛇身长度 +1。
- V2.3 连续吃到第 2、3 个食物：分数依次为 `2`、`3`，蛇身长度依次累加，食物每次在非蛇身空格重新出现。
- V2.4 未吃食物期间（空转至少 3 秒）分数不因时间或蛇长变化而增减。
- V2.5 显示与状态一致：`#score` 数值与渲染层读取的核心分数一致（走查 `render.js` 更新来源为 `getState().score`，且每 tick 后刷新）。

通过条件：V2.1–V2.5 全部符合。不通过条件：初始非 0、食物不消失、分数不加/多加/错乱、蛇不增长、显示滞后超过一个 tick 或与状态不一致。

### AC-3 结束展示与重开（P0）

依据：意图 AC3；契约 §3 重开与 UI、§6.6–§6.7。

- V3.1 制造一次撞墙结束（可复用 AC-4 步骤），确认 `#status` 显示结束态文案且含最终分数，文案中的分数等于结束前 `#score` 数值。
- V3.2 确认 `#restart` 重开入口在结束态可见且可点击（同时走查/实测 `r`、`R` 重开键是否可用——键位为契约 §4 附加，非意图必需，缺失记观察项）。
- V3.3 重开后 `#score` 立即回到 `0`。
- V3.4 重开后蛇回到与开局相同的位置与长度（用开局截图与重开后截图对比），方向复位为向右。
- V3.5 重开后食物重新生成，且不与蛇身重叠。
- V3.6 重开后立即按方向键，蛇立刻响应并继续移动（可立即操作），不出现无响应或需要额外点击画布才生效。

通过条件：V3.1–V3.6 全部符合。不通过条件：无结束提示或无最终分数、无重开入口、重开不生效、分数不清零、蛇/食物不复位、重开后不可操作。

### AC-4 边界碰撞即 game over（P0）

依据：意图 AC4；契约 §6.5–§6.6（`x<0 || x>=cols || y<0 || y>=rows` 即 `over`，不穿墙、不夹取）。

- V4.1 让蛇朝边界直行（如持续向上），观察蛇头到达最后一格后，**下一个 tick 立即结束**，不越界绘制、不从对侧出现（不穿墙）。
- V4.2 结束瞬间截图确认蛇头停在界内最后一格（20×20 网格内），不存在半格越界或飞出画布。
- V4.3 结束后等待至少 2 秒：蛇不再移动、`#score` 不再变化、界面保持结束态。
- V4.4 结束后依次按四个方向键：蛇仍不移动、分数不变。
- V4.5 至少实测两条不同的边界（如右边界与上边界）；其余边界不单独实测，由 P1.2 代码走查覆盖越界判定。

通过条件：V4.1–V4.5 全部符合。不通过条件：越界后仍继续移动、穿墙到对侧、结束后仍响应方向输入并移动、结束后分数仍变化。

### P1.1 交付形态与可开局（P0）

依据：意图「运行形态 / 范围」与质量档位「无阻塞性缺陷」；契约 §5（零外部资源）、架构「单页静态网页，双击即运行」。

- V5.1 从项目文件夹双击 `index.html`，浏览器以 `file://` 打开后 3 秒内呈现可玩的游戏区域（非空白画布、无需构建步骤、无「需要服务器」类失败）。
- V5.2 开发者工具 Network 面板无任何外部网络请求；Elements 走查无外部 CDN / 字体 / 图片引用，脚本为经典 `<script src>`（非 `type="module"`）。
- V5.3 全流程（开局 → 移动 → 吃食物 → 撞墙结束 → 重开）无页面崩溃、无冻结、无「无法开局」。
- V5.4 断网状态下上述流程同样可用（本机离线即视为等同于离线）。

通过条件：V5.1–V5.4 全部符合。不通过条件：需要构建/服务器才能运行、依赖外部资源、页面崩溃或冻结、无法开局。

### P1.2 契约结构走查（P1，辅助）

对照 `docs/contracts/snake-game-contract-v1.md` §2–§5 走查并记录（不改代码）：

- V6.1 `index.html` 含固定 id：`#game-canvas`（`<canvas width=400 height=400>`）、`#score`、`#status`、`#restart`；样式 `src/style.css` 以 `<link rel="stylesheet">` 引入。
- V6.2 脚本加载顺序 `src/game.js` → `src/render.js` → `src/input.js`，均为经典脚本。
- V6.3 `src/game.js` 以 IIFE 挂载 `window.SnakeGame`，暴露 `create/start/step/setDirection/reset/getState`；除命名空间挂载外不访问 DOM、事件或定时器。
- V6.4 越界判定为 `x<0 || x>=20 || y<0 || y>=20` 即 `over`；`over` 后 `step()` 为空操作。
- V6.5 反向拦截在 `step()` 时以当前生效方向校验 `pendingDirection`（快速连按不能绕过）。
- V6.6 tick 常量为 130ms 且不随分数变化；`over` 后停止计时器；重开只保留一个计时器。
- V6.7 网格 20×20、初始蛇长 3、初始方向向右、初始分数 0、每食物 +1；`reset()` 清空 `pendingDirection` 并复位分数/蛇/食物/状态。
- V6.8 输入层对方向键 `preventDefault`，且不直接写蛇坐标/食物/分数/状态字段。

判定：逐条记录符合/偏差。凡偏差导致 AC-1–AC-4 或 P1.1 判定改变者，按对应 P0 条目不通过处理；其余偏差作为观察项写入报告，不单独阻断通过。

### P1.3 稳定性与无报错（P1，辅助）

- V7.1 开局、吃食物、撞墙结束、重开各阶段，开发者工具 Console 无未捕获异常（uncaught error）。
- V7.2 连续重开 3 次：每局速度与首局一致，不出现加速/双倍步进（无计时器叠加）。
- V7.3 结束后静置 3 秒，状态与分数不变化；重开后不出现方向残留导致的立即反向或立刻撞墙。

判定：出现未捕获异常或计时器叠加导致的加速/错乱 → P1.3 不通过，并在报告列为缺陷；若该缺陷造成崩溃或分数错乱、重开失效，则按 P0 阻塞性缺陷处理。

## 四、总体判定规则

1. 全部 P0 条目（AC-1、AC-2、AC-3、AC-4、P1.1）均通过，且 P1.2 / P1.3 无阻塞性缺陷 → 建议「通过」（最终业务选择不由验收人作出）。
2. 任一 P0 条目不通过 → 结论「不通过」，列明失败条目、复现步骤与观察证据，按新 attempt 回 A11 返工。
3. 任一 P0 条目缺少真实证据 → 该条记 `insufficient evidence`，整体不得判通过。
4. P1 观察项在报告中如实列出，但不单独否决；不得把观察项夸大为通过结论，也不得隐瞒偏差。
5. 只对 A12b 任务指定的最终完整 OID 判定；候选漂移或内容已变，不判通过并如实回报来源链。

## 五、证据方式与命名

1. 实测为主证据：浏览器操作截图（可加简短文字记录）。
   - 截图路径：`docs/verification/snake-game-ac<N>-<slug>.png`（如 `snake-game-ac2-score.png`）。
   - 每张 P0 证据必须配同名 sidecar `<artifact>.meta.json`，其中 `acIds` 覆盖对应 criteria id（如 `AC-2`），并记录实际 `lines` / `bytes` / `sha256` / `metrics`；三者与 sidecar 不一致按 mismatch 处理，不得宣称通过。
   - metrics 建议记录观察值，例如：分数序列、蛇长、结束提示文本、重开前后分数与坐标、步进次数。
2. 代码走查证据：`docs/verification/snake-game-walkthrough-record.md`，逐条对应 V6.x，引用文件与代码片段（不给外部链接）。
3. 报告：`docs/quality/snake-game-report-v1.md`，逐条给出 AC 判定（通过/不通过/insufficient evidence）、证据路径、复现步骤与结论；报告结论须与证据一致。
4. 不要求录屏；缺录屏不判失败。证据文件一律使用纯项目相对路径。
5. 不伪造、不改写证据；需要重跑时重新生成证据与新 sidecar。

## 六、非验收项（明确不要求）

- 性能数值指标（帧率、内存）、跨浏览器全覆盖（仅需 Chrome 或 Edge 任一现代桌面浏览器跑通）。
- 移动端触控、手柄、联网对战、账号与持久化、排行榜、关卡/难度/暂停/道具/加速。
- WASD 等附加键位（可选，仅记观察项）。
- 满盘无可放食物格的情形（契约 §6.8 的确定性处理，不作为验收项）。
- 部署上线、安装包、兼容性矩阵。
