# snake-game 产品意图 v1

- flowId：`snake-game`
- workflowId：`wf-5f518ee14f687c8c8f3c6966`
- 版本：v1（版本化：新需求/变更出新版本 v2、v3…，本版只读）
- 意图入口：`docs/intents/snake-game-playable-intent.md`（intentId 与本文件 frontmatter 一致）

## 一、目标用户与场景

- **目标用户**：客户本人及少量同事/朋友，在 Windows 桌面上想快速玩一局小游戏，用于功能验收与轻度娱乐。
- **使用场景**：拿到项目文件后直接打开入口页面即可开始一局；一局通常几十秒到几分钟；结束时看到分数，想再来一局时一键重开。
- **环境假设**：现代桌面浏览器（Chrome/Edge 等），本地文件打开，离线可用，不需要安装任何运行时或依赖。

## 二、要解决的问题

1. 客户需要「一个能真正玩起来的贪吃蛇」，而不是设计稿或半成品。
2. 需要四项核心行为全部可用：键盘控制、计分、重开、撞墙即结束。
3. 需要一个**可独立验收**的明确口径：验收人不必追问「撞墙是结束还是阻止移动」这类歧义，按 AC1–AC4 逐条实测即可判定通过/不通过。
4. 客户未指定运行形态与技术栈，需要一个不增加环境负担的合理默认，避免验收被构建、联网、依赖安装阻塞。

## 三、范围

### 3.1 范围内（v1 必须有）

1. **运行形态**：单页静态网页（HTML/CSS/JS），无构建、无后端、无联网，直接打开入口页面可玩。
2. **键盘控制**：方向键上/下/左/右控制蛇的移动方向；蛇按固定节拍持续前进；禁止 180° 反向调头。
3. **计分**：初始 0 分；吃到食物该食物消失、分数 +1、蛇身增长；分数实时显示。
4. **重开**：一局结束后展示结束状态与最终分数，并提供重开入口；重开后分数清零、蛇复位、食物重新生成，立即进入可操作状态。
5. **边界碰撞**：蛇头越出游戏区域边界即本局结束（game over），不穿墙、不阻止移动；结束后停止移动直到重开。
6. **游戏区域与食物**：固定大小网格游戏区域；场上有食物，位置随机且不与蛇身重叠。

### 3.2 范围外（non-goals）

- 穿墙模式、难度/关卡、随分数加速、暂停、道具、排行榜、存档读档；
- 移动端触控、手柄、联网对战、账号与后端数据；
- 美术/音效资源与视觉打磨；
- 安装包、部署上线、兼容性矩阵测试。

## 四、成功/验收标准（可勾选）

> 验收方式：以现代桌面浏览器直接打开入口页面，按下列条目逐条实测；条目全部满足即意图达成。

- [ ] **AC1 键盘控制**：开局后按方向键，蛇按对应方向改变走向并持续移动；反向 180° 输入不生效（不原地调头）；方向键为必需键位，WASD 等为可选附加。
- [ ] **AC2 计分**：初始分数 0；吃到食物后食物消失、分数 +1、蛇身增长、分数显示实时更新。
- [ ] **AC3 重开**：撞墙结束后显示结束状态与最终分数并提供重开入口；重开后分数归 0、蛇复位至初始位置与长度、食物重新生成、可立即继续操作。
- [ ] **AC4 边界碰撞（game over）**：蛇头越出边界即立即结束本局，不穿墙、不被阻止；结束后无法继续移动，仅可重开。

**质量档位**：可独立验收的最小可玩版——四项功能完整、无阻塞性缺陷（无法开局/崩溃/分数错乱/重开失效）、操作响应无明显延迟；不要求美术、音效、性能优化或跨浏览器全覆盖。

## 五、客户原话与约束

**客户原话要点（原样保留）**：「在当前项目里做一个贪吃蛇游戏，要求：键盘控制、计分、重开、边界碰撞（撞墙判定）。」

补充口径（来自本次 A2 派发，待 A3 客户确认）：
- 计分为「吃到食物加分」；
- 重开为「一局结束后可重新开始，分数重置」；
- 边界碰撞为「撞到边界即本局结束（game over）」；
- 运行形态/技术栈客户未指定，本意图采用「可直接打开的静态网页版，无需构建/联网」为默认，客户可在 A3 确认或要求修订。

**约束**：
1. 默认假设须显式告知客户，客户 A3 未反对即视为接受；若客户要求改为其他运行形态，本意图升版为 v2。
2. 不引入外部素材与第三方依赖。
3. 实现方案与文件结构不在本意图内定，由 A4 提案/模块清单承接。
4. 计分粒度、网格步进、重开即时生效等行为口径以本意图为准。
