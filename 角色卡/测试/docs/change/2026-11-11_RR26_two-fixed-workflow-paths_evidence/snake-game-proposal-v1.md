# snake-game 策划方案 v1

> 依据产品意图：`docs/product/snake-game-intent-v1.md`（v1，intentId=snake-game-intent，客户已在 A3 意图确认卡确认）。本方案在意图范围内制定实现与协作方案，不改变意图；如客户提出不同选择，另出意图 v2 与新的提案版本。

## 1. 方案概述
交付一个零依赖、零构建的浏览器端单页贪吃蛇：`index.html` + `styles.css` + `src/game.js`（传统 script，非 ES module），在桌面 Chrome/Edge 中双击本地文件即可游玩。20×20 网格、单格 20px；方向键与 WASD 双键位、禁止 180 度反向；蛇按固定步长自动前进；吃到食物 +1 分、蛇身增长；撞墙或撞到自身立即结束并展示本局得分；会话内最高分实时维护且不持久化；结束页「重开」按钮或 R 键开新局，分数清零、最高分保留；纯色几何画面、无音效、仅桌面键鼠。

## 2. 技术选型与取舍
| 取舍点 | 推荐方案 | 备选 | 理由与风险 |
| --- | --- | --- | --- |
| 运行形态 | 静态文件 + 传统 `<script>`，零依赖零构建 | 引入打包器/框架 | 意图要求本地直接打开；打包与依赖会违背「打开即玩」并增加验收风险 |
| 脚本加载 | 经典 script（非 ES module） | `type="module"` | `file://` 下 ES module 受 CORS 限制会直接违反 A10，故不采用 |
| 渲染 | Canvas 2D（400×400）+ DOM HUD/结束层 | 400 个 DOM 格子 | Canvas 代码量小、契合纯色几何；DOM 备选便于无障碍，但非本期目标 |
| 实现组织 | 单一实现模块 `src/game.js`，文件内按规则/应用/渲染/输入分区 | 拆多个游戏模块 | 小体量下拆分增加交接成本；规则函数保持纯函数并允许注入随机源以缓解耦合风险 |
| 节奏 | `setInterval` 固定约 130ms/步（约 7.7 步/秒），不随分数加速 | 帧驱动 + 累积器 | 固定步长更简单可复现；页面隐藏节流后只推进单步，避免多步追赶 |
| 计分与最高分 | 每食物 +1；最高分为内存变量，实时更新，刷新重置 | 持久化最高分 | 意图明确不做持久化（A8 预期行为） |

## 3. 与意图验收逐条对应（A1–A10）
| 验收 | 实现要点 |
| --- | --- |
| A1 启动可见 | `index.html` 渲染 400×400 画布、当前分数、会话最高分、操作提示；`init()` 后主循环立即启动，蛇自动前进 |
| A2 键盘控制 | `keydown` 映射方向键与 WASD，写入 `pendingDirection`，在下一个 tick 生效 |
| A3 反向保护 | 接受输入时与当前方向比较，反向输入直接忽略：不改变方向、不掉头、不致死 |
| A4 吃食物计分 | 蛇头进入食物格即 `score += 1`、HUD 同步更新、蛇身长度 +1（不删尾），食物在非蛇身非边界的随机空格重生 |
| A5 撞墙结束 | 蛇头越界（`x<0 / x>=20 / y<0 / y>=20`）立即结束，不穿墙，展示结束信息与本局得分 |
| A6 撞自身结束 | 新蛇头与自身身体段重合即立即结束，展示结束信息与本局得分 |
| A7 结束态冻结 | 结束后停止主循环，方向输入被忽略，画面保持结束状态 |
| A8 最高分（会话内） | `highScore = max(highScore, score)`，超过时立即更新显示；结束页并列展示本局得分与最高分；不使用任何存储 API，刷新即重置 |
| A9 重开 | 结束层「重开」按钮或 R 键均可开新局：分数归零、蛇与食物复位、会话最高分保留 |
| A10 运行质量 | 桌面 Chrome/Edge 最新版 `file://` 直接打开可运行；无网络请求、无控制台报错；行为可由人工试玩逐条观察判定 |

## 4. 文件组织与交付物
| 文件 | 属主模块 | 说明 |
| --- | --- | --- |
| `index.html` | entry-index（env-bootstrap） | 单页入口，声明画布/HUD/结束层/重开按钮，加载样式与脚本 |
| `styles.css` | env-resources（env-bootstrap） | 纯色几何样式与布局 |
| `src/game.js` | game（game-owner） | 全部游戏规则、渲染、输入、主循环与重开 |

不引入 `package.json`、构建脚本、依赖目录或任何持久化数据；无网络请求。

## 5. 模块、角色与契约
- 模块清单：`docs/proposals/snake-game-modules-v1.md`（game / env-resources / entry-index）。
- 人员名单：`docs/proposals/snake-game-roster-v1.md`（env-bootstrap 负责 env-resources + entry-index；game-owner 负责 game）。
- 架构契约：`docs/contracts/snake-game-architecture-v1.md`（DOM 契约、`window.SnakeGame` 脚本契约、依赖方向、数据流与扩展点）。
- 每模块恰一属主，路径互不重叠：`index.html`、`styles.css`、`src/game.js`。

## 6. 风险与取舍
| 风险/缺口 | 处理方式 |
| --- | --- |
| 单一实现模块与单一属主存在集中风险 | 规则保持纯函数分区、内部注释清晰，并按 A1–A10 人工清单自测；内部重构不触发角色重招 |
| 棋盘填满时意图未定义胜利条件 | 方案默认「无合法空位即结束本局并展示当前得分」，不新增持久化；如幕僚判断属材料性选择，可另行呈请客户，不在本方案代客户拍板 |
| 运行中按 R 的语义未在意图中细化 | 默认仅在结束态响应 R，运行中忽略；结束页按钮与 R 行为一致 |
| 同一 tick 内多次按键 | 仅最后一个合法方向生效，符合「输入在下一移动步生效」 |
| Canvas 文本/字体跨环境差异 | 使用系统默认无衬线字体，仅影响观感，不影响 A1–A10 判定 |
| 验收证据形式 | A10 明确为人工试玩，本期要求验收角色按 A1–A10 逐条观察记录，不引入测试框架或自动化脚本 |
| 待澄清（非阻塞） | 是否需额外 README 运行说明（默认不需要，`index.html` 即入口）；是否接受约 130ms 固定步长与 Canvas 表现（属 C3/C6 默认假设范围内） |

## 7. 非目标遵守
明确不做：穿墙模式、分数与最高分持久化、音效与背景音乐、移动端/触屏与自适应布局、暂停/继续、联机对战/排行榜/账号/云存档/关卡道具/皮肤主题/可调难度与速度。上述均不进入本期实现与验收。

## 8. 验收与证据
- 交付物为上述三个文件；验收由验收角色在桌面 Chrome/Edge 最新版以 `file://` 打开页面，按 A1–A10 逐条人工试玩观察，记录每条通过/不通过与现象描述。
- 不要求自动化脚本；若后续需要，可另行新增测试模块与版本化文档，不修改本版契约。
