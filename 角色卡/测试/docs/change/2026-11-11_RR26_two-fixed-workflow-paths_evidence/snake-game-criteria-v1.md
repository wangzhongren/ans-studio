## 0. 通用验收环境与前置

### 0.1 环境
- 浏览器：桌面版 Google Chrome 或 Microsoft Edge 最新稳定版（二者任一即可，记录实际使用的浏览器与版本）。
- 打开方式：以 `file://` 协议直接打开项目根目录下的 `index.html`（双击文件或地址栏输入本地文件路径），不使用本地服务器，不启用任何构建步骤。
- 浏览器缩放 100%，窗口足够展示 400×400 棋盘与 HUD；关闭会向页面注入脚本的浏览器扩展（或使用干净配置文件），以免第三方报错干扰 A10 判定。
- 开发者工具：Console 面板与 Network 面板在验收开始前打开并清空；Console 的过滤级别保持默认（Errors/Warnings 不被过滤隐藏）。

### 0.2 交付文件与依赖前置
- 交付文件（缺任一项则相关条目按「未交付」记录，不代替实现方补造）：
  - `index.html`（entry-index，env-bootstrap 属主）：DOM 结构、样式与脚本加载入口；
  - `styles.css`（env-resources，env-bootstrap 属主）：纯色几何样式与布局；
  - `src/game.js`（game，game-owner 属主）：规则、渲染、输入、主循环与重开。
- DOM 契约前置（架构契约 §4.1）：`#game-canvas`（400×400 Canvas）、`#score`、`#high-score`、`#overlay`（默认 hidden）、`#final-score`、`#final-high-score`、`#restart-btn`、`#hint` 均存在且语义符合契约。
- 脚本契约前置（架构契约 §4.2）：`src/game.js` 以传统 `<script src="src/game.js"></script>` 加载（不得 `type="module"`），暴露 `window.SnakeGame.init/getState/reset`；常量 `GRID=20`、`CELL=20`、`TICK_MS=130`。
- 判定方式：全部条目为人工试玩可观察行为，不依赖自动化脚本、不要求录屏；允许在 Console 用只读方式（如 `SnakeGame.getState()`）辅助确认状态，但通过与否以画面可观察行为为准。

### 0.3 判定口径
- 每条按「判定步骤 → 通过标准」执行；步骤中未列出的前置条件不得自行添加。
- 单条内所有通过标准同时成立才记「通过」；任一项不成立记「不通过」并记录实际现象。
- 若某条因前置缺失（如文件未交付、页面无法打开）无法执行，记「未执行/证据不足」，不得记为通过。
- 结论与证据由 A12b 报告记录：逐条写实际观察到的现象；截图等附件放 `docs/verification/`，并将路径写入报告。

## 1. AC-1 启动可见（对应意图 A1，P0）

- 判定步骤：
  1. 以 0.1 的环境直接打开 `index.html`，不点击页面任何位置、不按任何键。
  2. 观察首屏：棋盘（20×20 网格、单格 20px、整体约 400×400）、蛇（初始长 3、居中、朝右）、食物（1 格，位于非蛇身且非棋盘最外圈的空格）、当前分数、会话最高分、操作提示（方向键/WASD 与 R）是否同时可见。
  3. 保持不操作，观察 3–5 秒，确认蛇按固定步长（约 130ms 一步）自动前进，且在撞墙前一直前进。
- 通过标准：
  - 首屏同时显示棋盘、蛇、食物、当前分数、会话最高分、操作提示；分数与最高分初始均为 0（显示形式可为 `0` 或含标签的 `0`）。
  - 蛇无需玩家输入即自动前进；步进节奏均匀，速度不随得分递增。
  - 页面无白屏、无布局错位导致任一必需元素不可见。
- 观察方法：首屏截图 + 连续观察；必要时 Console 执行 `SnakeGame.getState()` 只读核对初始 `snake.length===3`、`score===0`、`status==='running'`（仅作辅助，画面为准）。
- 关联交付/前置：`index.html`（DOM id）、`styles.css`、`src/game.js`（init 与主循环）。

## 2. AC-2 键盘控制（对应意图 A2，P0）

- 判定步骤：
  1. 开局后（蛇朝右自动前进）按一次 `ArrowDown`，观察下一次移动是否向下；再按一次 `ArrowUp` 观察是否向上。
  2. 分别用 `ArrowLeft`/`ArrowRight` 验证左右方向可用（注意避开 AC-3 的反向限制：先转向再验证横向）。
  3. 另开一局（重开或刷新），改用 `W`/`A`/`S`/`D` 重复上述四个方向的验证。
  4. 在相邻两个 tick 之间快速按两个不同方向键，确认「输入在下一移动步生效」且同一 tick 内以最后一个合法方向为准。
  5. 在方向键输入时观察页面是否发生滚动或焦点移动。
- 通过标准：
  - 方向键四向均可改变蛇的移动方向；WASD 四向均可改变蛇的移动方向（W=上、A=左、S=下、D=右）。
  - 每次方向改变发生在按下的下一个移动步，未出现「按了不动」或「滞后多步」。
  - 同一 tick 内多个合法输入时仅最后一个生效；不出现一次 tick 连走多格。
  - 按方向键时页面不滚动（`preventDefault` 生效）。
- 观察方法：逐方向试玩 + 关键操作前后截图/状态快照（`getState()` 的 `direction`/`pendingDirection` 仅作辅助）。
- 关联交付/前置：`src/game.js`（输入层 keydown 映射）、`index.html`（脚本加载）、`styles.css`（页面无滚动条负面影响）。

## 3. AC-3 反向保护（对应意图 A3，P1）

- 判定步骤：
  1. 开局蛇朝右自动前进时，直接按 `ArrowLeft`（反向键），持续观察至少 3 个 tick。
  2. 蛇转向下后按 `ArrowUp`（当前方向的反向），观察至少 3 个 tick；蛇转向左后按 `ArrowRight`，同理。
  3. 另开一局用 WASD 重复：朝右时按 `A`，朝下时按 `W` 等。
- 通过标准：
  - 反向输入被忽略：蛇不改变方向、不掉头、不因此死亡（`status` 保持 `running`）。
  - 反向输入不产生延迟生效（即不会在后续 tick 突然反向致死）。
  - 随后按合法方向键仍能正常转向。
- 观察方法：单局内连续操作观察蛇轨迹与状态；记录反向按键后 3 个 tick 的画面变化。
- 关联交付/前置：`src/game.js`（方向校验，规则层纯函数分区）。

## 4. AC-4 吃食物计分（对应意图 A4，P0）

- 判定步骤：
  1. 开局后控制蛇头移动到食物格，记录吃食物前后的当前分数显示与蛇身长度。
  2. 吃食物后立即观察：分数显示是否 +1；蛇身是否比之前长 1 格；食物是否从原格消失并在另一格出现。
  3. 检查新食物位置：不与蛇身任何格重叠、不在棋盘最外圈（非边界）、在棋盘范围内。
  4. 连续吃 2–3 个食物，重复核对分数为 1、2、3 且每次蛇身长度相应 +1。
- 通过标准：
  - 蛇头进入食物格即判定为吃掉；当前分数每次 +1 且 HUD 在同一 tick 内同步更新。
  - 蛇身长度每次 +1（默认不删尾）；未出现蛇身长度不变或跳变。
  - 每次新食物均在非蛇身、非边界的随机空格生成；不出现食物与蛇身重叠、食物在边界外或食物缺失。
- 观察方法：逐次吃食物记录「吃前分数/长度 → 吃后分数/长度 → 新食物位置」；`getState()` 中 `score`/`snake.length`/`food` 仅作辅助核对。
- 关联交付/前置：`src/game.js`（step 规则、食物生成、HUD 渲染）、`index.html`（`#score`）。

## 5. AC-5 撞墙结束（对应意图 A5，P0）

- 判定步骤：
  1. 开局后控制蛇持续朝某一方向移动，直至蛇头到达最外圈并尝试越界。
  2. 观察碰撞瞬间：蛇是否停在边界内、本局是否立即结束、是否出现结束信息（结束层）与本局得分。
  3. 分别从上、下、左、右四个方向各撞墙一次（可分多局）核对行为一致。
- 通过标准：
  - 蛇头到达或尝试越过网格边界即立即结束本局，不发生穿墙或从另一侧出现。
  - 结束后显示结束信息与本局得分（`#final-score` 可见且等于结束瞬间的当前分数）。
  - 撞墙前后蛇不越出 400×400 棋盘可视区域。
- 观察方法：撞墙前后截图；记录结束层出现时机、本局得分与实际吃食物次数是否一致。
- 关联交付/前置：`src/game.js`（越界判定、结束状态）、`index.html`（`#overlay`、`#final-score`）、`styles.css`（结束层可见样式）。

## 6. AC-6 撞自身结束（对应意图 A6，P0）

- 判定步骤：
  1. 先吃至少 1 个食物使蛇身长度 ≥4（初始长度 3 在禁止反向规则下无法完成自撞，故这是本条的前置，不是跳过判定）。
  2. 控制蛇以合法转向（非 180 度反向）绕出一个能碰到自身身体段的轨迹（如绕小圈/U 形），使蛇头进入自身身体段所在格。
  3. 观察碰撞瞬间：本局是否立即结束、是否显示结束信息与本局得分。
  4. 重复一次以确认可复现。
- 通过标准：
  - 蛇头与自身任意身体段重合即立即结束本局，不出现「穿身而过」继续移动。
  - 结束后显示结束信息与本局得分，本局得分与结束前当前分数一致。
  - 自撞判定不依赖反向输入（反向输入按 AC-3 被忽略）。
- 观察方法：自撞前后截图；记录蛇身长度、碰撞位置（头与哪一段重合）、结束层内容。
- 关联交付/前置：`src/game.js`（自撞判定）、`index.html`（结束层 DOM）。

## 7. AC-7 结束态冻结（对应意图 A7，P1）

- 判定步骤：
  1. 在任一结束条件（撞墙或撞自身）触发后，不点击重开、不按 R。
  2. 依次按 `ArrowUp`/`ArrowDown`/`ArrowLeft`/`ArrowRight` 与 `W`/`A`/`S`/`D` 各若干次，持续观察 3–5 秒。
  3. 对比按键前后：蛇的位置/长度、食物位置、当前分数、结束层内容是否发生变化。
- 通过标准：
  - 结束后方向输入不改变蛇的位置与方向，画面保持在结束状态（不继续前进、不复活）。
  - 当前分数、食物、蛇身与结束层内容在观察期内不变。
  - 结束层持续可见，未被方向输入关闭或遮挡。
- 观察方法：结束前后与多次按键后的截图对比；记录按键次数与观察时长。
- 关联交付/前置：`src/game.js`（结束态输入忽略、主循环停止）、`index.html`（`#overlay`）。

## 8. AC-8 会话最高分（对应意图 A8，P1）

- 判定步骤：
  1. 新开会话（刷新页面）后记录初始当前分数与会话最高分显示。
  2. 吃第 1 个食物，立即观察当前分数与会话最高分显示是否同步变为 1。
  3. 继续吃到第 2 个食物，核对最高分同步更新；随后故意结束本局，核对结束层同时展示本局得分与会话最高分。
  4. 重开后打一局得分低于此前最高分并结束，核对会话最高分保持不变、不被低分覆盖。
  5. 按刷新（如 F5/Ctrl+R）重新加载页面，核对会话最高分重置（不保留上次会话值）。
- 通过标准：
  - 本局得分超过会话最高分时，最高分显示立即更新（无延迟到结束才刷新）。
  - 结束页同时可见本局得分与会话最高分（`#final-score` 与 `#final-high-score`），数值正确。
  - 更低分不覆盖更高分；刷新页面后最高分不保留（重置）。此为意图明示的预期行为，不是缺陷。
  - 全程不出现持久化存储调用（如 `localStorage`/`sessionStorage`）导致的刷新后残留。
- 观察方法：逐局记录「本局得分/最高分」数值序列与结束层数值；刷新前后对比截图。
- 关联交付/前置：`src/game.js`（highScore 内存变量与更新）、`index.html`（`#high-score`、`#final-high-score`）。

## 9. AC-9 重开（对应意图 A9，P0）

- 判定步骤：
  1. 触发一次结束（撞墙或撞自身），结束层可见。
  2. 点击结束页「重开」按钮（`#restart-btn`），观察新局。
  3. 再触发一次结束，此次按 `R` 键，观察新局。
  4. 在运行中（未结束）按一次 `R`，观察是否误重置（契约规定 R 仅在结束态响应）。
  5. 对比重开前后：当前分数、蛇长度与位置、食物位置、会话最高分、结束层是否隐藏、蛇是否恢复自动前进。
- 通过标准：
  - 结束页「重开」按钮与 `R` 键均能开始新一局，行为一致。
  - 新局当前分数归零；蛇回到初始状态（长 3、居中、朝右）；食物重新生成在合法空格。
  - 会话最高分保留（不清零）。
  - 结束层隐藏，蛇恢复自动前进；无上一局残留状态（分数、蛇身、食物、结束层文字）。
  - 运行中按 `R` 不产生重置（与契约 §4.2 一致）。
- 观察方法：重开前后截图与 `getState()` 辅助快照；记录按钮与 R 两条路径的新局初始状态。
- 关联交付/前置：`src/game.js`（reset 逻辑）、`index.html`（`#restart-btn`、结束层）。

## 10. AC-10 运行质量与无控制台报错（对应意图 A10，P0）

- 判定步骤：
  1. 在桌面 Chrome 或 Edge 最新稳定版中，以 `file://` 直接打开 `index.html`，Console 清空后从加载开始观察。
  2. 完成一轮完整流程：开局自动前进 → 用方向键与 WASD 转向 → 吃到至少 1 个食物 → 撞墙或撞自身结束 → 点击「重开」按钮 → 再结束 → 按 `R` 重开。
  3. 全程检查 Console：是否出现页面自身产生的 error（含未捕获异常、资源 404、脚本语法错误）。
  4. 检查 Network 面板：是否存在任何 `http(s)://` 网络请求或外部资源请求。
  5. 刷新页面重复一次第 1–3 步，确认无报错。
- 通过标准：
  - 页面在桌面 Chrome/Edge 最新版以 `file://` 直接打开即可运行，无需服务器、构建或联网。
  - 完整流程中 Console 无页面自身产生的 error；无脚本 404、语法错误或未捕获异常。
  - Network 面板无任何外部网络请求（仅 `file://` 本地资源加载）。
  - 若 Console 有仅由浏览器扩展/环境注入产生的消息，需如实记录来源并注明不属于页面自身错误；页面自身错误一律记不通过。
- 观察方法：Console 与 Network 面板截图（含完整流程后状态）；记录浏览器名称/版本与打开方式。
- 关联交付/前置：`index.html`（传统 script 加载，非 ES module）、`styles.css`、`src/game.js`（无网络/无 Web Storage、无第三方依赖）。
