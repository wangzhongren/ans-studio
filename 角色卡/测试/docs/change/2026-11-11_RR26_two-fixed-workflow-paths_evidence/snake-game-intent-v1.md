# snake-game 产品意图 v1

## 1. 目标用户与场景
- 目标用户：想在电脑上快速玩一局经典贪吃蛇的普通用户；无需注册、无需联网、无需安装额外运行环境。
- 使用场景：打开本地页面即开局，用键盘操作，一局结束看分数后按 R 或点按钮立刻再开一局；单局时长通常在几十秒到数分钟。
- 典型诉求：操作跟手、规则直观、计分清楚、失败原因明确（撞墙或撞自己）、能马上重来。

## 2. 要解决的问题
- 提供一个规则完整、可自证结果的贪吃蛇小游戏，覆盖客户明确要求的四件事：键盘控制、计分、重开、边界碰撞。
- 让「玩—得分—失败—重开」形成闭环：失败有明确反馈，重开不需要刷新页面。
- 规则边界清晰，避免歧义：撞墙即结束而非穿墙；吃到食物加分并增长；反向输入被忽略而不是直接死亡。

## 3. 范围与产品取舍
### 3.1 在范围内（v1 验收覆盖）
| 维度 | 本版取舍 | 说明 |
| --- | --- | --- |
| 运行平台与形态 | 浏览器端单页小游戏，桌面本地直接打开 | 客户未指定平台，取最轻量的浏览器单页作为默认假设 |
| 输入方式 | 方向键 + WASD 双套键位，二选一皆可 | 覆盖两类常见习惯，不增加额外操作负担 |
| 转向规则 | 每步只接受一个有效方向；禁止 180 度直接反向，反向输入忽略 | 避免玩家误触直接致死，规则更好判定 |
| 边界规则 | 撞墙即结束（不穿墙） | 与客户「边界碰撞」字面一致，失败原因最直观 |
| 自撞规则 | 蛇头碰到自身即结束 | 贪吃蛇经典规则，补齐边界碰撞之外的失败条件 |
| 计分 | 每吃一个食物 +1 分，当前分数实时显示 | 规则最简、验收可逐次观察 |
| 最高分 | 会话内最高分，实时维护并在结束页展示；不做持久化 | 保留成就反馈，又避免首版引入存储与隐私口径 |
| 速度 | 固定基础速度，不随分数递增 | 保证可玩性与验收可复现；难度递增列为后续增强 |
| 食物生成 | 在非蛇身、非边界的随机空格生成 | 避免食物不可达或与蛇重叠 |
| 重开语义 | 结束页「重开」按钮 + R 快捷键；重开清零本局分数与棋盘状态，保留会话最高分 | 重开即新局，最高分是会话级荣誉不因重开丢失 |
| 暂停 | 不纳入本版范围与验收 | 首版聚焦四要素闭环，暂停列为后续可选增强 |
| 画面与音效 | 约 20x20 网格、单格约 20 像素、纯色几何风格；无音效 | 视觉最小化，减少与核心规则的耦合 |
| 设备范围 | 仅桌面键鼠 | 触屏与移动端布局不在本版范围 |

### 3.2 非目标
- 穿墙模式、可切换的边界规则。
- 分数与最高分的本地/云端持久化。
- 音效、背景音乐、动画特效。
- 移动端触屏、虚拟摇杆、小屏自适应。
- 暂停/继续（后续可选增强，非本版验收项）。
- 联机对战、排行榜服务端、账号体系、云存档、关卡与道具、皮肤主题、可调难度与速度设置。

## 4. 成功标准与验收
成功标准：用户能在桌面浏览器中打开即玩，用方向键或 WASD 控制蛇，吃到食物分数实时增加，撞墙或撞到自身时本局立即结束并显示分数，点「重开」或按 R 能立刻开始新一局且分数归零、最高分保留。

验收以第 3.1 节与 frontmatter `acceptance` 中的 A1–A10 逐条人工试玩观察为准：
1. 启动后棋盘、蛇、食物、当前分数、会话最高分与操作提示均可见，蛇自动前进。
2. 方向键与 WASD 均可改变方向，输入在下一步生效；反向输入被忽略且不致死。
3. 吃到食物后分数 +1、显示同步、蛇身 +1、食物在合法空格重生。
4. 撞墙或撞自身立即结束并展示本局得分；结束后方向输入不再移动蛇。
5. 会话最高分随本局得分刷新；结束页展示本局得分与最高分；刷新页面后最高分重置为预期行为。
6. 「重开」按钮与 R 键均可开新局，分数清零、棋盘复位、最高分保留。
7. 桌面 Chrome/Edge 最新版本地打开可运行，无控制台报错。

判定方式：上述每一条均为可观察、可复现的行为点，由验收角色按清单逐项核对；不要求自动化脚本。

## 5. 客户原话与约束
- 客户原话（经 A1 任务转述到本阶段）：「做一个贪吃蛇游戏，需包含键盘控制、计分、重开、边界碰撞。」
- 客户未提供更多偏好；本版对未明确项按默认假设成文（见第 6 节），不冒充客户已确认。
- 约束：单机本地、无网络依赖、无账号、无持久化存储；交付可玩闭环即可，不含生产级运营能力。
- 版本约束：本文件为 v1，任何需求变更另出 v2/v3，旧版本只读，不原地修改。

## 7. 质量档位
- 档位定位：首版可玩闭环小游戏，优先保证规则正确、操作跟手、失败与重开反馈清楚。
- 代码质量预期：结构清晰、可读、可本地直接运行，方便后续迭代；不追求高并发、可运营、可观测等生产级能力。
- 体验底线：无控制台报错；方向输入不出现「反向即死」这类非预期挫败；重开不出现残留状态（分数、蛇身、食物未复位）。
- 明确不做的质量投入：跨浏览器全兼容矩阵、性能压测、无障碍与国际化、移动端适配。
