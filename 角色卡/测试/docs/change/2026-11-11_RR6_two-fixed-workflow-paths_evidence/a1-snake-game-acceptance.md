## 2. 需求边界初判

客户给了四个功能点：键盘控制、计分、重开、边界碰撞。整体为经典单机贪吃蛇，规模小、无后端、无账号、无网络，**可做**，无阻塞性技术风险。

## 3. 待澄清项（A2 意图文档需落定）

### 3.1 键盘控制
- 方向键 ↑↓←→ 与 WASD 是否都要支持：建议**两者都支持**（方向键为主、WASD 为辅）。
- 是否禁止直接 180° 反向：建议**禁止反向**，转向输入队列最多缓存 1 个。
- 是否支持暂停（空格/P）：建议支持空格暂停，但列为可选。

### 3.2 计分
- 吃一个食物的分值：建议 **+10**（或 +1，需定死）。
- 是否随蛇长/速度递增计分：建议**固定分值**，简单可验。
- 分数显示位置：建议顶部 HUD 同时显示「当前分数 / 最高分」。

### 3.3 重开
- 重开触发方式：建议 **R 键 + 「重开」按钮**双通道。
- 重开是否保留最高分：建议**保留最高分**（localStorage），当前分数清零、蛇重置。
- 游戏结束表现：建议覆盖层显示 Game Over + 本局分数 + 重开提示。

### 3.4 边界碰撞
- 确认语义：**撞墙即游戏结束**（不是穿墙/四边环绕）；四边穿越列为可选、默认关闭。
- 自身碰撞：建议同样判定游戏结束（经典规则）。
- 场地形态：建议固定 20×20 网格；初始速度约 8 格/秒，恒定速度（不加速）即可满足需求。

### 3.5 运行形态
- 默认方案：**浏览器单页 HTML + Canvas + 原生 JavaScript**，无构建、无外部依赖、可 `file://` 双击离线打开。
- 目标浏览器：现代 Chrome/Edge（桌面）。
- 响应式画布 / 移动端触控：默认**不做**（需求明确为键盘控制）。
- 音效、主题、难度选择：默认不做，范围内不含。

## 4. 建议技术形态与理由

单文件或少量静态文件的纯前端实现：零依赖、零构建、离线可开，验收时可直接打开页面手工操作（方向键移动、吃食物加分、撞墙/撞自结束、R/按钮重开）。便于 A2 写意图、A3 确认、后续实现与验收。
