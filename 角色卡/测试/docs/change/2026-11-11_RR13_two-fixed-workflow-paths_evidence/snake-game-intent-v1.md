  5) 重开：分数、蛇身长度与位置、食物、速度全部复位，可直接继续玩下一局。

  - AC-1 方向控制生效：打开页面后按 ↑/↓/←/→ 或 W/A/S/D，蛇按对应方向每步前进一格，且同一时刻只有最后一次合法方向生效；蛇向右移动时按左（180° 反向）不生效，蛇不反向、不穿身自撞。
  - AC-2 计分实时递增：引导蛇吃到食物后，当前分数立即 +1 并在界面上可见（游戏进行中即可看到，不必等结算）；被吃的食物消失并在其他空白格生成新食物，新食物不落在蛇身上。
  - AC-3 撞边界即失败结算：控制蛇朝场地边界前进，越过最后一格边界时蛇立即停止，界面显示结算（本局得分与最高分），蛇不穿墙、不在对侧继续出现、不再响应移动、分数不再变化。
  - AC-4 撞自身即失败：使蛇身形成回环并撞到自身，立即进入与 AC-3 相同的失败结算态（停止 + 显示得分/最高分 + 可重开）。
  - AC-5 重开完全复位：在结算态点击「重开」按钮或按 R / Enter，分数归 0、蛇回到初始长度与初始位置、食物重新生成、速度回到初始档、移动恢复可控；连续重开多局表现一致，无残留状态。
  - AC-6 零依赖离线可玩：在断网状态下直接双击打开 HTML 文件，控制、计分、失败结算、重开全部可用；无外部网络请求依赖导致的白屏或报错，无需安装依赖或执行任何构建步骤。

# snake-game · 产品意图 v1

- flowId：snake-game
- version：1
- intentId：snake-game-intent（小写 slug，全文唯一；非 flowId 别名）
- 状态：待客户确认（**本文件不构成客户已批准**；确认以幕僚呈递的意图确认卡为准）
- 上游依据：`docs/governance/convener/snake-game-a1-intake.md`（A1 受理记录）、`docs/product/snake-game-a1-product-intake.md`（产品侧 A1 准备记录）

## 1. 客户原话

> 做一个贪吃蛇游戏，要求键盘控制、计分、重开、边界碰撞（撞边界即失败 / 结算）。

客户点名能力共四项：键盘控制、计分、重开、边界碰撞即失败/结算。本意图的必含范围以这四项为骨架，其余均为产品侧建议默认值或非目标。

## 2. 目标用户与场景

- **用户**：单一本地玩家（自娱或向他人演示），无账号、无网络依赖、无社交属性。
- **场景**：在本地电脑上双击打开页面即可开始玩；一局为短时（数十秒级）体验；失败后立刻重开再来，期望「打开即玩、失败即结算、结算可重来」的闭环。
- **使用前提**：玩家使用键盘操作；运行环境为客户本机常用现代桌面浏览器（具体兼容范围待确认）。
- **说明**：以上为目标用户与场景的产品侧理解，基于客户原话与空项目基线推断，随意图确认卡一并请客户确认。

## 3. 要解决的问题

客户想要一个**自用、开箱即玩的贪吃蛇**：不想安装环境、不想构建、不想联网，也不想为一个简单小游戏引入重型框架或资源依赖。核心体验闭环是：

1. 用键盘控制蛇在固定场地内移动、吃食物变长得分；
2. 撞边界（及撞自身）就是失败，必须立刻停下并结算，不能穿墙或悄悄继续；
3. 失败后一键重开，状态干净复位。

产品侧判断：该问题边界清晰、无外部依赖、无服务端，属于「小而完整、可离线交付」的单页小游戏；主要风险不在功能规模，而在**范围被稀释**（例如被顺手加上音效、排行榜、移动端适配）与**细节语义未定**（结算形态、加速规则、最高分是否持久化）。

## 4. 范围

见 frontmatter `scope`。要点：

- **必含（客户点名）**：键盘方向控制、进食计分、失败后重开、边界碰撞即失败并结算。
- **建议默认纳入（待客户确认）**：撞自身亦失败、实时分数 HUD、最高分 localStorage 本地保存、方向键 + WASD、禁止 180° 掉头、空格暂停、固定网格 + 得分加速、R / Enter 重开快捷键、中文界面。
- **交付形态**：单个可直接打开的网页（具体为单页 HTML 或少量配套静态文件——属实现层决策，本意图只约束「零依赖、零构建、可离线直开」这一可验收结果）。

## 5. 非目标

见 frontmatter `nonGoals`。要点：不做多人/联机、排行榜/账号/云存档、音效与美术资源、移动端触控、关卡编辑器与皮肤成就系统、桌面可执行打包、多端兼容矩阵打磨。**非目标须在意图确认卡中请客户明确确认一次**，避免后续因「客户没说不」而扩张范围。

## 6. 成功 / 验收标准

验收以「可复现的手动操作 + 可观察结果」为口径，见 frontmatter `acceptance`（AC-1 ~ AC-8）。结构说明：

| 验收项 | 对应客户点名能力 | 验证方式 |
| --- | --- | --- |
| AC-1 方向控制与禁止掉头 | 键盘控制 | 打开页面，逐方向按键观察蛇每步前进一格；反向键无效 |
| AC-2 计分实时递增 | 计分 | 吃到食物后界面分数 +1，食物在空白格重生 |
| AC-3 撞边界失败结算 | 边界碰撞（撞边界即失败/结算） | 朝边界移动，越界即停止并显示得分/最高分，不穿墙 |
| AC-4 撞自身失败 | 失败语义完整性（建议默认） | 绕圈撞自身，进入同一结算态 |
| AC-5 重开完全复位 | 重开 | 结算态点按钮或按 R/Enter，分数/蛇身/食物/速度复位 |
| AC-6 零依赖离线可玩 | 运行形态（建议默认） | 断网双击打开，全流程可玩，无构建/无网络依赖 |
| AC-7 最高分本地保留（条件项） | 计分（增强） | 结算显示最高分，刷新后仍在，重开不清空，无网络请求 |
| AC-8 暂停（条件项） | 控制（增强） | 空格暂停/恢复，移动与分数表现符合定义 |

- AC-7、AC-8 为**条件验收项**：仅当对应默认值（最高分 localStorage、空格暂停）在意图确认中被客户接受时才生效；客户若拒绝，则相应默认值与验收项一并从本意图后续版本中移除，不影响 AC-1 ~ AC-6。
- 本意图只给验收口径，不规定证据文件格式；A7/A8 阶段的证据组织与 sidecar 规范由后续质量/验收阶段决定。

## 8. 质量档位

- **建议档位：最小可用但完整可玩（功能型 MVP）。**
- 含义：客户点名的四项能力 + 建议默认值全部真实可用；失败与重开闭环正确、无卡死与状态残留；界面可读、操作有即时反馈。
- 不追求：美术精修、动画过渡、音效、性能极致优化、多端适配、可访问性专项、多语言。
- 若客户希望更高档位（例如精致视觉、动画、难度曲线、最高分历史记录），需在意图确认中显式追加；未经确认不纳入，避免范围隐性膨胀。
