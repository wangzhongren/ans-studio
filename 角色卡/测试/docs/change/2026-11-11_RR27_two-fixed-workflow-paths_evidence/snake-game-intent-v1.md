# 贪吃蛇游戏 · 产品意图 v1

## 1. 目标

在空项目（新建项目路径 A）中交付一个单机单人的贪吃蛇小游戏：玩家用键盘方向键控制蛇的移动方向，吃到食物加分并显示分数，撞到边界（墙）即游戏结束，结束后可重开，重开后分数与游戏状态复位。

## 2. 范围

- 单机单人贪吃蛇，一局一名玩家、无联网。
- 键盘方向键控制蛇的移动方向。
- 食物随机生成；吃到食物加分，界面上显示当前分数。
- 撞墙（边界）即游戏结束。
- 结束后可重开；重开后分数归零，蛇与食物复位。
- 交付一个可在本地运行、可玩的完整小游戏成品。

## 3. 验收标准

1. 启动后进入初始状态，蛇可随键盘方向键移动并改变方向。
2. 吃到食物分数增加，且分数在界面上实时可见。
3. 撞墙（边界）立即结束游戏，停止移动与计分，进入结束态。
4. 结束后可按约定方式重开；重开后分数归零、蛇回到初始位置与长度、食物重新生成、结束态清除，且可再次正常操作。
5. 成品可按约定交付形态在本地启动，并完整走通「移动 — 吃食物加分 — 撞墙结束 — 重开复位」流程。

## 4. 非目标

- 不做多人/联机对战。
- 不做排行榜、账号、云端存档等在线功能。
- 不做暂停、音效、皮肤/关卡系统等未被要求的功能（如客户另行提出再评估）。
- 不提前锁定未经客户确认的技术栈，不引入超出小游戏范围的能力。

## 5. 约束

- 单机单人、离线可玩；键盘方向键为主要操作方式。
- 不得擅自扩大范围：多人、联网、排行榜等一律不做。
- 项目为空目录、新建项目路径 A；环境事实以应用记录为准（当前空目录、非 Git 仓库）。
- 客户未明示的细节按合理默认执行，并在本文档中显式标注为「待客户确认的假设」。

## 6. 客户原话

> 做一个贪吃蛇游戏（键盘控制、计分、重开、边界碰撞）

## 7. 待客户确认的假设

以下为本意图采用的合理默认，均待客户确认；若客户另有指定，以客户确认为准并据此修订意图新版本。

1. **撞自身判定**：蛇头撞到自身（蛇身）也判定为游戏结束（默认与撞墙同为结束条件）。
2. **180° 反向**：不允许直接反方向移动；与当前方向相反的按键输入被忽略（默认做法）。
3. **速度/难度**：默认固定匀速移动，不随分数加速；不设难度档位。
4. **食物与计分**：同一时刻仅一个食物，随机生成在空白格；每个食物默认 +1 分，分数只增不减。
5. **边界行为**：撞到边界即结束，不做穿墙。
6. **重开方式**：游戏结束后以按键或界面按钮触发重开（具体方式待确认）；重开即重置分数、蛇、食物与结束态，不保留历史成绩。
7. **交付形态与技术栈**：客户未指定；默认按浏览器网页版（单页、可本地打开运行）交付，最终以客户确认为准。
8. **界面细节**：画布尺寸、网格大小、配色与字体等视觉细节未指定，按常规默认实现，待客户确认。
9. **附加功能**：暂停、最高分记录、音效等未要求，默认不做（非目标，如需要另行提出）。
