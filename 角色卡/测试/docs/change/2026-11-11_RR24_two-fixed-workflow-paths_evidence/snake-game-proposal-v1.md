# snake-game 提案 v1

意图依据：`docs/product/snake-game-intent-v1.md`（已确认意图 v1，intentId=`snake-game`）。本提案只覆盖该意图的目标/范围/验收 A1–A5 与约束，不扩大范围。

## 1. 目标与交付物

交付一个可离线、单人游玩的经典贪吃蛇：方向键/WASD 控制、每食物 +1 分实时显示、蛇头触及或越过边界立即结束、结束后可立即重开（分数清零、蛇身与食物重置）。交付物为一个零构建、零第三方依赖的本地浏览器页面，可直接打开游玩。

## 2. 推荐方案（单一推荐）

| 维度 | 推荐 | 要点与理由 |
| --- | --- | --- |
| D1 交付形态 | **浏览器网页（本地静态页）** | 单人本地离线天然满足；无需安装与账号；键盘事件语义统一；「画面同步」「按键即时」可直接观察，A1–A5 验收路径最短；不引入安装包/运行时安装成本 |
| D2 技术栈与构建 | **原生 HTML/CSS/JS + Canvas 2D，零依赖、零构建**；使用普通 `<script>`（非 ES module），不使用 fetch/CDN | 无 Node/npm 等工具链依赖，不受「环境能力未探测」影响；普通脚本可在 `file://` 下直接加载（ES module 会受 CORS 限制）；产物即源码，A12 可直接复核 |
| D3 界面尺寸与网格 | **20×20 网格，每格 24px，画布 480×480**，上方状态栏显示分数 | 方形网格边界对称、撞墙判定直观；24px 下单格蛇身/食物清晰；整体窗口约 520×600，常见屏幕无需缩放 |
| D4 配色与界面语言 | **深底高对比 + 中文界面**：背景 #16181D、网格线 #2A2F3A、蛇 #4ADE80（蛇头 #22C55E）、食物 #F87171、文字 #E5E7EB、结束覆盖层半透明黑 | 深底高对比保证蛇/食物/边界可辨；界面文案用中文「游戏结束」「分数」「重开」，与客户语境一致，便于验收取证 |
| D5 初始速度与节奏 | **固定 130ms/格（约 7.7 格/秒），不随分数加速** | 保证按键后下一次推进可感知、方向判断可控；加速与难度选择属意图非目标，v1 不实现 |
| D6 重开入口形式 | **双入口**：结束覆盖层内「重开」按钮 + 空格/回车键 | 按钮可见、易发现（满足「必须存在且易发现」）；按键满足快速重开；二者走同一重置路径 |
| D7 验收证据方式 | **A5 只预留，形式由 A12 决定**；推荐候选：截图序列（开局/转向/得分/撞墙结束/重开各一）+ 可运行构建人工复核，可选补一段完整闭环录屏 | 截图序列能逐条对应 A1–A5 的静态证据，可运行构建提供动态复核；不预先承诺自动化测试（v1 不引入测试框架依赖） |

推荐方案的统一约束落实：

- 单人、本地、离线：纯静态页面，无网络请求、无服务端、无账号。
- 方向键与 WASD：输入层同时映射两组键；禁止 180° 反向（相对当前生效方向过滤）。
- 每食物 +1 分：核心层计分唯一来源，渲染层只读显示。
- 触边即结束：下一格蛇头坐标越出 0..19 任一方向即置结束态；结束后输入层忽略方向、渲染层显示结束提示与最终分数。
- 重开清零重置：分数归零、蛇回到初始长度 3 与中心位置、食物重新随机生成、状态回到运行中。
- 不假设工具链：本方案零构建，不依赖 Node/npm/打包器；运行只需现代浏览器（浏览器可用性由客户环境决定，本阶段未做 shell 探测）。

## 3. 备选方案与取舍理由

| 编号 | 备选 | 影响 | 不推荐理由（或适用条件） |
| --- | --- | --- | --- |
| D1-a | 桌面应用（Electron/Tauri） | 需 Node/Rust 工具链、安装包体积大、打包与签名成本高 | 与「最小可玩闭环、零依赖」冲突；仅在客户明确要求桌面分发时再考虑 |
| D1-b | 终端命令行（字符画） | 无浏览器依赖，但字符渲染下「画面同步」取证弱、终端键盘差异大、边界视觉不直观 | 可玩性与验收可观察性较差；仅在客户要求 CLI 时再考虑 |
| D2-a | TypeScript + Vite 构建 | 类型安全与工程化更好，但需 npm 依赖与构建步骤、产物与源码分离 | 增加工具链依赖与验收构建负担，对本项目规模收益不足 |
| D2-b | ES module 多文件 + 本地静态服务器 | 模块化清晰，但 `file://` 直接打开会被 CORS 阻断 | 违背「打开即玩」；如客户接受本地服务器可再评估 |
| D3-a | 25×25 格 × 20px | 棋盘更大、单局更长 | 小屏下蛇身与网格线偏细，可读性下降 |
| D3-b | 30×20 非方形 | 横向视野更宽 | 边界不对称、撞墙判定直觉较弱，且布局适配复杂 |
| D4-a | 英文界面 | 通用性略好 | 客户语境为中文，验收文案「游戏结束」等按中文更直观 |
| D4-b | 浅色主题 | 白天观看更舒适 | 蛇/食物对比度通常低于深底方案，可辨识性略差 |
| D5-a | 100ms/格（更快） | 更刺激 | 初手易误判方向，A1「按键后方向实际改变」取证窗口更短 |
| D5-b | 180ms/格（更慢） | 更易操作 | 节奏偏拖沓，闭环演示时间变长 |
| D6-a | 仅按键重开 | 实现最简 | 可发现性弱，不满足「易发现」 |
| D6-b | 仅按钮重开 | 可见性好 | 快速重开体验差，且键盘玩家需移手 |
| D7-a | 录屏 | 动态闭环直观 | 文件大、难以逐条对应验收编号 |
| D7-b | 自动化 headless 测试 | 可重复 | 需引入浏览器自动化依赖，超出 v1 最小范围 |

若客户在 A6 选择任一备选，需在方案 v2 中同步调整模块路径与角色职责，不在本 v1 内混用。

## 4. 意图验收对照（A1–A5）

| 验收 | 本方案承载 | 说明 |
| --- | --- | --- |
| A1 键盘方向控制 | input-control + game-core + app-entry | 方向键/WASD 映射为方向意图；相对当前方向过滤反向；下一 tick 生效 |
| A2 实时计分 | game-core + render-ui | 吃食物同 tick 内 score+1，渲染层每帧读取快照显示，无延迟队列 |
| A3 撞墙结束 | game-core（判定）+ input-control（结束态忽略）+ render-ui（结束提示） | 下一格越界立即置结束；结束后不接受方向输入；覆盖层显示「游戏结束」与最终分数 |
| A4 结束后重开 | app-entry（入口与重置编排）+ game-core（reset） | 按钮/空格/回车触发统一重置：分数清零、蛇身复位、食物重生 |
| A5 闭环可复现 | 全部模块 | 固定 130ms tick 下可连续多轮；无暂停/加速等额外状态干扰 |

## 6. 范围与非目标

- 纳入：意图 scope 的五项行为与验收 A1–A5。
- 不纳入 v1：联网、多人、账号、排行榜、移动端触控与响应式、音效与美术资源、存档/读档、暂停、难度与随分加速、特殊食物、最高分记录、商业化功能。均不作验收内容，也不在实现中「顺手」加入。

## 7. 风险与依赖

- 若 `file://` 直开受浏览器安全策略影响，备选是以本机任意静态服务器打开；实现上坚持普通脚本与相对路径，尽量避免该依赖。
- 蛇占满全部网格为数学边界情形，v1 仅保证不崩溃（记录，不纳入验收，不扩展功能）。
- 环境能力：本阶段未运行任何 shell 探测；方案不依赖构建工具链，运行依赖由客户环境决定。
- 依赖下游：A6 客户确认 → A9 团队计划/基线 → A10 任命 → A11 一模块一任务实现 → A12 独立验收 → A13 merge-main。
