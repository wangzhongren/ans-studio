# snake-game A1 产品受理/准备记录

> 本文件是 A1 受理阶段的**准备记录**，不是产品意图文档；不得替代 A2 的 `docs/product/snake-game-intent-v1.md`。本记录只梳理初始理解与尚缺信息，不拍板范围、不定稿验收口径、不写实现方案。

## 1. 客户目标（既定事实）

做一个贪吃蛇游戏，四项明确要求：

1. 键盘方向控制；
2. 实时计分；
3. 游戏结束后可重开；
4. 撞墙（边界）判定结束。

## 2. 目标用户与场景（初始理解，待 A2/A3 确认）

- 用户画像：单人本地玩家，无需账号、无需联网。
- 使用场景：打开游戏 → 键盘操作蛇移动 → 吃到食物得分 → 撞墙结束 → 重开新局。四项目标构成一个最小可玩闭环。
- 需求性质：全新项目（路径 A），无存量代码与兼容约束。

## 3. 要解决的问题（初始理解）

让玩家能以最低门槛获得一局完整、可反复进行的经典贪吃蛇体验：输入可感知（键盘控制）、反馈即时（计分）、失败可达（撞墙即结束）、失败可再来（重开）。四项要求分别对应可操作性、反馈、失败判定与可重复游玩，缺任一项闭环即不完整。

## 4. 范围与非目标（初判备注，不越权收窄或扩大）

- 初判范围内（由客户四项要求直接推出）：单人贪吃蛇核心玩法、键盘方向控制、实时计分显示、撞墙结束判定、结束界面的重开入口。
- 初判范围外/未纳入（记录，不在 A1 决定）：联网、账号、排行榜、多人对战、移动端触控、音效、存档、内购等增值功能。
- 待客户决定是否属于范围的候选：暂停、难度/速度递增、最高分记录、特殊食物、可调参数、界面语言与视觉风格。

## 5. 验收口径的初始理解（候选，A2 成文、A3 客户确认后才定稿）

| 客户要求 | 可观察的验收行为（候选） | 尚需明确的细则 |
| --- | --- | --- |
| 键盘方向控制 | 按下方向键/约定按键后，蛇的移动方向实际改变且画面同步 | 方向键与 WASD 是否都支持；是否禁止 180° 掉头；输入响应延迟要求 |
| 实时计分 | 吃到食物瞬间分数变化并在界面可见 | 每食物固定分值或计分规则；是否显示最高分 |
| 结束后可重开 | 本局结束后可按约定操作开新局，蛇身/食物/分数回到初始状态 | 重开后分数是否清零、最高分是否保留；重开入口是按钮还是按键 |
| 撞墙判定结束 | 蛇头触及/越过边界即本局结束，不再接受移动输入 | "触及即结束"还是"越出才结束"；结束提示文案与形式 |

- 总体验收可用一个黑盒流程表达：开局 → 键盘改变方向 → 吃食物得分可见 → 撞墙结束 → 重开并恢复正常游玩。
- 证据形式（截图/录屏/可运行构建/自动化测试）由 A12 验收方式定，不在 A1 决定。

## 6. 客户原话与约束

- 原话要点：「做一个贪吃蛇游戏」，要求「键盘方向控制、实时计分、游戏结束后可重开、撞墙（边界）判定结束」（转引自运营 A1 受理记录，未增删语义）。
- 约束：客户仅给出上述四项；其余细节客户尚未表态，不能替客户默认，也不得在 A1 提前收窄或扩大范围。
- 流程约束：意图正文属 A2 独立任务；本记录不含实现方案、技术选型与代码。

## 7. 质量档位（初判，待 A2 成文与 A6 方案确认）

- 定位为「最小可玩闭环优先」：四项要求必须真实可用、行为可复现，不做概念演示或半成品。
- 可玩性底线：操作无卡顿到影响判断、计分不跳变、结束与重开状态干净无残留。
- 非质量承诺项（不强制）：视觉精致度、美术资源、音效表现、跨平台一致性——除非客户后续明确要求。

## 8. 尚缺信息（交 A2 意图表述/A3 客户确认，不在此代答）

1. 交付形态与运行平台：网页、桌面应用还是命令行；目标操作系统与浏览器。
2. 技术栈与构建方式：是否限定语言/框架；是否需要可双击运行的产物。
3. 界面与视觉：窗口/画布尺寸、网格大小、配色风格、界面语言。
4. 节奏参数：初始移动速度、是否随分数加速、难度是否可调。
5. 食物与成长规则：食物数量、每次增长格数、是否出现特殊食物。
6. 计分细则：每食物分值、是否记录并展示历史最高分。
7. 重开语义：分数是否清零、最高分是否保留、是否需要暂停/继续。
8. 键盘细则：方向键与 WASD 是否都支持、是否允许 180° 掉头。
9. 失败提示与重开入口：结束画面文字、按钮或按键。
10. 验收证据形式：截图/录屏/可运行构建/自动化测试（按 A12 定）。
11. 范围边界：音效、移动端、排行榜等增值功能是否纳入。
