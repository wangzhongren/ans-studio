# snake-game 验收标准 v1（A12a，实施前定稿）

> 本文件为 A12a 验收标准，先于实现定稿。A12b 独立验收必须按本文件的冻结版本与任务指定的最终完整 OID 逐条核对；不得在实现完成后回改本版本（如需变更出新版本 v2，不原地修改）。

## 1. 目的与依据

- 目的：把意图 A1–A5 转成可观察、可复核、可判不通过的验收标准，供 A12b 逐条对照。
- 依据（按地址引用，本文件不转抄任何哈希，哈希由应用计算与记录）：
  - 意图（硬标准 A1–A5）：`docs/product/snake-game-intent-v1.md`
  - 已确认方案（D1–D6 推荐项）：`docs/proposals/snake-game-proposal-v1.md`
  - 模块清单：`docs/proposals/snake-game-modules-v1.md`
  - 名单：`docs/proposals/snake-game-roster-v1.md`
  - 架构/契约（公开契约与判定口径）：`docs/contracts/snake-game-architecture-v1.md`
- 验收对象：A12b 任务指定的最终完整 OID 所对应的实现产物（本地静态页）；A12a 本阶段不运行任何 shell 探测、不运行实现。

## 2. 判定基线（方案已确认参数）

| 项 | 基线 | 来源 |
| --- | --- | --- |
| 交付形态 | 本地静态页，可直接在浏览器打开，离线、无网络请求、无账号 | 提案 D1 |
| 技术形态 | 原生 HTML/CSS/JS + Canvas 2D，零构建、无第三方依赖、普通 `<script>` | 提案 D2 |
| 棋盘 | 20 列 × 20 行，每格 24px，画布 480×480；分数状态栏位于画布上方 | 提案 D3、架构 §4.5 |
| 界面 | 深底高对比，中文文案（「分数」「游戏结束」「重开」） | 提案 D4 |
| 节奏 | 固定 130ms/格，不随分数加速；唯一计时来源在 app-entry | 提案 D5、架构 §3 |
| 初始态 | 蛇长 3、位于中心区域（具体初始朝向不限定）、单一食物位于空格 | 提案 §2、架构 §4.1 |
| 重开入口 | 结束覆盖层「重开」按钮 + 空格/回车键，二者同一重置路径 | 提案 D6、架构 §4.4 |
| 计分 | 每食物固定 +1，无其他加减分 | 意图 A2、架构 §4.1 |

判定口径统一说明：

- 「立即」= 在该行为发生后一个 tick（130ms）内可从画面/结束态观察到，不出现持续延迟或多步滞后。
- 「边界结束」采用架构 §4.1 口径：下一次推进蛇头将越出 `0..cols-1 / 0..rows-1` 时置 `over` 并停止推进。若实现选择更严格的「抵达边界格即结束」，只需仍满足「结束立即发生、结束后不再推进、忽略输入」，不因更严格判不通过；但任何情况下不允许蛇头越出画布可见网格后继续前进或穿墙。
- 本文件不评价视觉精致度、性能指标等非意图项；非目标（联网、音效、暂停、加速、最高分等）不作为验收内容，也不得因额外添加而判通过或加分。

## 3. 证据规范（A12b 执行）

### 3.1 必需证据（P0 项）

1. **可运行产物人工复核**：在客户环境（浏览器由客户环境决定，A12a 不探测）真实打开指定 OID 的入口页，按本文件第 4 节逐条操作并记录结果。复核记录（浏览器与版本自报、打开方式、操作步骤、观察结论）写入 A12b 报告正文。
2. **截图序列**（真实运行所得，禁止示意图/合成图/复用旧版截图），最少 5 张，覆盖：
   - `开局`：初始画面，可辨网格、蛇（长 3）、食物、分数 0；
   - `转向`：一次方向改变前后各 1 张（键位与转向后朝向可对应）；
   - `得分`：吃到食物后的画面（分数 +1、蛇长增加、食物已重生）；
   - `撞墙结束`：结束瞬间/结束覆盖层（「游戏结束」+「最终分数：N」）；
   - `重开`：重开后的新局画面（分数 0、蛇身复位、食物重生）。
3. **证据落盘与 sidecar**：截图保存到 `docs/verification/` 下（建议命名 `docs/verification/snake-game-a12b-01-open.png` … `-05-restart.png`，实际以 A12b 报告为准）；P0 证据必须带 sidecar（`<artifact>.meta.json`，`evidence-meta/v1`），其 `acIds` 覆盖所支撑的 AC 编号。字节数/行数/sha256 由应用计算并核验；本标准不转抄哈希，A12b 也不得手写伪造。
4. **连续多轮记录**：A5 至少 2 轮（建议 3 轮）完整闭环，逐轮记录「开局分数 → 结束分数 → 重开后分数」与是否正常恢复移动。

### 3.2 可选证据

- 完整闭环录屏（可选，用于动态佐证转向/计分时序）。**缺录屏不判失败**；不得以「没有录屏」为由判不通过，也不得用录屏替代必需截图。
- 控制台报错截图（AC-15 佐证，可并入复核记录）。

### 3.3 证据有效性

- 截图/记录必须对应任务指定最终完整 OID 的真实运行；候选漂移、内容已变或无法对应 OID 的旧证据不计入。
- 缺失、过期（sidecar 不匹配）或无法复现的证据按 `insufficient evidence` 处理，不得判通过。
- 发现伪造证据（合成图、改 sidecar、复述未实际看到的画面）→ 该条不通过并按真实失败回报来源链。

## 4. 逐条验收标准与判定方法

### AC-1（P0，基线）本地打开入口页即可进入运行态

- 判定方法：以指定 OID 的 `index.html` 在浏览器打开（`file://` 直接打开或本机静态服务器，以实际可行方式为准），页面显示画布、分数状态栏；开局后蛇按固定节奏移动；整个过程无网络请求依赖、无未捕获异常导致白屏。
- 所需证据：开局截图；复核记录中的打开方式与控制台观察；如需说明离线，记录未联网/无外部请求的观察。
- 不通过判据：页面无法打开或白屏；必须构建/安装运行时才能运行；依赖外网资源；控制台存在导致游戏不可用的异常。

### AC-2（P0，A1）方向键使蛇的移动方向实际改变

- 判定方法：运行中分别按 ↑ ↓ ← →（每次按键后留出 ≥1 个 tick 观察），确认蛇头朝向与推进方向变为对应方向；四个方向均验证；按键后方向变化在画面可见。
- 所需证据：至少两次转向（含反向轴之外的方向）的转向前后截图；复核记录逐键结果（四键各一次）。
- 不通过判据：任一方向键无效；按键后方向不改变或改错方向；方向改变但画面不同步（蛇身不按新方向推进）。

### AC-3（P0，A1）WASD 控制生效（大小写不敏感）

- 判定方法：运行中分别按 W/A/S/D（含一次大写/Shift 组合或 CapsLock 情形），确认与方向键等价的移动方向改变；四键均验证。
- 所需证据：WASD 至少一次转向的前后截图；复核记录逐键结果（四键各一次，含大小写说明）。
- 不通过判据：任一 WASD 键无效或方向映射错误；大小写不同导致失效（与架构 `normalizeKey` 约定不符）。

### AC-4（P0，A1）禁止 180° 反向（不一步掉头）

- 判定方法：蛇向某方向移动时按相反方向键（如向右时按 ←），观察蛇**不**立刻掉头：反向指令被忽略，蛇继续原方向至少一个 tick；随后按垂直方向（如 ↑）可正常转向。方向键与 WASD 各验证一次反向过滤。
- 所需证据：反向按键前后的连续截图（证明未掉头）；随后垂直转向成功的截图；复核记录注明按键与观察 tick 数。
- 不通过判据：按反向键后蛇立即反向（一步掉头/自撞）；或反向键导致方向错乱、卡住、丢失后续正常转向能力。
- 说明：反向判定相对「当前生效方向」而非待处理方向；按架构允许最多保留一个待处理方向，重复同向忽略，不作为不通过理由。

### AC-5（P0，A1）按键后方向实际改变且画面同步、无方向错乱

- 判定方法：连续做「转向→推进→再转向」组合（至少 3 次转向，含方向键与 WASD 混用），每次确认下一次推进即按新方向、蛇身连贯无跳格/穿模；快速连按不同方向时不出现方向错乱或蛇身断裂。
- 所需证据：组合操作的截图序列（3 次转向各一对前后图）；复核记录的操作顺序与观察。
- 不通过判据：按键被吞（游戏仍在运行却无效）；同一 tick 内出现多次方向跳变/方向与按键不一致；蛇身断裂或位置错乱；快速连按导致崩溃或状态失步且不可恢复。

### AC-6（P0，A2）每吃到一个食物分数精确 +1

- 判定方法：记录开局分数（应为 0），操控至吃食物，核对分数恰好 +1；连续吃至少 2 个食物，分数按 1、2 递增，无额外加分/扣分；蛇长同步 +1/次。
- 所需证据：开局分数截图 + 至少 2 次得分后的截图（分数值与蛇长可见）；复核记录逐次「进食前分数→进食后分数」。
- 不通过判据：分数不增加；增量不是 1（多加、少加、跳变）；分数与实际进食次数不一致；蛇长与计分不同步。

### AC-7（P0，A2）分数界面可见且实时，无延迟跳变

- 判定方法：分数显示位于画布上方状态栏、字号与对比度清晰可读；吃到食物后的下一帧画面分数已更新（≤1 tick），无「先吃多格后一次性补分」的延迟跳变；分数文本不得被覆盖层或画布遮挡。
- 所需证据：得分前后截图（同一局、可见分数区域）；复核记录描述观察到的更新时序；可选录屏佐证，缺录屏不判失败。
- 不通过判据：界面无分数或数值不可读；分数在多次进食后才跳变/批量补记；刷新后分数与蛇身长度矛盾。

### AC-8（P0，A3）蛇头触及/越过边界立即结束

- 判定方法：让蛇持续向同一边移动至边界，观察在本局结束前蛇头未被允许越出可见网格继续前进；越过判定触发时本局立即进入结束态（停止推进），画布上的蛇停在原地且不再移动。分别至少验证两个不同边（建议左/上或右/下各一次）。
- 所需证据：接近边界与结束瞬间的截图（可辨蛇头与边界关系、推进已停止）；复核记录注明触发的边与观察结果。
- 不通过判据：蛇头越出画布/穿越边界后继续移动；到边界不结束；结束后蛇仍在推进；提前无关地结束（未到边界）。
- 说明：更严格的「抵达边界格即结束」实现可接受，但必须满足「立即结束、不再推进」。

### AC-9（P0，A3）结束态忽略方向输入

- 判定方法：进入结束态后，依次按 ↑ ↓ ← → 与 W/A/S/D，观察蛇身位置与结束画面均不改变、状态不被重新激活；持续按 2–3 秒仍保持结束态。
- 所需证据：结束态截图 + 结束态按键后的截图（两图状态一致）；复核记录列明按过的键。
- 不通过判据：结束后方向输入使蛇移动/画面变化；结束态被误退出且未重开；结束后按键导致报错或卡死。

### AC-10（P0，A3）结束画面显示「游戏结束」与最终分数

- 判定方法：结束瞬间出现覆盖层/结束提示，文案包含「游戏结束」，并显示最终分数（如「最终分数：N」），数值与结束前状态栏分数一致；提示不被遮挡、可读。
- 所需证据：结束覆盖层截图（文案与数值清晰）；复核记录记录结束前分数与提示中最终分数一致性。
- 不通过判据：无结束提示；文案缺失或不可读；最终分数缺失或与结束前分数不一致；提示遮挡导致无法继续操作重开。

### AC-11（P0，A4）「重开」按钮可立即开新局

- 判定方法：结束态点击覆盖层内「重开」按钮，观察到覆盖层消失、进入新局并恢复推进（≥1 tick 后蛇位置变化）。
- 所需证据：点击前（结束覆盖层）与点击后（新局运行）截图；复核记录。
- 不通过判据：按钮不存在/不可见/不可点；点击后不重开；重开后不恢复推进；同一次点击触发多局或状态错乱。

### AC-12（P0，A4）空格或回车键可立即开新局

- 判定方法：结束态分别按空格与回车（各验证一次，建议两轮间分别使用），均能重开并恢复推进；重开键不得在运行中导致异常（可观察为无副作用或按实现无操作，不判不通过）。
- 所需证据：两次按键重开的结束态/新局截图；复核记录注明使用的键。
- 不通过判据：空格与回车均无效；仅一个有效且另一个完全无效（提案 D6 约定双入口）；按键重开不恢复推进或导致状态异常。

### AC-13（P0，A4）重开后状态干净：分数清零、蛇身复位、食物重生、恢复运行

- 判定方法：在结束分数 N>0 的一局重开，逐项核对：分数显示 0；蛇长为初始长度 3 且位于中心区域（具体朝向不限定）；食物重新生成于空格（不与蛇身重叠）；覆盖层已移除；≥1 tick 后蛇正常移动。连续重开 2 次均干净（不残留上一局分数/蛇身/覆盖层）。
- 所需证据：结束画面（分数 N）→ 重开后开局画面（分数 0、蛇长 3、食物可见）对比截图（含连续两次重开）；复核记录逐项核对表。
- 不通过判据：分数残留；蛇长/位置残留上一局；无食物或食物压在蛇身上；覆盖层未消失；重开后不推进；两次重开结果不一致。

### AC-14（P0，A5）连续多轮闭环可复现、无卡死

- 判定方法：至少连续完成 2 轮（建议 3 轮）「开局→转向→吃食物得分→撞墙结束→重开」完整闭环；每轮均满足 AC-2/3、AC-6/7、AC-8/9/10、AC-11 或 AC-12、AC-13；轮间可随时继续，无冻结、无输入失联、无状态错乱。
- 所需证据：每轮至少「开局/得分/结束/重开」四类截图（可复用对应 AC 的截图并标注轮次）；复核记录逐轮数据表（结束分数、重开分数、是否正常恢复）。
- 不通过判据：任一轮任一环节失败；出现卡死（画面停止推进且输入无效）；需刷新页面才能继续；轮次间状态污染。

### AC-15（P1）运行期稳定，无未捕获异常/白屏

- 判定方法：完整复核过程（含快速连按、结束态按键、连续重开）中观察浏览器控制台无未捕获异常，页面无白屏/崩溃；键盘长按不导致失步或持续加速推进。
- 所需证据：控制台截图或复核记录中的控制台观察；可与第 3.1 节记录合并。
- 不通过判据：出现未捕获异常、白屏或崩溃；异常导致 AC-1–AC-14 任一项不可用（此时按对应 P0 不通过处理）。
- 说明：P1 失败本身不单独否决，但必须如实记录并交幕僚评估；若影响可玩闭环，按相应 P0 判定。

## 6. 通过 / 不通过与复核规则

- **通过**：全部 P0（AC-1 至 AC-14）均满足，证据齐备且真实可复核；P1（AC-15）已如实记录，无影响闭环的异常。
- **不通过**：任一 P0 不满足（含可复现的行为偏差）。按新 attempt 回 A11 由原属主修复，修复产生新指定 OID 后重新验收。
- **insufficient evidence**：证据缺失、无法对应指定 OID、sidecar 过期/不匹配或无法复现的行为，一律不判通过，按缺证如实回报，不得以推测补足。
- **范围规则**：只核对指定最终完整 OID 与冻结本版本；候选漂移或内容已变不判通过，必要时停止核验并如实回报来源链。
