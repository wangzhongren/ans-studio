# snake-game A1 受理/准备记录

> 本记录只做受理与准备：记录目标/范围/验收口径的初始理解与尚缺信息，不拍板范围、不写产品意图正文（意图撰写属 A2，由 product 独立完成）。

## 1. 客户目标（原话要点）

客户目标：做一个贪吃蛇游戏。

客户列出的要求（四项）：

1. 键盘方向控制；
2. 实时计分；
3. 游戏结束后可重开；
4. 撞墙（边界）判定结束。

## 2. 初始理解（记录，非定稿）

- 玩法基线：单人对战环境的经典贪吃蛇；蛇按键盘方向移动，吃到食物后增长/得分；撞墙即本局结束；结束后可开新局。
- 四项要求的初始验收口径候选（最终口径以 A2 意图与 A6 方案确认为准）：
  - 键盘方向控制：按键能实际改变蛇的移动方向；需明确是否禁止 180° 反向、是否支持 WASD 与方向键。
  - 实时计分：吃食物时分数即时变化并显示；需明确每食物分值、是否显示最高分。
  - 结束后可重开：本局结束后可通过界面操作开始新一局；需明确重开后计分/蛇身/食物状态如何重置。
  - 撞墙（边界）判定结束：蛇头越出边界即判定本局结束；需明确“结束”是立即停止并可重开，是否有结束提示。
- 范围初判（仅备注，未拍板）：默认单人、本地运行、无联网、无账号；四项目标构成最小可玩闭环。是否包含暂停、音效、难度递增、移动端触控等，均未纳入本阶段判断。

## 3. 尚缺信息（待客户/A2 意图确认或 A6 方案确认澄清）

1. 交付形态/运行平台：网页（浏览器）、桌面应用还是命令行？目标操作系统与浏览器？
2. 技术栈与构建方式：是否限定语言/框架；是否需要可双击运行的构建产物。
3. 界面与视觉：窗口/画布尺寸、网格大小、配色与样式、中文还是英文界面。
4. 节奏参数：初始移动速度、是否随分数加速、是否可调难度。
5. 食物与成长规则：食物数量、增长格数、是否出现特殊食物。
6. 计分细则：每食物固定分值？是否记录并展示历史最高分？
7. 重开语义：重开后分数清零？最高分是否保留？是否需“暂停/继续”。
8. 键盘细则：方向键与 WASD 是否都支持；是否允许 180° 掉头。
9. 失败提示与重开入口：结束画面文字、按钮或按键。
10. 验收证据方式：截图 / 录屏 / 可运行构建 / 自动化测试（按 A12 验收方式确定，不在本阶段定）。
11. 范围边界：是否要音效、移动端、排行榜等增值功能。

以上均只记录，不擅自替客户选择；由客户在意图/方案确认环节决定。
