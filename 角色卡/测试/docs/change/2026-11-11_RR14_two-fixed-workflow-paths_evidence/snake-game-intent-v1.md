# 产品意图：贪吃蛇小游戏

## 1. 目标用户与场景

- 目标用户：希望在本地轻松玩一局经典贪吃蛇的普通用户（单人玩家）。
- 使用场景：在本地电脑打开游戏即玩；用键盘操控蛇移动、吃食物涨分；一局结束后可立即重开，反复游玩。

## 2. 要解决的问题

客户希望获得一个完整可玩的经典贪吃蛇核心闭环：键盘可控、吃食物有反馈且计分、撞边界有明确的结束判定、结束后能方便地重开再来。当前没有该游戏，需要从零交付一个最小可行版本。

## 3. 范围与非目标

### 3.1 做什么（草案）

- 单人、单机、单一棋盘的一局制游戏。
- 键盘方向控制蛇的移动。
- 吃到食物后实时加分并在界面刷新分数。
- 本局结束后可重开（重新开始一局）。
- 蛇头撞到边界即判定碰撞并结束本局，给出可见的结束提示。

### 3.2 不做什么（草案 / 非目标）

- 不做联机、多人对战。
- 不做账号、后端服务与云存档。
- 不做在线排行榜与跨会话持久化最高分（除非客户另行要求本机保存）。
- 不做移动端触控适配。
- 不做皮肤、音效、多关卡、AI 对手等非核心扩展。

### 3.3 平台与画面形式（默认假设）

默认浏览器单页 2D 色块画面（Canvas 或等价），本地打开即可玩；非桌面原生程序、非 3D。此为实现形态层面的目标假设，具体方案由后续提案阶段决定，本意图不写实现方案。

## 4. 成功 / 验收标准

1. **键盘方向控制**：按方向键（或 WASD）后，蛇头按对应方向在下一游戏 tick 前移一格；支持的四向输入均生效，180° 反向输入被忽略；按键到画面移动的响应可观察（≤100ms 或下一 tick 生效）。
2. **吃食物计分**：每吃到一次食物，分数按约定增量增加，界面分数即时刷新，且分数与累计吃食次数一致。
3. **重开**：在结束态触发重开（R 键或等价操作）后，蛇长、位置、分数、速度、食物布置恢复初始态，可立即继续游戏，无需刷新页面。
4. **撞墙即游戏结束**：蛇头触到任一边界时本局立即结束并显示可见的结束提示；不穿墙、不静默继续、不误判为吃食，结束后不再移动。

以上四项均为可观察行为，作为 A3 意图确认与后续验收的基准。

## 5. 客户原话与约束

- 客户原话：「做一个贪吃蛇游戏（键盘控制、计分、重开、边界碰撞）。」
- 约束：一期最小可行；平台与画面形式为默认假设（浏览器 2D 色块、本地打开即玩）；其余待澄清项按下方默认假设执行，客户可在 A3 确认卡上修订。

## 6. 质量档位

一期为最小可行/演示级质量：本地可运行、四项核心行为正确、界面可读即可；暂不要求自动化测试、部署上线、性能指标或多端适配。如客户另有要求，应在 A3 确认时提出并另行约定档位。

## 7. 待澄清与默认假设

以下 6 条为 A1 受理阶段列出的待客户澄清问题。在客户于 A3 意图确认卡答复前，先按「默认假设」执行；客户可在确认卡上逐条修订，修订后按新答复更新意图版本。

1. **运行平台与形态**：做成浏览器网页（打开即玩）还是桌面程序？画面用简单 2D 色块是否可接受？
   - 默认假设：浏览器网页、2D 简单色块画面，本地打开即可玩。
2. **边界碰撞语义**：撞墙直接结束本局，还是穿墙从对侧出现？
   - 默认假设：撞墙直接结束本局，不穿墙。
3. **计分规则**：每吃一个食物加几分？吃食物后蛇是否加速（难度递增）？是否需要保存最高分？
   - 默认假设：每吃一个食物 +1 分；不随吃食物加速；不持久化最高分。
4. **操作键位与暂停**：仅方向键、仅 WASD，还是两者都支持？是否需要暂停功能？
   - 默认假设：方向键与 WASD 均支持；不设暂停功能。
5. **重开范围**：只在游戏结束后可重开，还是游戏中也可随时重开？重开是否同时清空最高分？
   - 默认假设：仅结束态可通过 R 键重开；重开清空当前分数（无持久化最高分）。
6. **交付与质量档位**：只需本地可运行（无自动化测试、无部署要求），还是需要测试与运行说明？
   - 默认假设：仅需本地可运行，无自动化测试与部署要求。
