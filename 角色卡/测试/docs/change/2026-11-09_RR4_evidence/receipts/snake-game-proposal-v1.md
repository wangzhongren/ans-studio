# 2D 贪吃蛇小游戏 — 实施提案（v1）

- flowId: `snake-game`
- intentId: `snake-2d-game`
- 产品意图：`docs/product/snake-game-intent-v1.md`（v1，客户已通过 intent-confirm 本人确认）
- 本提案状态：draft（待客户在提案卡上确认；未获确认不视为通过）

## 1. 摘要

交付一个纯前端、零第三方依赖的 2D 贪吃蛇单页游戏：交付物为 `game/` 目录下三个静态文件（`index.html`、`styles.css`、`game.js`），浏览器直接打开即可游玩。无构建、无包管理器、无本地服务器、无网络请求。游戏包含方向键与 WASD 双套控制、吃食物 +1 分并变长、撞墙/撞自身结束、当前分与最高分（localStorage）显示、结束后 R 键或「重新开始」按钮重开。

## 2. 技术方案

### 2.1 总体选型

| 关注点 | 定案 | 理由 |
| --- | --- | --- |
| 渲染 | HTML5 Canvas 2D，单画布 `#game-canvas` | 意图硬约束；网格与蛇身按格绘制最直接 |
| 脚本组织 | 单个经典脚本 `game.js`，IIFE 包裹，不拆分 ES module | `file://` 直接打开时 ES module 的跨文件 `import` 会被浏览器 CORS 策略拦截；经典脚本是「双击即可运行」最稳妥的做法 |
| 样式 | 单个 `styles.css`，系统字体栈，无外链字体 | 零依赖、离线可用 |
| 依赖 | 无任何第三方库/CDN/包管理器清单 | 意图范围与 AC-2 |
| 构建 | 无构建步骤，源码即产物 | 意图约束「浏览器直接打开」 |
| 持久化 | `localStorage`，单 key `snake-game.highscore.v1` | 意图约束「最高分仅存本地浏览器」 |

### 2.2 文件布局

```text
game/
├── index.html    # 页面骨架：HUD、canvas、overlay、重新开始按钮
├── styles.css    # 深色主题、棋盘容器、HUD、按钮与 overlay 样式
└── game.js       # 全部游戏逻辑：状态机、输入、步进、碰撞、渲染、localStorage
```

入口与运行方式：用浏览器直接打开 `game/index.html`（双击或拖入浏览器窗口），不需要启动任何服务器。

### 2.3 模块分解与依赖方向

- **单一实现模块 `game`（path `game/`）**：交付上述三个静态文件，作为整体交付与验收单元。
- 模块内分层（逻辑分层，非目录拆分）：
  1. 页面骨架（index.html）：只负责 DOM 结构与静态文案；
  2. 表现层（styles.css + `render()`）：只读游戏状态、只写画布与 DOM；
  3. 规则层（`step()`、`queueDirection()`、`placeFood()`、碰撞判定）：不触碰 DOM；
  4. 输入与持久化适配（键盘事件、按钮事件、`loadBest()`/`saveBest()`）：边界适配层。
- 依赖方向：`index.html` → `styles.css`、`game.js`（单向引用）；`game.js` 内部 规则层 ← 表现层/适配层，规则层不反向依赖 DOM。无模块间循环依赖，无跨项目依赖。

### 2.4 关键定案

| 项 | 定案值 |
| --- | --- |
| 棋盘尺寸 | 24 列 × 24 行，单元格 20 px，画布 CSS 尺寸 480 × 480；按 `devicePixelRatio` 放大 backing store，CSS 尺寸保持不变（网格清晰不模糊） |
| 初始蛇 | 长度 3，水平放置，位于第 12 行，蛇头初始朝右；蛇身格互不重叠 |
| 初始速度 | 固定步进 120 ms/步；不做加速、不做难度曲线（非目标） |
| 游戏状态 | `READY`（等待首次方向输入）→ `RUNNING` → `GAME_OVER`；首次加载进入 `READY`，overlay 提示「按方向键 / WASD 开始」 |
| 反向保护 | 禁止相对当前朝向的 180° 掉头；方向输入进入容量为 2 的队列，每步消费一个，避免同一 tick 内连续两次转向导致自撞 |
| READY 阶段输入 | 首个方向键设置朝向并立即进入 `RUNNING`；与初始朝向（向右）相反的方向（←）视为无效输入，保持 `READY` |
| 吃食物 | 蛇头进入食物格：分数 +1、蛇身 +1（不删除尾格）、立即在新空格随机生成食物；食物不与蛇身重叠 |
| 碰撞判定 | 蛇头下一步越出 24×24 边界 → 撞墙；蛇头下一步进入「本步结束后仍将存在的蛇身格」（未进食时排除即将离开的尾格）→ 撞自身；两者均立即进入 `GAME_OVER` |
| 结束提示 | 画布上的 overlay 显示标题「游戏结束」与副标题「得分 N · 按 R 或点击「重新开始」」；蛇与食物保持静止显示 |
| 重新开始按钮 | 文案「重新开始」，位于画布下方控制区右侧，`id="restart"`，始终可见；点击后立即开始新一局并进入 `RUNNING` |
| 重开键 | `R` / `r` 仅在 `GAME_OVER` 状态生效，效果与按钮一致 |
| 最高分刷新时机 | 每次得分后若 `score > best` 立即更新 `#best` 并写入 localStorage（实时刷新）；新一局分数归零、最高分保留 |
| 最高分读取 | 页面加载时读取并校验为「非负安全整数」，非法/缺失一律按 0 处理 |
| localStorage 不可用 | 读写均 try/catch；不可用时游戏照常运行，最高分退化为内存内记录，不报错、不阻断 |
| 棋盘填满 | 理论边界：无空格可放食物时本局以「通关」结束（AC 不覆盖，仅作防御性处理，不扩大交付范围） |
| 设备与输入 | 仅桌面键盘；不做触屏（非目标） |

### 2.5 状态机

```text
READY --(方向键/WASD，非反向)--> RUNNING --(撞墙/撞自身)--> GAME_OVER
                                   ^                            |
                                   |----(R 键 或 重新开始按钮)----+
                                   ^
页面首次加载 ----------------------READY
```

- 状态迁移时保证：`RUNNING` 有且仅有一个步进定时器；离开 `RUNNING` 立即清除定时器（防重复计时器泄漏）。
- `GAME_OVER` 下方向键不改变状态；`READY` 下按钮/R 不产生副作用（避免误开）。

### 2.6 可扩展点（不实现，仅预留结构）

- `CONFIG` 常量对象集中管理棋盘行列、格宽、步进间隔、初始长度、颜色与 localStorage key，后续可单点调整。
- 步进与渲染解耦：`step()` 只改状态，`render()` 只读状态绘制；换渲染方式不影响规则层。
- 输入映射表集中定义，新增键位不改规则层。

## 4. AC-1 ~ AC-10 覆盖矩阵

| AC | 覆盖方式 | 观察点 |
| --- | --- | --- |
| AC-1 直接打开可运行 | 纯静态三文件，无服务、无构建 | 双击 `game/index.html` 正常出棋盘与分数区，Console 无阻断性报错 |
| AC-2 无第三方依赖 | 全部引用为同目录相对路径；无 CDN/外链/package.json | 断网刷新与游玩不受影响；源码中无外链 URL |
| AC-3 深色背景 + 网格棋盘 | 深色主题 + 每格 20 px 网格线绘制 | 棋盘深色底、网格线可见、得分文字清晰 |
| AC-4 方向键控制 | `ArrowUp/Down/Left/Right` → 方向队列，禁止 180° 掉头 | 游戏中方向即时生效；按反向键蛇不转向、不自撞 |
| AC-5 WASD 控制 | `w/a/s/d`（含大写）映射同上 | 效果与 AC-4 一致 |
| AC-6 吃食物加分变长 | 头部进入食物格：score+1、length+1、重新生成食物 | 分数与长度恰好 +1；连续 k 次均累计 +k |
| AC-7 撞墙/撞自身结束 | 越界判定 + 自撞判定（排除本步将离开的尾格） | 立即显示「游戏结束」，蛇停止移动 |
| AC-8 当前分与最高分 | HUD 常显 `#score`/`#best`；破纪录实时写 localStorage | 刷新页面/重开浏览器最高分仍在；新局分数归零最高分保留；localStorage 中有对应 key |
| AC-9 重新开始 | `R`（GAME_OVER）或 `#restart` 按钮 | 两种方式均进入新一局，可继续游玩，分数归零、最高分保留 |
| AC-10 交付说明完备 | 交付时向客户给出路径与运行/操作/重开说明 | 说明与实际行为一致，验收人可按说明复现 |

核心必测项（意图要求至少覆盖）：AC-1、AC-2、AC-6、AC-7、AC-8。

## 5. 质量与测试计划

不引入任何测试框架或自动化依赖；全部为真实桌面浏览器手工核对。建议步骤：

1. **静态检查**：确认 `game/` 下仅 `index.html`、`styles.css`、`game.js`；全文搜索 `http://`、`https://`、`<script src=` 外链、`package.json`，结果应为 0（AC-2）。
2. **直接打开**：双击 `game/index.html`，确认棋盘、分数区、按钮渲染，Console 无 error（AC-1、AC-3）。
3. **离线**：断开网络（或 DevTools → Network → Offline）后刷新并游玩（AC-2）。
4. **方向控制**：RUNNING 下依次按 ↑ ↓ ← →，确认转向；再对每个方向按反向键，确认不转向不自撞（AC-4）；W/A/S/D 重复同样检查（AC-5）。
5. **计分与增长**：记录吃食物前后的分数与目视长度，确认各 +1；连续吃 3 个确认 +3（AC-6）。
6. **碰撞**：分别验证撞墙与撞自身（用长蛇绕圈制造自撞），确认立即出现「游戏结束」并停止移动（AC-7）。
7. **最高分持久化**：破纪录后检查 `#best` 实时变化；刷新页面、关闭并重开浏览器后确认最高分仍在；重开后当前分归零（AC-8）。
8. **重开**：结束后按 R 验证；再次结束后点「重新开始」验证；两种方式均可继续游玩（AC-9）。
9. **交付说明**：按交付说明复述路径与操作，确认与实际一致（AC-10）。

浏览器矩阵：Chrome、Edge、Firefox 最新桌面版（至少主验一款，其余抽查 AC-1/AC-4/AC-8）。分辨率：1280×720 及以上；页面在窄窗口下仅需不重叠，不做响应式适配要求。

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `file://` 下 localStorage 行为差异（部分浏览器限制） | 最高分可能不持久 | 读写 try/catch 降级为内存记录；验收以 Chrome/Edge 为准，并在交付说明中提示 |
| 高分屏网格/蛇身模糊 | 观感与 AC-3 观察 | 按 devicePixelRatio 缩放 backing store 后再绘制 |
| 同一 tick 内连按两次方向导致自撞 | 操作手感与 AC-4 争议 | 方向队列容量 2、每步消费一个、入队时校验反向 |
| 步进定时器在重开/结束时未清理 | 双倍速或结束后仍移动 | 单一 `timer` 句柄，迁移状态时统一清理 |
| 食物生成死循环 | 卡死 | 从空格集合随机选取，空格为空时进入「通关」防御分支 |
| 键盘重复事件刷屏 | 队列被无效输入占满 | 入队前与队尾方向相同则忽略；队列容量上限 2 |
| 范围蔓延（音效/加速/移动端） | 超范围交付 | 已列入非目标，投标与实现均不触碰 |

## 7. 非目标复述

不做后端/账号/登录/云存档；不做在线排行榜与任何联网；不做移动端触屏与响应式适配要求；不做音效、皮肤、多关卡、障碍物、道具、加速难度；不做多人对战；不引入第三方库、构建工具、包管理器；不做营销页、埋点、运营后台。
