# 产品意图 · 贪吃蛇（snake-game）v1

## 1. 目标用户与场景

- 目标用户：想玩一个简单贪吃蛇的普通用户（单人在自己设备上玩，无账号、无联网）。
- 使用场景：在浏览器/本机打开游戏后直接开始玩；用键盘操控蛇吃食物得分；撞墙后看到结束提示并重开再来一局。

## 2. 要解决的问题

客户希望拥有一个可玩的贪吃蛇游戏，且必须包含四条功能项：键盘控制、计分、重开、边界碰撞（撞墙判定）。当前项目目录为空、无既有实现，需要从零交付该最小可玩游戏。

## 3. 客户原话（照录，不改写）

> 做一个贪吃蛇游戏，需具备四条功能项：
> 1) 键盘控制；
> 2) 计分；
> 3) 重开；
> 4) 边界碰撞（撞墙判定）。

## 4. 范围与非目标

### 4.1 范围内

- 单机单人可玩贪吃蛇；四条功能项全部实现。
- 实现形态：HTML/JS 单页面（浏览器直接打开即可运行），或环境不支持浏览器时的等价最小可运行形态，启动方式在交付说明中写明。
- 隐含最小本体：蛇身增长、食物生成、游戏结束判定（四条功能项成立的必要前提）。

### 4.2 非目标

- 联网、多人、排行榜、账号登录、持久化存档。
- 超出功能最小实现的美术/音效/动画表现力要求。
- 移动端触屏适配（键盘为唯一要求的输入方式）。

## 5. 成功 / 验收标准

四条功能项各自的可核验判定口径（详见 frontmatter `acceptance`）：

| 编号 | 功能项 | 可核验判定口径 |
| --- | --- | --- |
| A1 | 键盘控制 | 方向键四向均产生可观察响应；以最后有效方向输入为准，不出现非法反向自撞 |
| A2 | 计分 | 进食加分、界面可见、随进食递增、重开后归零 |
| A3 | 重开 | 有可触发方式（R 键或按钮）；触发后状态归零并可立即新开一局，无需刷新 |
| A4 | 边界碰撞 | 封闭边界、非穿墙；蛇头触及/越界即判碰撞并结束，给出可观察结束提示，重复测试稳定复现 |

共同判定：均可人工操作观察验证，不依赖特定测试框架。

## 6. 客户明确 vs 假设 vs 待确认

### 6.1 客户明确（不可改）

- 交付对象是贪吃蛇游戏；四条功能项为必须。
- 边界碰撞的语义为「撞墙判定」。

### 6.2 假设（客户未明确，本意图按最小实现取值；如客户另有要求需变更版本）

- 假设：单机、单人、无联网、无账号、无持久化存档。
- 假设：场地为四周封闭边界（非穿墙）；撞墙即结束游戏（不扣分、不反弹）。
- 假设：方向输入以键盘方向键为最低要求（WASD 为可选扩展，不在验收必需项内）。
- 假设：计分为「吃到食物加分」的简单累计，不含连击/倍率规则。
- 假设：四条功能项为 must，其余（美术、音效、触屏、最高分）为可选扩展。

### 6.3 待确认项（不阻塞本版意图；若答复与本版假设冲突，按版本化出新版 v2）

1. 技术栈与运行方式（浏览器 / 桌面 / 终端；是否需要构建工具）。
2. 交付形态（源码 / 可运行包 / 演示链接）与验收时的启动方式。
3. 视觉与交互质量档位（最小功能实现 vs 像素风 / 音效 / 移动端可用）。
4. 撞墙后的期望行为（结束 / 扣分 / 反弹）。
5. 场地是否穿墙（本版按封闭边界）。
6. 操作细节（是否需 WASD、暂停键）。
7. 计分规则（固定分 / 连击 / 最高分记录）。
8. 重开触发范围（仅结束后可重开 vs 游戏中随时可重开；本版要求「可触发重开并可立即新开一局」，不限定只能在结束后）。

## 7. 质量档位

- 档位：功能最小可玩（功能正确、可人工验收、无严重异常）；不做美术/音效等表现层打磨。
- 质量底线：四条功能项验收口径全部通过；游戏可连续运行不崩溃；撞墙判定稳定可复现。

## 8. 约束

- 不联网、不引入账号或云端依赖；实现形态便于在本机直接运行与人工验收。
- 本版意图不含实现方案、模块拆分与名单安排（由后续策划产出）。
