## 0. 验收方法总则

- 全部标准通过**人工操作观察**判定：启动游戏后按步骤操作并观察画面/文本，不依赖自动化测试框架、不要求录屏。
- 证据最多为**真实运行截图**（放在 `docs/verification/`，文件字节数与 sha256 由应用计算并写入 sidecar；本文件不计算、不转抄哈希）。
- 每条标准分别给出「前置条件 / 操作步骤 / 通过条件」；任一条件不满足即该 AC 不通过。
- 证据缺失或无法观察时如实记为 insufficient evidence，不以推断替代真实核对。
- 判定基于任务指定的**最终完整 OID**当前内容与真实运行环境；内容已变或候选漂移时不得沿用旧结论。
- 若交付环境不支持浏览器，按意图与架构 §5 的等价最小可运行形态执行同样的步骤与通过条件，启动方式以 README 为准。
- 优先级含义：P0 为四条功能项与稳定性底线（不满足即整体不通过）；P1 为交付可运行与说明；P2 为非目标约束（应无违反，发现违反按缺陷记录）。

## 1. 验收标准明细

### AC-1 键盘方向键四向均产生可观察响应（对应意图 A1）

- 前置条件：游戏已启动并处于运行中（蛇在持续移动，尚未结束）。
- 操作步骤：
  1. 观察蛇当前移动方向，记下蛇头位置。
  2. 按一次 ↑（上方向键），等待至少 1 个 tick，观察蛇头是否向上移动。
  3. 按一次 ←（左方向键），观察蛇头是否向左移动。
  4. 按一次 ↓（下方向键），观察蛇头是否向下移动。
  5. 按一次 →（右方向键），观察蛇头是否向右移动。
  6. 每次按键与下一次按键之间留出至少 1 个 tick，确保上一次方向已生效；整个过程中不按与当前方向相反的键（反向校验由 AC-2 覆盖）。
- 通过条件：四个方向键各按一次后，蛇头在下一 tick 分别向上、左、下、右移动，四个方向均产生清晰可见的响应；不存在「按键后方向不变」或「四个方向中有方向无响应」的情况。

### AC-2 方向以最后有效输入为准且拒绝非法反向，不出现反向自撞（对应意图 A1）

- 前置条件：游戏运行中，蛇长度 ≥2 且在移动（初始长度即满足）。
- 操作步骤：
  1. 反向拒绝：确认蛇当前向右移动，按一次 ←（与当前方向相反），等待 1–2 个 tick，观察蛇是否仍向右移动、是否立即结束。
  2. 最后有效输入为准：确认蛇当前向右移动，在同一个 tick 间隔内快速连按 ↑ 再按 ↓（两者相对当前方向均为合法垂直方向），观察下一 tick 蛇头实际移动方向。
  3. 重复第 1 步的反向输入 2–3 次（可在不同方向下重复）。
- 通过条件：
  - 反向输入被拒绝：按下与当前方向相反的键后，蛇的移动方向不改变，且不出现因立即反向而撞到自身导致的游戏结束；
  - 同一 tick 间隔内多次合法输入时，下一 tick 的移动方向等于**最后一次有效输入**的方向（步骤 2 中应为 ↓）；
  - 重复反向操作后仍无「反向自撞」异常结束。

### AC-3 蛇吃到食物后分数增加，每次进食固定 +1（对应意图 A2）

- 前置条件：游戏运行中，画面可见蛇与食物。
- 操作步骤：
  1. 记下当前分数与食物所在格。
  2. 用方向键把蛇头引导到食物所在格，使蛇头进入食物格。
  3. 观察进食发生的当 tick 的分数与蛇身长度。
- 通过条件：蛇头进入食物格后，分数立即增加 1（本版架构约定每次进食固定 +1，无连击/倍率）；蛇身长度增加 1 格；食物在别处重新出现。

### AC-4 界面存在可观察的实时分数显示（对应意图 A2）

- 前置条件：游戏已启动。
- 操作步骤：
  1. 启动后不按键，观察界面是否显示分数（如「分数：0」）。
  2. 完成一次进食（参见 AC-3 步骤）后观察分数显示是否同步更新。
- 通过条件：界面存在明确的分数显示区域，启动时可见初始分数，进食后无需刷新即在同一界面更新；分数不是隐藏的调试值，正常视口内可读。

### AC-5 分数随每次进食逐次递增（对应意图 A2）

- 前置条件：游戏运行中，分数显示可见。
- 操作步骤：
  1. 记录初始分数。
  2. 连续引导蛇进食 3 次（每次进食后记录分数：S1、S2、S3）。
- 通过条件：S1 = 初始分数 + 1，S2 = S1 + 1，S3 = S2 + 1，即分数随每次进食严格逐次递增 1；期间不出现分数跳变、回退或与实际进食次数不符。

### AC-6 触发重开后分数归零（对应意图 A2）

- 前置条件：游戏运行中，已累计分数大于 0。
- 操作步骤：
  1. 记录当前分数（>0）。
  2. 按重开方式（R 键或界面按钮，见 AC-7）触发重开。
  3. 观察分数显示。
- 通过条件：重开后分数显示立即变为 0；无需刷新页面。

### AC-7 提供可触发的重开方式（对应意图 A3）

- 前置条件：游戏已启动；README 已写明重开方式。
- 操作步骤：
  1. 阅读 README 中的重开说明。
  2. 游戏运行中按说明触发重开（R 键或界面按钮）。
  3. 若游戏处于结束态，再次按说明触发重开。
- 通过条件：至少一种可触发方式真实有效，且与 README 说明一致；运行中与结束态均可触发（本版意图不限定只能在结束后重开）；触发后游戏有明确响应（不要求弹窗，状态变化即可）。

### AC-8 重开后状态归零且无需刷新即可立即新开一局（对应意图 A3）

- 前置条件：游戏运行中，分数大于 0、蛇已偏离初始位置（可另在游戏结束态复测一次）。
- 操作步骤：
  1. 记录重开前蛇的位置/长度、分数与结束态。
  2. 触发重开。
  3. 观察蛇的位置与长度、分数、结束提示、游戏是否继续运行。
  4. 重开后立即按方向键继续操作。
- 通过条件：重开后蛇回到初始位置与初始长度（长度与首局初始长度一致）、分数归零、结束态解除、结束提示清除；游戏立即恢复运行，可马上用方向键开始新一局；整个过程中页面未整页刷新（无需手动刷新、无需重新打开页面）。

### AC-9 四周封闭边界、非穿墙，蛇头触及或越界即判定碰撞并结束（对应意图 A4）

- 前置条件：游戏运行中，画面可见完整游戏区域边界。
- 操作步骤：
  1. 用方向键把蛇朝某一方向（如向右）持续直行，直到接近边界。
  2. 观察蛇头抵达边界时的行为：是否越过边界、是否从对侧穿出、是否结束。
  3. 重开一局，换一个方向（如上）重复步骤 1–2；再换第三、第四个方向重复，覆盖四条边。
- 通过条件：游戏区域四周为封闭边界；蛇头在将要越出边界的 tick 即被判定碰撞，游戏结束并停止移动；蛇头不显示在边界之外，也不从对侧穿出（非穿墙）；四个方向/四条边均符合该行为。

### AC-10 游戏结束时给出可观察结束提示（对应意图 A4）

- 前置条件：游戏运行中。
- 操作步骤：
  1. 按 AC-9 步骤主动撞墙结束游戏。
  2. 观察界面是否出现结束提示，是否包含「游戏结束」类字样与最终分数。
  3. 随后触发重开，观察提示是否清除。
- 通过条件：结束时界面显示清晰可读的结束提示，含「游戏结束」类字样与最终分数（与结束前分数一致）；结束后蛇不再移动、不再响应移动键；重开后结束提示清除。

### AC-11 边界碰撞判定重复测试稳定可复现（对应意图 A4）

- 前置条件：可正常启动与重开游戏。
- 操作步骤：
  1. 至少重复 3 次「主动撞墙」测试（可分别覆盖不同边界与不同方向，含一次在分数大于 0 后撞墙）。
  2. 每次记录：是否在预期 tick 结束、结束提示是否出现、最终分数是否正确。
- 通过条件：3 次及以上重复测试每次都稳定结束并出现结束提示，最终分数与结束前一致；不出现偶发「越界不结束」「结束但不提示」「时好时坏」等情况。

### AC-12 游戏可连续运行不崩溃（意图第 7 节质量底线）

- 前置条件：游戏已启动。
- 操作步骤：
  1. 启动后让游戏连续运行至少 180 秒，期间穿插若干次方向键操作与 1–2 次重开。
  2. 全程观察画面是否正常刷新、是否白屏/卡死/无响应。
  3. 打开浏览器开发者工具控制台（若可用），观察是否有未捕获的 JavaScript 错误。
- 通过条件：连续运行 ≥180 秒内游戏循环不中断、画面不白屏、页面不卡死，操作仍有响应；控制台（若可用）无未捕获异常；若交付环境无控制台，以「可连续操作且无异常中止」作为可观察判定并在报告中写明核对方式。

### AC-13 可按 README 说明直接运行，且说明含操作键位与规则（对应架构 §5）

- 前置条件：拿到交付目录。
- 操作步骤：
  1. 阅读 README.md 的启动方式，按说明启动游戏（本版约定：浏览器直接打开 `index.html`，不需要构建、依赖或本地服务器；若为等价最小形态，按 README 写明的启动方式）。
  2. 核对 README 是否写明操作键位（↑↓←→ 移动、R 重开；若用按钮重开则写明）、计分规则与结束规则。
- 通过条件：按 README 说明无需安装与构建即可成功进入游戏；README 包含启动方式、操作键位、计分与结束规则；说明与实际行为一致（至少抽验方向键、重开键与撞墙结束）。

### AC-14 不发起网络请求、不使用持久化存储（对应意图/架构非目标与 §5）

- 前置条件：游戏已启动，浏览器开发者工具可用。
- 操作步骤：
  1. 打开 Network 面板后启动游戏并游玩若干次（含进食与重开），观察是否有网络请求（本地页面自身资源加载除外）。
  2. 观察 Application/Storage 中是否有本页写入的 localStorage、sessionStorage 或 cookie。
- 通过条件：游玩过程中无外部网络请求；不使用 localStorage/sessionStorage/cookie 等持久化存储（刷新即重开的语义成立）；若交付环境无开发者工具，记录为无法核对并说明原因，不臆断通过。

## 3. A12b 核对要求（供后续报告使用）

- 报告写 `docs/quality/snake-game-report-vN.md`，逐条给出 AC 判定（通过 / 不通过 / insufficient evidence）与可观察证据。
- 报告与证据必须绑定任务指定的最终完整 OID；指定 OID 漂移或内容变化时停止沿用旧结论，如实回报来源链。
- 不通过按新 attempt 返工；缺证据或失败正式 blocked/failed 回报幕僚，不静默等待。
