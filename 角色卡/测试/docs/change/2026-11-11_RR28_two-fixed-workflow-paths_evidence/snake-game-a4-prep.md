# snake-game A4 方案受理/准备说明

> 本文仅为 A4 阶段「方案受理/准备」记录，**不是**正式提案、模块清单、人员名单或架构契约。正式产物按 A5 另行派发，写入 `docs/proposals/` 与 `docs/contracts/`。

## 0. 受理依据

- 意图：`docs/product/snake-game-intent-v1.md`（intentId=snake-game，flowId=snake-game，version=1；A3 已由客户本人 confirm）。
- 对照基线（四项硬验收 + 基本可运行性）：
  1. 键盘控制：方向键或 WASD 控制蛇持续移动；
  2. 计分：吃到食物分数增加，界面可见当前分数；
  3. 重开：游戏结束后可重新开始，分数与蛇的位置/长度等状态复位；
  4. 边界碰撞：蛇头撞边界立即失败并结束本局，不穿墙、不环绕；
  5. 基本可运行性：本地可正常启动并游玩，无启动即崩溃。
- 意图 6 节已界定范围/非目标/质量档位；本案准备说明与之逐项对照，未发现与意图冲突项。

## 1. 技术选型倾向

**倾向：纯前端 HTML/CSS/JS 单页实现（原生 JS，无构建工具、无外部依赖、无网络请求）。**

- 运行方式：在项目根目录新建 `index.html` + `styles.css` + `game.js`（或等价的最小文件集），双击 `index.html` 即可在浏览器打开游玩；也可经任意本地静态服务器（如 `python -m http.server`）访问。
- 理由：
  - 意图明确不锁定技术栈，仅要求本地可运行、功能齐全、稳定不崩溃；
  - 零依赖、零构建与「无需账号/联网」的非目标/场景一致，冷启动风险最低；
  - 使用 Canvas 2D 渲染与 `setInterval`/`requestAnimationFrame` 驱动的固定步长逻辑，可在无外部库条件下完整覆盖四项硬验收。
- 备选（仅在正式方案阶段发现上述方案不可行时再考虑）：以 Node.js + 静态托管脚本提供启动脚本（仍不含前端框架）；或改用 JS + 极简 Canvas 库（若客户后续要求视觉表现）。
- 明确不引入：前端框架（React/Vue 等）、打包器（Webpack/Vite）、网络后端、持久化存储。

## 2. 模块划分草案（仅草案，非正式模块清单/名单）

| 草案模块 | 职责 | 建议落点（草案） |
| --- | --- | --- |
| 游戏状态 | 蛇身坐标队列、食物位置、当前分数、游戏状态枚举（就绪/进行/结束）、重开时的状态复位 | `game.js` 内状态层 |
| 输入处理 | 监听方向键与 WASD，维护「下一方向」缓冲，禁止 180° 反向；游戏结束后忽略/承接重开输入 | `game.js` 内输入层 |
| 主循环/规则 | 固定步长推进，移动蛇身、判定进食与计分、边界碰撞判定（出界即失败，不环绕） | `game.js` 主循环层 |
| 渲染 | 绘制网格、蛇、食物、分数文本与结束提示/重开提示 | `game.js` + `styles.css` |
| 页面入口 | 标题、计分区、画布与操作说明的静态结构；脚本挂载 | `index.html` |

说明：以上为职责切分草案，文件级/模块 id 与目录归属留待 A5 正式方案与模块清单确定；草案中「单文件承载多职责」可在 A5 拆分为独立文件。

## 3. 验收所需证据形态建议（供后续实现/验收阶段参考）

- **静态证据**：
  - 实现文件清单与关键代码路径（`index.html`、`game.js`、`styles.css`）；
  - 关键逻辑的代码片段/行号引用：键盘事件绑定、计分递增、状态复位、边界碰撞判定；
  - 静态检查结论：无外部依赖/无网络请求（不出现 CDN、fetch、第三方脚本）。
- **运行证据**：
  - 本地启动方式与启动成功截图（页面加载完成、画布与分数可见）；
  - 键盘控制运行截图/录屏（方向键与 WASD 均可改变移动方向）；
  - 进食计分截图（分数数值实际增加）；
  - 边界碰撞失败截图（撞边界立即结束，无穿墙/环绕）；
  - 重开截图（结束后点击/按键重开，分数归零、蛇身复位）。
- **建议形态**：以 PNG 截图 + 简短操作步骤文本（playbook）为主；如运行环境支持，补充短录屏。证据需可由第三方按步骤复现，避免仅凭自述。
