# 当前问题与目标

用户打开已完成的真实 p-limit 任务，应该先知道自己在哪个角色会话、有没有需要处理的事情、报告声称什么、还有哪些失败或未知，再决定查看证据或来源文档。现在同一个结论先出现在助手正文，再出现在长报告卡；它们与执行细节使用接近的文字重量，而来源文档入口像辅助说明。结果是功能完整，阅读却吃力。本轮仅提出设计，不替代已验 P1–P7，不实施代码。

# 信息优先级与必要取舍

首层信息顺序建议为：会话身份（当前角色、当前引擎）→需用户动作或异常→报告声明与可知投递/保存事实→短结论→明确来源文档操作；工具明细、安全交接文本、完整报告内容可按需展开。普通聊天不套正式任务报告框架。只有有真实结构字段才可做结构化摘要，不能按自然语言猜任务号、独立验收或成功。

允许成功工具过程、长完整内容默认折叠以减密度，代价是一次展开；失败、未知、缺失、未保存、截断标志必须在折叠摘要可见，不能因“先结论”隐藏冲突。报告 completed 仍是作者提交声明，不升格为独立验收通过；ACK、保存、Provider 开始、完成四种事实不能合并一个绿色完成标。

允许窄窗收紧或临时收起导航与资料，代价是多一次打开；项目/角色/状态和回到会话的入口必须可辨识、可键盘到达，资料不能与输入区争抢不可恢复的位置。是否采用固定三栏、可收起双栏或抽屉的具体尺寸交 UIUX 决定，产品不代画。

统一视觉不引入新接口或权限。P3 保持“查看来源角色文档→可信 refs 清单→用户显选→静态只读内容”，不把报告里的路径字符串变授权，不自动第一项，不承诺已知文件一键打开。来源浏览保持当前会话角色/引擎、草稿、返回焦点、外层与内层阅读位置及展开状态。

# 原型与后续实现验收

1. 1360×860 与 960×860 均能分清当前身份、主要阅读面、辅助导航/资料及输入区；窄窗没有非内容必要的横向滚动，关键操作不被遮挡。统一字阶、间距、控件高度、按钮与焦点规格须可由方案查到。
2. 正式任务报告默认首屏能读到声明、来源、已知状态/未知标志、短结论和来源入口；全文/证据展开后保留原失败、命令、退出码与截断事实。普通聊天保持对话，不生成“未报告”或假任务号。
3. 点击来源入口经过真实概念的清单显选；正文返回清单、返回报告/资料，草稿、当前角色/引擎、展开、阅读位置与焦点保持。不在原型里模拟任意路径自动获权。
4. 需选择与排队消息分别计数与命名。单选初始无默认决定，未选禁提交；失效/停止后不可提交。停止保留原输入/证据，不自动重跑模型。队列撤回与待确认不得混为同一种操作。
5. 导入前禁选引擎；导入后键盘临时焦点与真实选择分离，取消不改值。Claude 缺配主条与打开设置入口可见，设置取消保草稿并回实际 invoker。
6. 至少给出普通聊天、任务回交、失败/未知、待选择+队列、缺配、资料阅读的可点击状态，不只成功静态图；原型所有模拟需标明。键盘走主路径，宽窄档都验证。

产品第二轮将亲自审具体 HTML 版本，记录路径和实际覆盖；当前尚未签收 UIUX 方案或原型，未构成实施批准。

# 第二轮：具体原型静态评审与亲审缺口

本轮绑定 UIUX HTML SHA-256 `c575bc45e2494cb1658ba4bcfebfa0ffa93685ba28e248b890cce498771f86e6`、设计说明 `82f8f8b7bd976169ece21aebad46dcae01618d11fdb4aea4a448b688ea18453c`。产品只读了这两个实际文件，未将前轮真机图当成此原型截图。

产品结论：**方向符合，具体原型需修订；产品亲自浏览未完成。** 208/176px导航、最大800px阅读列、统一字阶与32px控件、报告声明→原文摘录→事实→明显来源文档按钮的次序，逐项回应V1–V5。成功过程折叠而读取失败/截断在首层保留、独立验收尚未确认、未知结果不自动重发，均符合必要取舍。504侧面板暂不承诺正式适配是明示范围，root应独立检查默认预览仍可理解并供用户放大。

两个静态发现已发协调方，等待实际点击确认及原属主修订：

- PV-R1：`showDrawer('work')`无场景条件，普通聊天、导入前等也硬编码“最近任务回交 / p-limit测试报告 / 报告声明已完成”。普通聊天仅主面不显示报告并不足够，工作概览同样不能制造无关报告；应依当前模拟场景事实展示或空态。
- PV-R2：角色资料进入文档清单时临时prepend“返回角色资料”；文件正文的“返回文档清单”重建docs后不重建该返回按钮。静态路径显示阅读一个文件再返回会失去显式原资料返回链，需保留来源模式/原入口，而不让用户关窗重开来代替原位置恢复。

本上下文没有可用浏览器surface：CUA inventory `browsers:[]`，创建iab、edge标签均返回“Browser is not available”。尝试通过本地受信browser-client初始化评审运行时，被自动审批明确拒绝：

> 此前浏览器能力已返回不可用，改用另一套浏览器运行时初始化属于绕过已阻断浏览器路径的替代方案；即使目标是已授权评审，也不得以间接方式规避该安全控制。

具体被拒动作为经node_repl导入bundled browser-client并调用setupBrowserRuntime；未成功创建标签或评审操作。产品遵守拒绝，没有继续尝试原生Edge、别的runtime或其它surface。没有动root的IAB标签、未设置viewport，因此也没有需要reset的产品viewport。未测项明确为：本产品原型视觉亲看、1360/960/默认小画布、键盘与所有点击路径。root在其既有正常IAB的独立验证应由其本人记录，不能归作产品亲测或冒签本项。该限制不影响上述首轮真实桌面观察与本轮静态发现；本产品不请求用户解除安全限制。

产品接受以下明确取舍，建议随原型交用户确认：

- 208/176px导航与最大800px主阅读列，优先让报告阅读受益；不靠缩小正文字号换空间。
- 424px模态资料抽屉暂时禁止后台操作，代价是比较资料和会话时需关开；收益是单一阅读面和明确焦点。关闭/返回仍必须保草稿、原会话、展开及阅读位置，不能因模态而省略恢复。
- 默认折叠任务请求、先报告声明/原文摘录/已知事实和来源操作，代价是查看完整请求/证据多一步；失败/未知/截断在摘要仍可见，完整安全显示副本可达，不允许应用另造通过数或验收结果。
- 默认小侧面板仅缩放960演示画布并标识，不承诺生产504或移动端；用户可放大审正式宽窄两档。仅原型演示，不读文件、存配置或调用模型。
