# 改完的界面：五项没有退回，新皮肤也没有挡住正事

客户看过实现与 v2 设计后原话：「这个和设计还是有差别啊，你让桌面按照 UI设计来改，改完了让UI，和产品复核。」这一轮由产品做**独立复核**：在上轮五项返工（R1–R5）之后的「按设计对齐」改造，加上紧随的「虚拟行锚点漂移」修复，是否让界面更好用、且没有把上轮刚修好的体验改回去。**唯一结论：通过（限产品面）**——见文末「最终签署」；证据覆盖与限制同步列明，不作超出证据的宣称。

范围：R1–R5 保持性复核 + 对齐改造的产品面评估。不纳 O1–O4（报告声明/主入口验收措辞、Pi 易读标签/超时出口、文档预览、长会话查找），不召开新会议，不操作用户 ANS/模型，不改任何生产/测试/UIUX 文件。产品通过只代表本轮范围达到约定条件：不宣称「殿堂级」、不替代 UI/UX 的独立结论；PM 需在两角色对**同一冻结候选**都通过后才提交/推送，本角色不进行 git 提交或放宽这项条件。

### 发现的观察项（逐条，均非阻塞）

1. **浮动定位药丸会压住底部行首 1–2 个字**：1360 档 A 图底部「等待你确认」被压掉「等待」两字（可见「你确认」）；960 档压住段首首字。核实为**既有观感债，非本轮回退**：药丸的 sticky/位置规则对齐前后相同（几何一致），1360 档因内容列从贴左（x≈300）改为 760 居中（x=431），覆盖反而**减少**；960 档内容列左缘 300→296，无实质变化。它源于 R5 期「药丸靠未被抽屉覆盖的左侧」的定位优先于文字避让，当时已被接受。列为后置打磨项（例如底行避让或药丸加底槽），**不阻断**本轮对齐。
2. **S1/S2/S3（归档记录「保留/交回PM」清单）**：助手说话人行（.speaker）、队列纵向节奏（统一 16px gap 保留）、焦点环绿色 `#42745E`（在规范取色表外，来自原型）——均为设计裁定事项，产品面无阻塞；如实保留，不因复核扩新契约。
3. **证据卫生两则**：① A960 三张图（`chat` / `chat-top` / `chat-records-open`）经 MD5 核对为**同一字节的文件**（960 档的「顶部/展开」状态未单独成图；展开态本身在图内可见，且两档收起/展开的几何与断言由测试套件覆盖）。② PM `report.json` 内**无候选哈希字段**；其读数与冻结候选的 CSS/DOM 逐项一致，且漂移修复不动 CSS/DOM，故该组视觉证据对两版同样成立——**行为证据一律以测试角色哈希绑定的三套件为准**。

### A 图第一张异常卡的形状说明（S1 边界，务必别误读）

A1360 图顶部第一张异常卡形如「read_file 执行失败：src/store/missing.md（ENOENT）／目标未记录」。我按要求核实了这一形状的**可产性**：产品源码的 read_file 失败模板是 `read_file 失败：<路径>（原因）`（`src/provider/pi/tools.ts:446`；另一失败分支 `read_file: 缺少 path 参数` 不含路径）；git 全历史 `app/`、`src/` 无「read_file 执行失败：」产出；本机两条真实会话 JSONL 的失败形状也只有严格模板。「执行失败」实为状态**标签词**（tool-rows.js），该卡形状来自审计夹具的人造文本（`test/桌面应用/e2e/uiux-design-audit.mjs:53`），**不是产品会写出的形状**。对真实形状（含 S1 当初的旧 JSONL 无 details.path/callId 形态）：严格模板回填目标后，首行已含完整路径 ⇒ `appendDenied`（`renderer.js:831`）不再输出「目标未记录」；首行去重（`tool-rows.js:88`）后仅识别确定模板（「不从任意正文/stdout 猜目标」，工具名以外的词不参与失败判断）。独立回放用例「孤立 S1 首行回退」与 119 条内 S1 两条断言在最终候选上全过。**结论：S1 在上轮约定范围内闭合；A 图该卡仅作几何/视觉证据，不得引用为 S1 的行为证据，也不构成未决缺陷。**
