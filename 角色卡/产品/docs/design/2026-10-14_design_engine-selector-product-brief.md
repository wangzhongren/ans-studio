# 用统一的引擎选择器让用户明确选择当前会话引擎

用户导入项目后，需要一眼知道正在看哪个引擎，并能安心切到另一个。客户说现有下拉框“样式不对”，要求产品和 UI/UX 重新设计。本轮建议把角色名旁的引擎选择改成与 ANS 视觉系统一致的小触发器和三项弹出列表，完整保留现有会话行为。本记录是设计输入，不是业务代码实施授权。

## 依据与判断边界

- **代码事实**：`app/renderer/index.html:78–83` 当前是带“引擎”标签的原生 select，固定 Pi、Codex、Claude。`styles.css:476–478` 为 11px 标签、圆角 6px、最大宽 95px 的灰色边框控件。浏览器 select 的系统展开部分不能仅凭这段 CSS 推断具体观感。
- **代码事实**：`renderer.js:2554–2555` 未导入项目禁用；`selectRuntime:316–337` 保存旧草稿和阅读状态、按项目/引擎安装独立视图，重复选择当前值直接返回。配置缺项由 `renderRuntimeConfigNotice:1885–1893` 在主工作区显示，并给“打开 <当前引擎> 设置”。这些行为有用且必须保留。
- **只读契约**：[桌面引擎选择当前行为](../../../桌面UI/docs/feature/runtime-choice.md)说明切换只改变查看与下次发送目标，后台原引擎继续工作，消息/草稿/附件/待办/确认隔离。
- **产品判断**：三项固定短名称只需一个轻量选择控件。root的真实ANS观察经PM传回：展开为深色磨砂、亮蓝选中与白勾，触发器系统焦点出现双边框，与浅白/灰和olive-gray工作台失配；向上展开跨聊天头并暂盖缺配置条。观察生产者是root，产品未亲自打开用户ANS或查看截图原件；不能把它写成产品真机自验。问题属于视觉一致性，不证明业务切换损坏。工作树有在飞代码，引用的是本轮读取的工作树，不把 HEAD 的历史验收当当前候选证明。

## 推荐的最小方案

头部保留“引擎”标签，旁边单一触发器显示当前名称与向下箭头。点击在触发器附近展开三项列表：Pi、Codex、Claude；当前项带勾。列表不加入搜索、引擎图标、说明段落、配置编辑入口或额外确认。视觉尺寸、间距、边框、阴影与选中色由 UI/UX 定稿，产品只要求这些元素在同一体系内。

当前值和临时焦点是两种信息：当前项始终带勾，鼠标悬停或方向键移动仅突出待选行，不改变值；点击/Enter/Space 确认后收起并进入现有 selectRuntime 路径。再次确认当前项仅关闭，不重开会话。切到缺配置引擎仍成功显示该引擎，随后由既有主条准确说明缺项并打开对应设置；不能用禁用选项把恢复入口堵住，不能将“配置齐备”当作远程可用。

| 状态/动作 | 用户看到与得到的结果 |
| --- | --- |
| 未导入项目 | 当前名称留在头部、触发器禁用；鼠标和键盘都不打开，不伪装成可选 |
| 成功导入项目，包括空文件夹 | 三项可以选择；不因无角色而禁用引擎 |
| 打开列表 | 与触发器对齐，当前项带勾且获得初始活动位置 |
| ↑/↓、Home/End | 只移动活动位置；引擎和主工作区保持原样 |
| 点击项、Enter/Space | 提交选中一次，收起并回触发器；主区使用现有引擎切换流程 |
| Escape、点外部 | 取消临时选择，收起；Escape回触发器，外部点击不抢回外部目标焦点 |
| Tab/Shift+Tab | 不提交临时选择，关闭并按页面自然顺序离开，不陷入焦点循环 |
| 触发器重复点击、窗口失焦/尺寸变化 | 收起或重新定位；不遗留漂浮菜单，不意外提交 |
| 缺配置或读取失败 | 列表照常可选；保留主工作区既有缺项/失败文本与对应设置按钮 |
| 长名称与小窗口 | 触发器保持紧凑，视觉省略仍能获得全文；弹层不横溢，空间不足向上展开且必要时内部滚动 |

触发器可访问名称包含“会话引擎”及当前值，展开态程序化可读；列表与选项提供真实选中状态。必须能看见键盘焦点，不能只用色差证明已选。未导入禁用原因优先借现有导入项目空态表达，避免常驻第二份提示。

## 为什么选这一方案

继续原生 select 成本最低且键盘由平台提供，但不能保证展开列表与 ANS 的跨平台视觉统一。自绘列表能解决客户指出的失配，代价是桌面UI必须完整负责焦点、取消、视口与可访问语义。本轮只有三项固定集合，建议采用非可编辑选择语义，不引入搜索框或整个引擎管理面板。它是必要设计选择，不是默认勾选的选装。

## 实施后验收口径（待验证）

1. 打开前后视觉属于同一 ANS 灰色/圆角体系；1360与960宽画布头部角色名、描述和触发器清晰，没有异常换行或控件挤压。小于通常宽度时仍可访问三项。
2. 三项当前值、hover、键盘焦点、按压、禁用明确；键盘移动到别项后 Escape，名称/消息/草稿完全不变。
3. 未导入无法打开；导入空项目可以打开；选择当前项不产生新切换请求。
4. 选择缺配置引擎后主条留在原位置；“打开 Codex/Claude/Pi 设置”分别到正确抽屉，无需先选角色。
5. 选择不同引擎只调用既有切换流程一次；旧消息、队列、草稿、附件、确认和后台任务行为不回退。这是后续实现/独立回归要求，不把静态原型当运行时证明。
6. 键盘确认/取消/Tab完整路径、外部点击、视口上下翻转、长名全文、屏幕阅读器的标签/展开/选中语义均需实际验证。

## 联合评审与状态

首轮：已提交上述输入给 UI/UX 与项目管理；对UI/UX初步104×28触发器、160px列表、32px行建议，产品认为目标吻合。root真机观察经PM传回后，应用内列表相对仅native appearance的理由得到支持；菜单暂盖部分主区不是业务故障，不添加“绝不能覆盖缺配条”的硬约束。等待 UI/UX canonical 原型，第二轮只审查该版本是否满足目标，不扩充范围。PM负责综合评审与客户交付。产品只维护本角色文档，未改 app/src/test，未操作用户 ANS，未运行模型，也未做实施测试。


### 第二轮：产品推荐设计方向

**结论：recommend approval，限设计方向。** 没有剩余产品方向阻塞项。

实际读取的 canonical 是[UI/UX原型](../../../UIUX设计师/docs/design/2026-10-14_design_engine-selector-prototype.html)，最终本机 SHA-256 为 `aab42cf7c533027798bf50c26e05b4791ce1e3da69980b72773826e98eb10cd3`。产品只读HTML/JS并查看UI/UX生产者的四张1360/960图片：关闭缺配、展开浏览、960禁用、960展开缺配。没有操作原型浏览器或真实ANS；键盘动态结果仅来自UI/UX自验，经PM转述（PM未亲操键盘），不能写成产品亲测。

- 浅色列表、灰边与olive选中符合现有工作台；104×28触发器/160px弹层/32px行足够轻，不把选择升级成引擎配置或账号管理。
- 当前Claude勾与临时Codex高亮视觉分别表达。原型源码落实活动位置独立、方向键不提交、Escape/outside/Tab/window blur取消、点击/Enter/Space确认、窗口内夹取与上下翻转；这些是演示机制，不是生产系统行为验收。
- 产品第二轮提出的三项已实际核对闭合：动态可访问名称含当前值、设置按钮“打开 <引擎> 设置”、确认当前项仅close。没有把设计师认同当修完，读取了最终 `paint` 与 `commit`。
- 960禁用图没有菜单，960展开图三项和设置入口可见；菜单临时覆盖部分缺项文本可接受，关闭后恢复阅读。演示顶部操作、演示提示和正文不进入正式应用。

实施后仍须按上方六条验证实际renderer与引擎隔离；原型无IPC、后台事件或配置读写能力。屏幕阅读器软件、长名称压力、窗口极端高度未实际验证，应由实施验收如实覆盖，不作为本轮已有通过证据。没有新增选装或第三轮议题。PM综合评审与后续客户决定独立于本结论。
