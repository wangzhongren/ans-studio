# 推理与推理强度（G-5 设计提案）

一句话结论：给 ANS 补上**推理的两面**——①**请求面**：设置面板每平台新增一个「推理强度」字段（沿 `RUNTIME_SETTINGS` 元数据体格），统一语汇 **默认（不设置）/ 关 / 低 / 中 / 高**（「极」档列待评估回填），**未设＝逐字现状**（不发送任何推理参数、零行为变化），客户显式选档才下发各平台原生参数；②**呈现面**：思考内容以**折叠行**（「已思考 N 秒 ▸」，点击展开看原文，信息零丢失、视觉低调）进入聊天流——沿用工具行折叠的交互语法与状态机，但**运行中默认折叠**（与工具行默认展开的刻意差异，理由见 §5.2），**不并入工具组、不加 `[系统·]` 前缀**；③**失败面**：网关不支持推理参数时**不毁轮次**——有界恰一次「去参数重发」＋如实一行＋诊断（沿 G-4「会话照开、不毁轮次」先例）。三平台请求接线、档位映射、思考内容可达性**留占位标「待运行时核心评估回填」**（§3.1/§5.4/§七）。

本记录是**设计提案**，不是实施授权：**未实施、未测试**。本轮只读源码、SDK 类型面与证据文档并形成判断；没有改任何 `app/`、`src/`、`test/`、其他角色文件与证据目录，没有 git 提交，没有操作任何真实项目与轮次目录。涉及实施的部分须经客户确认文档后由项目管理派发属主角色；三平台机制细节以运行时核心并行评估为准（评估件落位后回填本提案对应占位）。

## 来源与动机（依据）

- 客户原话（PM 评审批次登记原文，逐字）：「**你这个需要支持推理，需要支持推理强度。**」（[PM 评审批次 §候选 G-5](../../../项目管理/docs/change/2026-10-15_change_kanban-fixes-pm-review.md)，2026-10-16）。
- PM 现状核（登记原文要点，本提案逐条对齐）：**Pi 路径**模型响应**已有 thinking 块**（G-3 探针实证——探针记录见 §1.3）但 ANS 观察面只取白名单字段 ⇒ **不呈现**；**Claude 路径** `queryOptions` **零 thinking 配置**（SDK 支持面未接线）；**Codex 路径**无 `model_reasoning_effort` 配置面（走 CLI 默认）；**设置面**（`RUNTIME_SETTINGS`）仅凭据/地址/模型/上下文窗口——**无推理强度字段**；`forceAdaptiveThinking:false`（Pi compat 收窄）为请求格式安全值，与「能否请求推理」待评估区分。
- PM 登记的三件配套（本文逐一对策）：①三平台推理请求接线——**机制面，本提案留占位**（§1.2/§3.1/§七），运行时核心并行评估回填；②推理强度档位（设置面板落位、档位语汇与默认口径）——§三/§四；③思考内容的聊天呈现（现状仅「正在思考」指示、无内容）——§五。
- PM 派发口径（登记原文）：「产品（设计提案：档位与默认、设置面落位、呈现形态、按角色覆写候选）＋运行时核心（跨平台机制评估：三 SDK 实据、配置注入面、事件面事实、探针清单——loopback 可决项与需客户真网关项分列）；经 PM 评审后呈客户批准。」
- 场景约束：客户单用户本机应用；客户此前反馈「聊天那块感觉太松散了」（视觉收敛 v3 焦点）、「正在思考，没有动画」（W9–W11 已以统一转轮回应）。**客户要的推理不是"把思考过程铺满聊天"**——是"能设强度、能看到它存在、想看时看得到"。本设计据此选形（§5.1）。

> 占位说明：本提案中凡标「**待运行时核心评估回填**」处，均为三平台机制细节（请求如何接线、档位如何映射、参数是否被网关接受、思考内容以何形态可达、错误如何识别）——写作时点只有 PM 现状核与 SDK 类型面可读，实测结论以运行时核心评估（在跑）为准，落位后按 G-4 §5.3 先例逐项回填、不改其事实。
>

### 1.3 思考内容呈现面现状（数据面/契约面/桌面面三层）

- **数据面**：Pi——模型响应**已有 thinking 块**（G-3 探针实证：响应 blocks 实测含 `thinking`，见[探针记录](<../../../Pi适配器/docs/fix/2026-10-16_probe_server-side-tools-live-results.md>) `:20` 等行），但适配器只经 `extractMessageText` 抽取 `text` 块（`real-adapter.ts:796-810`）、`message_end` 仅在有 text 时发事件（`:671-676`）——thinking 块**被整块丢弃、不发任何事件**；redacted thinking 同理（另有 `redacted_thinking` 块类型，内容不可读是平台设计）。Codex——`item/completed` 只映射 `agentMessage`/`webSearch`/`mcpToolCall` 三类（`src/provider/codex/session.ts:537-564`），推理类 item **完全不可见**。Claude——零接线，无来源。
- **契约面**：`SessionEvent.kind` 是**冻结集合**（`real-adapter.ts:680` 注释：上下文压缩事件「契约 §4 的 SessionEvent.kind 是冻结集合，故这里映射为 message，不新增 kind」）——思考内容要成为可呈现事实，事件面的扩展方式（新 kind vs 走核心投影单点 vs 映射进既有 kind）属**机制评估项**（§5.3 末）。
- **桌面面**：聊天流无推理行；推理期间唯一指示＝「正在工作」尾行（12px SVG 转轮＋原文案，W10 客户批准，`app/renderer/renderer.js:3082-3098`）与角色徽标转轮（W9–W11 统一图源，`app/renderer/role-status.js:53-59`）。**推理期与普通工作期无区分、零内容展示**（PM 现状核一致）。claude-api 面另注：Claude SDK 侧有 thinking 显示模式三态（§1.2 表），对呈现形态设计是直接输入（§5.4）。

### 1.4 呈现面可复用承载件（行体系既有先例）

- **工具行折叠状态机**（2026-10-16 客户批准口径，`app/renderer/renderer.js:954-1060`）：①运行中不折叠（live＋未 settled＋busy ⇒ 默认展开）；②轮结束（settled）折叠成一行「本轮 N 个调用：…」，**批尾落地**（不用计时器、防中间态错位）；③手动开合优先并在会话内保持（读过的人不被自动收起）、键盘焦点在组内不收；④折叠/展开走「先读锚点→改→实测→恢复」的**阅读锚点零位移**语义。折叠行文案口径＝信息零丢失（展开即逐条完整），计数口径单点在 `tool-rows.js`（`mergePhases`/`callSummary`，`app/renderer/tool-rows.js:106-169`）。
- **`system` 行口径**（G-2）：投递输入文首定格标记 `[系统·<子类>] `（子类≤12 字、闭合于 `]`），归类只依赖前缀特征、**不是"看起来像"的启发式**（`tool-rows.js:62-104` 注释即契约；`[系统·安装]` 冻结符号先例 `app/desktop/session.ts:552-558`）。**推理不是投递面消息**——此口径对推理行的含义是"**不加**系统前缀"（§5.3）。
- **核心投影单点**：工具事件行经核心单点投影（`projectToolEvent` 家族）到呈现层，适配器侧只产事实、不定样式——推理事件投影应沿此纪律（§5.3 末，机制评估项）。
- **适配器如实行先例**：截断收尾补发的一次性通知行「已自动补发一轮收尾提示（因上一轮输出被截断；限一次）」（`real-adapter.ts:824-827`）＋陈旧重建的如实行文案（`session.ts:941-949`）——降级/补发类事实的"一行如实"形态可直接照抄（§七）。
- **脱敏与预算链**：文本投影过 `protectText`（cleanPatterns A-base 收窄 2026-10-16）；大内容按核心预算裁剪并带 `omissions` 标记——推理内容若上屏，**同链同口径**（§5.2 纪律）。

### 1.5 客户品味裁判线（本提案的取舍标准）

- 客户口味五条（界面要干净 / 信息在对的上下文 / 常规提示不打扰 / 每样东西要有用 / 诚实呈现）＋近两轮显式反馈「聊天太松散」「正在思考没有动画（要有动效）」——**去噪、真实、可展开**是本轮三条硬尺子：默认不铺内容（去噪）、原文与降级一律如实（真实）、点击展开零丢失（可展开）。

## 二、设计总览

```
设置面                                    呈现面
客户在「<引擎> 设置」面板改「推理强度」
        │  （默认＝不设置；显式选 关/低/中/高）
        ▼
   .env（应用级；白名单校验同今天）       模型思考（平台原生）
        │                                      │
        ▼                                      ▼
   会话构造：值灌入进程环境              适配器观测面（Pi 块已实证存在）
        │                                      │
        ▼                                      ▼
   适配器按档位下发原生参数              核心投影单点（脱敏/预算）
   （未设 ⇒ 零参数＝逐字现状）               │
        │                                      ▼
        ▼                              聊天流「折叠行」：
   网关拒绝 ⇒ 有界一次去参数重发            「已思考 N 秒 ▸」（默认折叠）
   ＋如实一行＋诊断（不毁轮次）              展开＝原文纯文本（零丢失）
```

**一条原则**：推理是**可选增强**，不是判定链的一环——未设时逐字现状；设置坏值按未设处理；网关拒绝时降级不毁轮次（最坏情形＝没开启过这个功能）；呈现永远如实（有内容才显示内容、内容被平台省略就明说、时长只在有真实信号时显示）。**不新造行体系**：呈现复用工具行折叠的交互与状态机、不加 `[系统·]` 前缀、不并入工具组。

**非目标（V1 不做）**：客户未点名的一切——按项目维度的强度覆写（§四点名"按角色"为候选，项目/角色两级都只登记）；热生效（不重建会话即改推理参数）；思考内容的全文检索/导出；把推理强度选择自动化（如按任务复杂度自适应——那是"默认档＋平台自适应"的天然语义，不需要我们发明）；对 thinking 内容做摘要加工（Claude 平台的 summarized/highlights 是**平台呈现面**，可用即用，见 §5.4；我们不自行二次摘要）。

## 三、强度档位设计

### 3.1 统一语汇（推荐：默认（不设置）＋ 关/低/中/高；「极」档列待评估回填）

- **推荐语汇**：**默认（不设置）** / **关** / **低** / **中** / **高**——四档＋一默认态。理由：①与写作时点两平台 SDK 类型面天然对齐（Claude `low/medium/high`、Pi `low/medium/high` 的字面即档名，映射零转译成本）；②四档是客户记得住的粒度（客户原话只要"强度"，没要连续谱）；③「关」与「默认」**必须两分**（下条）。
- **「极」档（候选：收编 Claude `xhigh`/Pi `xhigh`/`max` 的更高层）**：SDK 类型面显示两平台均有比 high 更高的档（Claude `xhigh|max`、Pi `xhigh|max`）——**是否收编、收哪一层、Codex 是否有对应**，**待运行时核心评估回填**后随批文裁定（§十一-1）。倾向保留为「极」单项（客户真机成本敏感场景下它是显著不同的档；但三平台齐不齐、网关认不认须先有评估事实）。
- **「关」与「默认」的语义差（必须写进 help 文案）**：
  - **默认（不设置）**＝**不发送任何推理参数**——各平台走各自原生默认（可能本来就是"会思考"）。这是字段的初始态、也是"不改变既有行为"的保证。
  - **关**＝**显式请求"不要思考"**（Claude SDK 面有 `{type:'disabled'}`、Pi SDK 面有 `'off'`；Codex 是否有原生等价＝评估项）。客户要"快、省"时用「关」；客户没意见时留着「默认」。
- **档位映射表（待运行时核心评估回填）**：

| 统一档 | Claude（待回填） | Codex（待回填） | Pi（待回填） |
| --- | --- | --- | --- |
| 默认（不设置） | 零参数（逐字现状） | 零参数（逐字现状） | 零参数（逐字现状） |
| 关 | `thinking:{type:'disabled'}`（类型面已有；网关接受性待评估） | 待评估（无原生等价则本平台省略该档） | `thinkingLevel:'off'`（类型面已有） |
| 低 / 中 / 高 | `effort:'low'|'medium'|'high'`（类型面已有；老模型/网关回退路径待评估） | `model_reasoning_effort`（接线与枚举待评估） | `thinkingLevel:'low'|'medium'|'high'`（类型面已有） |
| 极（候选） | `xhigh`（`max` 是否并档待评估） | 待评估 | `xhigh`/`max`（待评估） |

- 映射表附注（诚实面）：**逐平台支持集可以不同**——某平台若无「关」的原生等价，该平台字段的候选集就**省略「关」**（宁少一档，不做假档）；某网关不支持某档时按 §七 降级链如实处理，不在设置面板里假装支持。

### 3.2 默认口径（推荐：未设＝逐字现状，客户显式选才生效）

- 三条理由：①**不改变既有行为**是仓库纪律（对照 Pi compat 收窄、G-3「默认关＋开关开启」先例）——今天所有会话不带任何推理参数，默认态必须逐字保持；②**零新增失败面**——不发送参数就绝不会因参数被网关拒绝（§七失败面只属于"客户主动开了"的场景）；③语义正确——客户原话是"**需要支持**推理强度"＝"给我这个能力"，不是"给我打开它"；显式选档＝客户明示意图，沿用产品一贯的「未注入即不注册/未开启即缺席」fail-closed 姿态。
- 面板文案义务：help 行按体格写「**留空＝不发送推理参数（平台默认）；可选：关 / 低 / 中 / 高。**」（支持集按评估回填逐平台微调）——把"默认不是什么"说破，避免客户以为留空＝关。

### 3.3 落位：每平台一字段 vs 全局单字段（推荐：**每平台一字段**）

| 维度 | A 每平台一字段（推荐） | B 全局单字段跨平台 |
| --- | --- | --- |
| 机制 | 沿 `RUNTIME_SETTINGS` 体格直接增补三处 `fields` 条目；保存白名单/校验/生效链**零新机制**（§1.1） | 需要"跨平台共享值"新概念：或在三个运行时的 fields 里放同一 key（面板仍出现三处、保存语义要特判来源），或新建一套全局设置面（机制新增） |
| 面板观感 | 设置面板**本就按引擎打开**（按钮文案「打开 <引擎> 设置」）——客户每次只看一个字段，无重复感 | 表面"设一次全平台"，但只有平台能力集相同时才诚实 |
| 诚实面 | help 按平台写支持集；不支持的值按平台拒绝/省略——**每个平台可以说自己的实话** | 一个值跨平台 ⇒ 无法表达"这台网关不支持"：要么静默近似（违约诚实），要么全局降级（一个平台的限制拖累其他平台） |
| 值面差异 | 三平台原生档位/语义/失败面各不相同（§3.1 映射表占位）——存储分开、**UI 语汇统一**即可 | 全局值的可用档＝三平台支持集的**交集**——最难的一档决定全局上限 |
| 先例 | 与「模型」字段完全同构（`ANS_PI_MODEL`/`ANS_CODEX_MODEL`/`ANS_CLAUDE_MODEL` 三键三名，同一概念分平台） | 无先例；引入与 per-runtime registry 体格冲突的新概念 |

- **推荐 A**。关键洞察：这不是"让客户设置三次"——客户在哪个引擎聊天，就只在那个引擎的面板里看见这一个字段；统一语汇（同名同档位字面）保证跨平台心智一致，存储分开保证每平台可以如实。
- 若未来出现"我要一键把三个引擎都调高"的真实诉求：候选＝面板上不做、登记（跨平台批量本来就 3 次点击内完成）。

### 3.4 字段元数据与控件（草案）

```text
runtime-settings.ts 增补（形状沿体格；key 命名待裁 §十一-10）：
claude:  { key: "ANS_CLAUDE_<推理强度>",   label: "推理强度", required: false, secret: false, help: "留空＝不发送推理参数（平台默认）；可选：关 / 低 / 中 / 高。" }
codex:   { key: "ANS_CODEX_<推理强度>",    label: "推理强度", required: false, secret: false, help: "同上（支持集按评估回填）。" }
pi:      { key: "ANS_PI_<推理强度>",       label: "推理强度", required: false, secret: false, help: "同上（支持集按评估回填）。" }
```

- `required: false` 的连带影响：**不算"配置不全"**——`missingKeys`/「必填配置已齐备」判据逐字不变（对照 `ANS_PI_CONTEXT_WINDOW` 先例 `renderer.js:2546-2551, 2610-2617`）。
- **控件**：现值面板所有字段统一渲染为文本输入框（`renderer.js:2582-2588`）。枚举档位建议**下拉/分段选择**而非自由文本——需要元数据小扩展（候选：`RuntimeSettingField.choices?: readonly string[]`，保存侧按 choices 校验、拒绝未知值——沿 URL 键校验先例 `runtime-config.ts:108-115`）。若评估轮裁定不动元数据，次选＝文本输入＋保存校验＋help 写明合法值（可用但客户手误面大）。**控件终形归桌面UI/项目管理定**（§九 I1/I3），本提案只钉"可选值集必须唯一来源、面板显示的合法值＝保存接受的合法值＝适配器认识的合法值"。
- **面板位置**：推荐**主字段区**（客户点名要的功能不进「高级」区——高级区先例是上下文窗口这种"大多数人不碰的旋钮"）；小裁点见 §十一-4。
- **分期诚实**：若实施分批（如 G-4 的 P1/P2/P3 平台分批），**未接线平台的字段不注册**（沿「未注入即不注册」精神）——绝不出现"设了没用的字段"（诚实呈现）。

## 四、按角色覆写（候选，登记不承诺）

- 客户原话只到"支持推理强度"——按角色覆写**不是客户点名**，本节按要求登记候选与落点预判，**不预设、不承诺**。
- 粒度事实：现设置面是**应用级 .env**（§1.1 末行）——即粒度矩阵现有两级＝「应用 × 引擎」；「项目 × 引擎」「角色 × 引擎」两级**都不存在**。
- 候选（登记；与 G-4 安装工具面**无关**——配置面属设置链，不经 su 工具、不加预授权、不动卡文本）：

| 候选 | 落点 | 预判 |
| --- | --- | --- |
| A `.ans/project.json` roles 条目扩展（如 `"roles": {"实现者": {…, "<强度字段>": "high"}}`） | 项目内、按角色、机器可读；已在项目枚举/角色解析读盘路径上 | 最顺的读取点，但该文件承载 pin/验收语义，**偏好混入治理文件**须先行评估；写面（谁写、走不走确认）须设计——不预设 |
| B 新项目内配置文件（如 `.ans/settings.json` 或 `角色卡/<role>/settings.*`） | 项目内、按角色 | 语义干净（专文件专事），但＝**新写面＋新边界条目＋新读取器**——成本最大，仅当客户明确要时才值得 |
| C 角色卡 frontmatter | `角色卡/<role>/role-card.md` 头部 | **不推荐**——G-4 已论证角色卡是身份文档、不宜承载高频可变配置；且它是系统提示源，塞进配置会让身份与偏好混淆 |
| D（推荐口径）**V1 不做**，仅登记 | — | 客户未点名；现状"应用级"已覆盖绝大多数场景（单用户本机）；若客户后续要，按 A/B/C 评估轮再裁 |

- 落点预判（若未来做）：**读取点必须在会话构造**（角色解析/`prepareRuntimeProfile` 同侧），才能继承「新会话生效＋settle 收敛＋在跑不打断」的既有链（§六）；优先级＝角色显式值 > 应用级 .env > 未设（与 `fallbackKeys` 的"文件 > 环境"收纳顺序同构，不发明新顺序）。

## 五、推理呈现设计

### 5.1 三候选对比与推荐（推荐 **②折叠行**）

| 候选 | 形态 | 评价 |
| --- | --- | --- |
| ① 维持现状 | 仅「正在工作」转轮指示，零内容 | **不满足**客户点名——"支持推理"若永远看不见推理，客户无从确认它工作了；调试/信任价值为零。否决 |
| ② **折叠行**（推荐） | 「已思考 N 秒 ▸」一行；点击展开＝推理原文；默认低调、轮结束定型 | **去噪**（默认不铺内容、行高一行）＋**真实**（原文照录、内容被平台省略就明说）＋**可展开**（信息零丢失）——与客户口味五条逐条对齐；复用工具行折叠机制＝实现成本最低的先例路径。推荐 |
| ③ 完整呈现 | 思考原文直接铺进聊天流（流式全文可见） | 与「聊天太松散」的既有投诉**方向相反**；长思考（数千字）会冲垮阅读节奏；客户想细看时②展开同样满足。否决 |

- 推荐②的"客户品味"论证：客户前一轮刚要求「正在思考，没有动画」→ 已用转轮回应了"**存在感**"；本轮要的是"**内容可看**"。②恰好是"存在感＋内容"的最小组件——默认态只比今天多一行（甚至可与尾行视觉同族、显性度极低），想看的人一步展开。

### 5.2 折叠行形态定格草案（产品面契约）

- **折叠态文案**：
  - 有真实时长信号：「**已思考 N 秒 ▸**」（N 从推理起止的真实信号算——写作时点各平台信号可得性待评估，§5.4）；
  - 无时长信号：「**推理内容 ▸**」（**不发明时间**——没有真实起止就不显示秒数，沿诚实纪律）；
  - 一段轮次多段推理（agentic 轮内工具调用之间的多段）：V1 逐段各一行、序位如实（不合并）；「轮结束收成一行『本轮推理 N 段（共 M 秒）▸』」为**候选增强**（沿工具行"轮结束折叠成一行"的语法，§十一-6 待裁）。
- **展开态**：
  - 内容＝**原文纯文本**呈现（pre-wrap、等宽或正文同款均可，**不做 markdown 渲染美化**——它是思考过程不是正式回复，视觉层级应低于助手正文，防"看起来像正式输出"）；行样式走次要视觉层（与工具行同族、弱于正文）。
  - 脱敏/预算**同链**：过 `protectText`；超预算按核心预算裁并带如实标记（§1.4）。
- **平台内容不可得时的如实形态**（宁少不装）：平台只给"思考发生过"不给内容（如 Claude `omitted`/redacted 块）⇒ 折叠行显示「**已思考（内容由平台省略）**」类如实文案；只给摘要/标题（Claude `summarized`/`highlights`）⇒ 展开态显示平台给什么就是什么——**绝不拿摘要冒充原文、绝不拿"发生"冒充"内容"**（文案逐平台定稿，§5.4）。
- **生命周期（推荐口径；与工具行折叠的异同都写明）**：
  - **运行中默认折叠**——这是与工具行"运行中默认展开"的**刻意差异**，理由：工具行的运行中展开展示的是**状态词＋短目标**（140 字上限、稀疏、每行一条），是"看得见工作在发生"；推理内容是**长文本**，运行中就铺＝与去噪目标相悖；且尾行转轮已在表达"进行中"。折叠行运行中实时更新「思考中… N 秒」（有信号时）。
  - **手动开合优先并在会话内保持**（读过的人不被自动收起）、**键盘焦点在行内不自动收回**——逐字复用工具行状态机三规则中的后两条（`renderer.js:958-960`）。
  - **轮结束（settled）定型**：折叠行文案从「思考中…」定格为「已思考 N 秒」；**批尾落地**（`flushDeferredFolds` 同款——不用计时器、防中间态错位，`renderer.js:981-999`）；阅读锚点零位移语义逐字复用。
  - 回放/恢复出的历史行：静态呈现（与工具行"回放默认折叠"同判据），时长取自存档事实、无存档则无时长文案（不猜测）。
- **重试/压缩等边界**：截断补发、上下文压缩、参数降级重试等系统动作**不吞行**——推理行数与内容以实际发生的量如实呈现（压缩导致内容截断时按预算标记，不给假完整）。

### 5.3 与既有行体系合流（三处接口，逐一钉死）

1. **与工具行折叠**：复用**同一套**开合机制（details/summary 语义、manualOpen 优先级、焦点保护、锚点恢复、批尾折叠）；**不进工具组**——工具组语义是"本轮 N 个调用：工具分解"（`callSummary` 按调用行计数），推理不是工具调用，混入会污染计数口径；推理行在组外独立成行、位于真实序位。
2. **与 `system` 行**：**不加 `[系统·]` 前缀**——该前缀是投递面定格标记（归类判据在原文上、带来源语义），推理是模型输出不是系统投递；推理行归属助手输出面（同 `message` 家族的行）。
3. **与核心投影单点/契约面**：行**不新造体系**——呈现事实经核心投影单点（沿 `projectToolEvent` 纪律：适配器只产事实、核心做脱敏预算、呈现层只渲染）。**事件面怎么扩展**（`SessionEvent.kind` 是冻结集合，§1.3；是加新 kind、还是走核心事实投影族的新 member、还是映射进既有 kind＋结构化 detail）属**待运行时核心评估回填**的机制项——本提案只钉产品契约：*折叠行需要的事实＝{该轮身份, 段落序位, 起止（可缺）, 内容形态（原文|摘要|仅发生）, 内容文本（可缺）, 预算/脱敏标记}*，形态载体留给评估与实施轮冻结。
4. **与尾行「正在工作」的关系**：尾行职责不变（进行中指示、转轮动效）；推理行是**内容面**——两者互补不重复措辞（推理行运行中若有文案用「思考中… N 秒」，不与尾行"正在工作"逐字重复；桌面UI 终稿时二选一侧重即可，不新增第二枚转轮/第二套图标——沿 W9–W11「全应用唯一转轮」纪律）。

### 5.4 三平台内容可达性与呈现形态（**待运行时核心评估回填**）

| 平台 | 已知输入（写作时点） | 评估要定格的事（回填位） |
| --- | --- | --- |
| Pi | 响应含 thinking 块（G-3 探针实证）；现被 `extractMessageText` 白名单丢弃；SDK 有 `thinkingLevel`/显示概念未见 | 块到事件的投影路径；原文可得性与流式时序（运行中能否实时见增量）；redacted 块形态；时长信号（起止事件时戳） |
| Claude | SDK 助手消息含 thinking 块；显示模式 `summarized/omitted/highlights`（第三方端点可能被拒、拒后该会话改 'omitted'） | 本网关下实际显示形态（summarized？omitted？）；与 `effort`/`thinking` 配置的组合面；时长信号 |
| Codex | `item/completed` 现有映射不含推理 item；推理 item 形状未见 | 推理 item 是否存在/形状（status/内容/时长字段）；模型面下发形态；网关接受性（与 G-4 V2「真机网关前置」同域） |

- 回填纪律（沿 G-4 §5.3）：定格事实逐字取用评估/探针记录；呈现形态表与 §5.2 的"平台内容不可得"分支按回填结果逐平台定稿（哪些平台首期能有原文、哪些首期只有"仅发生"形态、哪些首期不接）。

## 六、生效语义（如实口径）

- **保存**＝写应用级 `.env`（**即刻落文件**）＋界面如实显示应用时点（既有 `applicationLabel` 三态文案逐字复用：「当前配置已应用」/「下一次开启会话时应用」/「当前轮次继续使用原配置；结束后下一次输入应用新配置」）。**不发明第四种文案**。
- **生效**（沿既有设置链，逐条如实——比 G-4 的"下次开会话生效"更精确的现状是）：
  1. **新会话**：构造时读取新值（`prepareRuntimeProfile` → `applyRuntimeConfig` → 适配器工厂决策参数），即刻按新档位下发；
  2. **已开且空闲的会话**：在既有 O-1 陈旧检查（`changed="运行时配置"` 分支）**无卡作废重建**——settle 后/下次发言/下次投递时收敛，**无需客户手动重建**；重建走既有如实行（"该角色边界已更新或运行时配置已保存（运行时配置）……"）；
  3. **在跑轮次**：**不打断**——该轮继续用原配置，轮次结束后的既有检查点收敛（Pi 忙碌时有专门如实句：新配置在其结束后应用）；
  4. **续接命中的 stale note**：「当前轮次继续使用原配置，新配置在轮次结束后应用。」逐字照旧。
- **粒度如实**：设置是「这台机器 × 这个引擎」（应用级 .env）——**不是**"这个项目"、**不是**"这个角色"（§一 末行事实）；面板 hint 恒显同一句（"只修改本引擎字段"），不需要新文案。
- **热生效**（不重建会话、下一轮直接换档）：**不承诺**（登记候选，§十一-8）——与既有"配置变更走重建"的语义保持一致，避免为推理参数发明第二套生效路径。
- **手编 .env 的坏值/未知档**：保存入口已挡（choices 校验，§3.4）；绕过面板直编文件出现的未知值 ⇒ 该键**按未设处理**（零参数、零行为变化）＋一次性如实诊断——**绝不因偏好值坏件拒开会话或毁轮次**（偏好不是承载件；对照 G-4「坏件跳过不崩会话」先例）。候选：首次开会话在聊天流轻提示一行（可裁，§十一-9）。

## 七、失败面（不毁轮次，沿 G-4 先例）与降级设计

**沿用先例**：G-4 §八「MCP server 起不来 ⇒ 会话照开、工具缺席、如实类别一行、不毁会话轮次」；本节的推理参数属"客户主动开启的请求面增强"——失败面必须**只降不杀**。

| 失败 | 检出点 | 行为（口径） |
| --- | --- | --- |
| 设置值非法/未知档（绕过面板直编） | 会话构造读取处 | 按未设处理（零参数）＋如实诊断；不拒开会话、不毁轮次（§六） |
| 网关拒绝所设推理参数（整请求级拒绝） | 首请求响应（产出任何内容前） | **有界降级重试**：去掉该参数、其余逐字不变，**恰一次**重发；成功 ⇒ 本轮继续＋**如实一行**（沿截断补发通知行形态，§1.4）如「本网关不支持所设推理强度，本轮已按默认执行」＋诊断事件；仍失败 ⇒ 按既有失败口径如实收场（不假装成功） |
| 模型不认识档位但网关不回绝（静默近似/忽略） | 无检出（平台特性） | 无行为变化；呈现面按"实际有没有思考内容"如实显示（有则显示、无则没有——不给"已开启"的假承诺） |
| 思考内容不可达/被平台省略 | 呈现投影 | 折叠行按 §5.2 不可得分支如实（"内容由平台省略"）；**不因内容缺席毁轮次** |
| 重试面误触发（把普通网关错误误判为参数问题） | 降级识别判据 | **保守优先**：识别判据（哪些错误算"参数导致"）**待运行时核心评估**＋loopback/真网关探针分列（§十一-9）；不可识别 ⇒ **不重试**、按既有失败口径走（宁可少见降级行，也不多发一次请求） |
| 降级链与截断补发的叠加 | 同一轮内两机制同时触发 | 各自的有界计数独立、互不放大（各恰一次）；两行如实各报（文案不合并） |

- 纪律三条：**绝不静默**（降级必须有一行如实＋诊断）；**绝不循环**（重试有界恰一次）；**绝不改判定**（降级只发生在适配器请求面——不动任何门禁/边界/投递语义）。

## 八、与既有机制的衔接

1. **G-4（能力安装）**：生效语义（重建/在跑不打断/settle 收敛）、失败面（不毁轮次）、如实行形态、诚实面口径——四处先例直接沿用；「未注入即不注册」精神的两处借用＝未接线平台字段不注册（§3.4）、未设零参数（§3.2）。

3. **工具行折叠批（2026-10-16 客户批准）**：开合状态机/焦点保护/锚点恢复/批尾落地/折叠行文案纪律全套复用（§5.3-1）；本提案不改其任何既有语义。

## 十、测试/验收思路（含真机断点观测项）与风险

**单测（离线；供实施轮与独立验证轮参考，本轮未做）**

- 设置：字段元数据（required:false 不改 missingKeys 判据）；保存白名单（未知键丢弃照旧）；choices 校验（非法值拒绝文案）；来源五态显示不受影响。
- 映射：各档位→原生参数的映射表逐档断言（未设 ⇒ **零参数**——对照组回归钉子，防"默认态也发参数"的偷跑）；未知值按未设＋诊断。
- 降级：参数拒绝→去参数重发恰一次→成功续轮＋如实一行；不可识别错误→不重试；重试仍失败→既有失败口径；降级链与截断补发叠加不放大。
- 呈现：折叠行默认态（运行中折叠/轮结束定型）；手动开合优先；内容不可得分支文案；脱敏/预算标记透传。
- 回归：未设状态全链逐字现状（无参数、无新行、无新文案）；工具行折叠/system 行/`[系统·]` 归类既有测试逐字不动。

**真机 E2E 断点观测项（绝对路径 OUTDIR）**

1. **改档-生效链**：面板改「高」→ 保存 → 开新会话（断点：会话构造取值）→ 请求含原生参数（断点：适配器请求面/网关可辨）；在跑轮次不打断＋settle 收敛（断点：重建如实行）。
2. **默认零参数**：未设状态开新会话 → 请求与今天逐字一致（对照组；防回归）。
3. **呈现全链**：触发一轮有思考的对话 → 折叠行「已思考 N 秒 ▸」→ 点击展开见原文（或平台回填后的如实形态）→ 轮结束定型、焦点/锚点行为同工具行。
4. **降级**：指向不支持参数的 loopback/测试网关 → 轮次完成（不毁）＋如实一行＋诊断事件；未见静默降级。
5. **零泄漏/零误伤**：推理行内容抽查明文不含凭据；未开推理的角色会话逐字无变化。

**风险**

- **网关拒绝误伤轮次**（主风险）：若识别/重试链有缺陷，最坏＝轮次被参数问题杀死。缓解＝降级链（§七）＋保守识别（宁不重试）＋"未设零参数"默认态意味着**不开启该功能就零风险**。
- **档位语汇与实践漂移**：三平台原生档位异步演进（新档出现/枚举改名）——缓解＝映射表单点（适配器侧）、未识别值按未设＋诊断、评估轮定期重核。
- **呈现形态过度承诺**：平台内容可达性差异大（原文/摘要/仅发生），若统一按"原文"设计会翻车——缓解＝§5.4 逐平台定格＋不可得分支先行。
- **多段行噪音**：agentic 轮多段推理逐段成行可能显吵——缓解＝候选聚合（§十一-6）；不预设，先用真实轮次观察。
- **面板自证失真**：help 声称的支持集若与评估结论不一致＝对客户说谎——缓解＝I1 支持集文案随评估回填、验证项含逐平台对照。

## 十一、未决点清单（供 PM 评审与客户裁定）

1. **档位语汇与「极」档**（§3.1）：推荐「默认/关/低/中/高」；「极」档收不收、收哪一层、Codex 有无对应——**待运行时核心评估回填**后裁定。

4. **「关」的表达与省略**（§3.1/§3.4）：Codex 无原生「关」时该平台省略该档 vs 近似映射——**待评估**；面板位置（主区 vs 高级区）小裁。
5. **按角色覆写**（§四）：登记不承诺（推荐 D）；若客户明确要，A/B/C 评估轮再裁。

8. **热生效**（§六）：不承诺（推荐）；是否登记为后续候选。
9. **降级识别判据与重试界**（§七）：**待运行时核心评估**（loopback 可决项与真网关项分列）；保守触发面为默认口径。
10. **命名**（§3.4）：三平台 env 键名、面板标签（「推理强度」）、行文案（「已思考 N 秒」）——待点名或改名。
11. **三平台机制回填**（§1.2/§3.1/§5.4/§七）：请求接线、档位映射、内容可达性、错误识别——**待运行时核心评估**（本提案全部占位处汇总于此）。
