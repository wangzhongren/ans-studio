# 建立运行时接入组

客户已确认把运行时核心、Pi适配器、Codex适配器和Claude适配器纳入同一协作组，并明确指示“可以的，你新建角色吧，然后开发吧”。本次由固定身份的 ANS Governance 上下文建立治理产物；应用代码交给各角色的独立上下文实现。

新增运行时核心、Codex适配器、Claude适配器三个角色；保留Pi适配器并登记为组员。运行时核心承担组长的契约和技术对接职责，项目管理承担项目级授权、安排及验收。组别是角色卡的普通文档元数据，写权仍来自每个角色的 boundary.yaml；组内权限不合并。

新增角色的公共源码逐文件登记，私有辅助代码与专属测试按各自有界目录登记。现有公共代码的归属迁移、消费方修改和新增精确文件由对接设计明确后再更新边界；任何成员均不得直接改其他成员的私有代码。

项目管理角色卡同步澄清本次客户已授权的独立上下文派发：有 task_ops 时遵循它的协调协议；未启用时遵循技能明确支持的同等核对路径，不创建伪造授权或手写全局审计记录。

按项目管理 ANS-RUNTIME-V2 revision 1 的具体文件核对，桌面窗口新增精确测试路径 `test/桌面应用/multi-runtime.test.ts`，桌面UI新增精确测试路径 `test/桌面应用/runtime-ui.test.ts`。两者仅验证本次多引擎的接线、会话隔离、设置和组展示；现有 app 源码边界保持，测试路径各自独立归属。

Pi适配器角色卡同步职责迁移：专属 SDK 注册、事件与原生会话由 Pi 维护；中立契约和公共工具由运行时核心维护，Pi 仅保留旧路径的兼容入口。本次没有改变 Pi 文件边界，也不授予 Pi 修改核心文件的权限。

Pi迁移完成后，boundary.yaml 与 boundary.md 将 `src/provider/pi/tools.ts` 的用途同步为旧公开路径兼容转出，符合实际源码；文件属主和可写路径不变。

装配回归发现新增桌面测试条目置顶会改变既有“首个项目文件”展示示例。Governance 将两个新增测试条目移动到各自现有测试条目之后，保留 `app/main.ts` 与 `app/renderer/` 的原始首项顺序；白名单集合和权限完全相同。

桌面窗口与桌面UI的 boundary.md 人类可读镜像同步登记上述两个精确测试路径，顺序与唯一生效的 boundary.yaml 一致；窗口目录描述不再写死模块数量。此同步不产生额外权限。

治理产物已验证：生产 `listProject` 枚举到运行时核心、Pi、Codex、Claude 四个成员，组别均为运行时接入组，组内职责分别为一个组长、三个组员，warnings 为空。早期候选源码归属检查覆盖 53 个已跟踪变更路径和 107 个新增路径；桌面交付后的检查覆盖 93 个已跟踪变更路径和 144 个新增路径，所有 src/app/test 文件各匹配一个有效角色，无遗漏或重叠。

桌面窗口、桌面UI与Pi适配器的 Markdown/YAML 白名单镜像路径集合一致。只读归档 `角色卡/桌面应用/`、vendored renderer 库与真实 `.env` 没有修改；HEAD 保持初始基线，未自动提交。上述计数记录本次检查时的候选，后续测试角色只能增加自己已接受目录内的测试及证据。

这些检查验证角色定义和文件归属，应用实现和整体集成验证仍由项目管理依据各角色原始证据汇总。

独立集成测试补齐后的治理核对覆盖 93 个已跟踪变更路径和 183 个新增路径，其中 105 个 src/app/test 文件各有且仅有一个有效角色属主，镜像一致、实际组枚举无警告、保护路径和 HEAD 均未改变。三个新增角色卡的功能导航删除建立时的“未实施”临时状态，改为指向本角色证据及项目管理验收记录；组别、职责与写入权限不变。该核对不代替正在修复的桌面同轮历史/实时消息合并问题的产品验收。

桌面修复形成候选后的核对覆盖 97 个已跟踪变更路径和 216 个新增路径，108 个 src/app/test 文件全部唯一归属。Core 的只读 onTurnStarted 生命周期通知、Window 的原消息显示关联和 UI 的 history/live 合并均位于既有属主的已接受路径，不新增权限；公共 Model/Service 仅由 Core 修改，发送选项沿已有 Pipeline 契约透传。实际组枚举仍为一个组长、三个组员且 warnings 为空；三份白名单镜像一致，保护路径、真实 .env 的大小及时间戳、HEAD 均保持，git diff --check 通过。当前产品候选交固定测试角色最终独立复测；本记录只确认治理边界。

最终独立验证后再次核对：99 个已跟踪变更路径、301 个新增路径中，110 个 src/app/test 文件全部只有一个有效角色属主；四成员组及一个组长、三个组员的职责枚举正确，warnings 为空。归档、vendor、真实 .env 与 HEAD 保持，测试角色已清理本次生成的 Electron user-data 缓存，保留报告、截图、指纹及原失败证据。Governance 逐份复算 current-main 指纹中的 107 份生产文件，与最终实际入口候选完全一致；实际入口23项全部通过、无errors且起止不变。全仓原日志为1226项、1225通过、0失败、1既有Windows跳过，类型及diff检查通过。产品结论以[固定测试角色的最终报告](../../../测试/docs/change/2026-10-14_change_multi-runtime-independent-verification.md)和[项目管理验收](../../../项目管理/docs/change/2026-10-14_change_multi-runtime-integration.md)为准；这里只回交最终治理核对，无真实账户或在线模型验收声明。
