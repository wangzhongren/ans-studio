## overlay-2（首跑 CI 失败后追加）

首跑 CI run `39389502551` 三平台均在 **Regression tests** 阶段失败。属主修复（未提交）后，装配按**精确路径**纳入 5 条（单文件、不开目录）：

- **生产（唯一）**：`src/common/编排/shell-command-guard.ts` —— Windows 盘符/UNC 路径反斜杠被当 POSIX 转义消费，`grep -r foo D:\...\source` 漏判 allow；修复为 Windows 绝对路径按分隔符保留、双引号内仅 POSIX 特殊字符转义、`isWidePath` 用 `path.win32` 归一比较。
- **测试/夹具 4 条（断言不放宽）**：
  - `test/编排/shell-command-guard.test.ts` —— 平台无关 Windows 路径回归；
  - `test/编排/flow-service.test.ts` —— 原子写失败用例 Windows 平台真值分支（POSIX 目录 `0o500`；win32 目标文件 `0o444` 只读 + rename 失败）；

  - `test/桌面应用/runtime-resolution.test.ts` —— mac arm64 teardown `ENOTEMPTY`，临时目录清理有界重试，产品零改。

**后续已复跑通过**：最终 CI run `39393657089` 三平台 build + release 全绿（见「发布结果」）；本段记录的是当时的本地验证与临时 clone 预演。属主记录见 `角色卡/编排/docs/change/2026-10-20_change_v1.4.0-ci-windows-guard-atomic-write.md` 与 `角色卡/桌面应用/docs/change/2026-10-20_change_ci-test-races.md`（文档面，overlay excluded）。详见[overlay-2 上下文](2026-10-20-release-packaging-v1.4-evidence/overlay-2-context.md)。

## overlay-3（第二轮 CI Windows 负载敏感夹具超时）

第二轮 CI run `39391972925` 仅 Windows job 新红一条：`test/装配/multi-runtime.test.ts:154`「actual bin missing SDK errors are honest and masked without starting model requests」，10.5s 后 `actual signal 'SIGTERM' / expected null`。该用例对 codex 的 `spawnSync` 使用 `timeout: 10000`；Windows 原生 runner 本次 codex 启动/模块解析在负载下超过 10s，被夹具自身超时杀掉，并非产品错误（同文件 mac arm64 2.7s、mac x64 3.9s 通过；首轮 Windows 未红）。

- **仅改测试夹具**：新增平台常量 `SPAWN_TIMEOUT_MS = process.platform === "win32" ? 30_000 : 10_000`；同文件 4 处 `spawnSync`（missing-config 默认 runtime、SDK lazy import/help/doctor、missing SDK）统一使用。超时仍是**有界上界**，真挂起照限失败，未取消超时。
- **断言未放宽**：signal null / status 1 / 错误文案 / 密钥不泄漏等全部逐字保留。
- **无需新增 policy 路径**：`test/装配/` 已在目录白名单内；selected 由 11 增至 **12**（新增 `test/装配/multi-runtime.test.ts`）。
- **后续已复跑通过**：最终 CI run `39393657089` 三平台 build + release 全绿（见「发布结果」）。详见[overlay-3 上下文](2026-10-20-release-packaging-v1.4-evidence/overlay-3-context.md)。
