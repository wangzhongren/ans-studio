## 追加（2026-10-16，发布前 CI 检查）：Windows 平台测试小修纳入 overlay（selected 7 → 8）

**红因**：发布前 CI 回归在 Windows 平台发现 `test/runtime-core/shell-exec-timeout.test.ts` 有 3 条断言（两处期望 `signal === "SIGTERM"`、一处期望 `SIGKILL`）假定 Unix 信号名语义，Windows 下不成立而失败——**产品行为无缺陷**。该文件属**运行时核心**角色边界，其平台自适应小修由该角色并行实施（本角色未改该文件，仅只读参考）。

**问题（为何必须动 policy）**：本批 overlay 白名单收敛为精确集合后，构建树＝冻结 tag ＋ selected 差值补丁。`test/runtime-core/**` 不在白名单，且既不触发 `app/`·`src/` 的 fail-closed、也不命中 files/directories——会被 `selectOverlay` **静默放入 excluded**，构建树沿用 tag 内旧断言 ⇒ Windows CI 必然再红。改前复算已实证：把该文件并入输入 → 落入 excluded。

**决定与依据**：按 v1.0.0 时期既有做法（当时 overlay 清单本就包含多个 `test/*` 文件），把该**经评审的具体测试文件**精确加入 `files` 集合（`src/common/装配/release-policy.mjs`）：**单文件路径、不开目录**——`test/runtime-core/` 其余文件与其余未评审测试依旧 excluded，最小授权不变；纳入缘由以注释随 policy 落盘。fail-closed 守卫与反例测试**未动**（抽检 `app/main.ts`、`src/provider/runtime/tools.ts` 仍被明确拒绝）。

**复算（输入＝`git -c core.quotePath=false diff --name-only v1.1.0 HEAD`；Node v24.14.0 / macOS arm64）**：本记录收尾时，运行时核心小修**已落入工作区（未提交）**。① 该命令（仅已提交面）输出 **21 文件 → selected 7**（原集合；小修未提交、尚不在差集中）。② 以 **`git -c core.quotePath=false diff --name-only v1.1.0`（tag 对工作区＝overlay 提交落地后的形态）**复算，输出 25 文件 → **selected 恰为 8**：`.github/workflows/release.yml`、`package-lock.json`、`package.json`、`src/common/装配/release-policy.d.mts`、`src/common/装配/release-policy.mjs`、`src/common/装配/release-prepare.mjs`、`test/runtime-core/shell-exec-timeout.test.ts`、`test/装配/release-packaging.test.ts`；excluded 17 项**全为文档/角色卡面**（README、`角色卡/装配/**` 13 项、`角色卡/运行时核心/**` 3 篇），无一产品文件。改前对照（旧 policy）：该文件落入 excluded——正是 Windows 必红路径。

**验证**：`node --test "test/装配/**/*.test.ts"` **71/71 通过、0 失败**（新增 1 例锁定「该文件按精确路径入选、同目录其余文件与 codex-adapter 未评审测试仍 excluded」；原 70 例断言未放松）；`npm run typecheck` **退出 0**（末次复跑已含运行时核心小修的工作区状态）。
