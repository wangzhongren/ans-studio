# Q-1 热路径治理 + Q-2 聊天流虚拟渲染

**来源**：客户原话「现在又很多操作会阻碍主线程」（澄清：**角色工作期间 UI 卡死**——每事件 IPC→DOM）+
「这个是 markdown 渲染带来的卡顿吗，那**应该虚拟渲染**啊」。**属本角色边界内**。

## 热路径三件（Q-1）

1. **合并推送**（主进程）：事件按 **16ms（≈一帧）** 窗口**合帧**——`session:events`（数组，顺序不变；
   preload 同时保留单发 `session:event` 兼容探针/直发）；角色状态快照**按角色去抖 100ms**（同角色只留**最新**
   快照——快照语义）。纯逻辑在 `app/desktop/push-batcher.ts`（计时器注入、可单测）；关窗 dispose 挂起计时器。
2. **追加式更新 + 批量收尾**（渲染侧）：一次 flush 内**抑制滚动与虚拟窗口更新**（`batchDepth`），收尾统一
   贴底/更新窗口；左树重渲染**每批至多一次**（原先每事件一次）；无 per-event `scrollHeight` 读（reflow 风暴源）。
3. **流式 Markdown 惰性化**：角色在跑（真信号 `roleBusy`）时助手消息先**纯文本**（textContent）挂上，
   **settled 一次性** Markdown 化该段（只升**已挂载**元素；离屏行标 `mdReady`、挂载时才解析）。用户消息照旧即时。
4. **O-1 哈希缓存**：边界快照指纹加 **mtime+size 命中跳过**（未变文件只 stat；变了才重读重哈希）。

## 窗口化（Q-2）

- **行表**（append-only）+ **窗口**：行数 < `VIRT_MIN_ROWS=150` ⇒ **全挂载**（常规会话逐字不变）；
  ≥150 ⇒ 只实体化**视口 ± 30 行**，窗口外折成上下 `virt-spacer`（按行高和撑总高）；离屏行**不持 DOM、不跑
  Markdown**（`build` 惰性）。行高 = **估算（按类型）+ 挂载实测修正**（写读分离，防逐行 reflow）。
  滚动经 **rAF 合帧**每帧至多一次更新；交互行（待确认卡/回交卡/注入行）`keepEl`（离窗只脱挂、监听器保留）。
- **四条滚动语义逐条保住**：① 贴底（收尾统一滚）+ ② P-1 卡定位（目标行未实体化 ⇒ **先实体化再滚**并高亮）
  + ③ 切角色**点击即到底部**（**U-1 客户裁定，2026-10-12——取代本轮的「恢复位置」**；有未作答卡则卡优先） + ④ **D-1 回放整段包批量 → 行模型先建、
  DOM/Markdown 按需**（长转录不一次性实体化）。
- **如实取舍（登记）**：窗口化后 **Ctrl+F 页内查找 / 全选复制只覆盖已实体化行**（浏览器语义所限）。
  缓解建议（**不擅自加**）：聊天流「复制全文」按钮或「导出转录」——待客户裁定。

## S-1 回归修复（同日；客户「输出不会让滚动条滚动到最底下了」）

**复现（真机 e2e 确定性用例）**：长会话（200 行 ⇒ 窗口化生效）+ **按批**（`session:events` 数组——生产热路径形态）
追加输出 ⇒ 修前实测 `S1_STICK_AT_BOTTOM_DIST=339`（**未贴底**，正是客户症状）；另一向：上翻后新输出把读者
**拽回底部**（`S1_NOT_YANKED=false`，既有「无条件贴底」的旧行为）。

**根因（逐条核对派工列出的四个疑点）**：
- ① **flush 贴底判据在窗口化后失准（命中，主因）**：`flushBatchSideEffects` 在**窗口更新之前**贴底——
  此刻底部 spacer 尚未随新行增长（行只进了行表、未挂 DOM），`scrollTop=scrollHeight` 贴到「**旧底**」，
  每批差一整批高度（实测 339px≈10 行×34px 累积）。**修**：**先** `updateVirtualWindow`（挂尾行、spacer/
  实测高落定），**再**贴底；强制贴底（`scrollBottomForced`）同样先令窗口落定。
- ② **rAF 合帧把滚动放到测量之前**：rAF 本身无责；真正错的是 flush 内部顺序（同①，已修）。另在
  `updateVirtualWindow` 内加**「本就在底部者」补偿**：入口记 `wasAtBottom`（≤1px），高度/窗口修正后**仅在
  底部者**补一次贴底——**上翻者绝不拽**。
- ③ **P-1「到达不打断」误伤普通流式输出**：核对结论 = **是**（旧代码**无条件**贴底，完全违背「上翻不打断」）。
  **修**：新增**流式贴底判定** `streamShouldPin`（纯映射 `stickToBottom`，阈值 **24px**，**先量后挂**——
  距离在追加新行**之前**测；批量期**一次测量、批内复用**防逐 append 读布局）；助手/系统/拒绝/注入/回交
  五类流式行走「在底部才贴底」；**用户自己的动作**（发送）、**P-1 卡到达**、**切角色/回放收尾**仍
  **强制**贴底（`scrollBottomForced`）。
- ④ **行高实测修正顶回上方**：部分成立——修前实测修正只 `prefix=null`，spacer 高度要等**下一帧**才对，
  期间总高漂移会松开贴底。**修**：修正后**立即** `rebuildPrefix` 并**同帧**重设 spacer 高度。

**修后（真机 e2e 双向断言，两类路径分别覆盖）**：
| 断言 | 修前 | 修后 |
| --- | --- | --- |
| 窗口化（>150 行）贴底距底 | **339px（红）** | **1px** |
| 窗口化 上翻后新输出不拽回 | 红（拽回） | **true**（且远离底部保持） |
| 窗口化 回底后再次输出贴底 | true | true（1px） |
| 常规路径（<150 行）贴底 | — | **0px** |
| 常规路径 上翻不拽回 | — | **true** |

**取舍（如实登记）**：贴底时机从「每事件即时」变为「**每批收尾一次**（≈一帧）+ 窗口落定后」——即贴底最多
**晚一帧**（16ms 级，不可感知）；换取消灭 per-event 布局风暴。上翻期间**不再**有任何自动滚动（新的正确语义）。



## 跨角色建议（**不越界改**，请协调方转达门禁引擎/编排）

真机拒写路径的**同步小读盘**（`reloadBoundaryEntriesSync`，`src/**`）若落在**每写尝试**上，在一轮数百次
写尝试下会是主进程侧的同步阻塞源。建议：**按 mtime+size 缓存**（与 O-1 同法）或改 async 预载。
预计收益：把每写尝试的读盘+解析从主线程热路径上摘除（量级与 O-1 缓存护栏同型）。
