## 候选差异与取证边界

- 修正前候选的三个用例实际接收第二次请求，已打开的幕僚 handle 缺启用工具。最终候选在已核对原实例终态、无活动投影及 owner、会话空闲且新客户授权有效后才重绑。复测三条均通过。两条在原窗口继续只读和 B 流程，另一条在隔离 appData 的已开控制器等待原运营核验停稳，释放原 owner 后重新取得本人批准并启动另一保存图。保留早期夹具比较失败和真实旧 handle 缺工具的日志。见 E4、E7。
- 同宿主受信排队和重放保留原授权标识。冷启动重投中尚未 ACK 的纯排队文本不继承上一窗口授权，已落盘待确认提议和批准待办沿原请求恢复。W3 最终实包真实二次启动到首页，第二窗口未完成同项目 GUI 查询；表中同一待确认、批准待办和旧实例恢复来自 W5 的真实控制器、SQLite、Dapr 以及两包测试。另一个 linked worktree 的准入取证使用自定义模型工厂，随包实际模型的该检出入口未单独验证。
- W3 使用本机 Anthropic 兼容 SSE 替身，窗口、Preload、Pi、业务工具、SQLite 与 Dapr 实际运行。W5 以受控角色脚本和隔离项目走生产桌面控制器，原生资产与最终包逐项核对。组件注入、受控 IPC 和 Run-as-node 两包接续的入口均按实际记录。线上模型自动选图质量、真实外网中断、完整系统重启和 macOS 未实测。
- `4c6efec` 的原冻结 T2、T3、T5 缺口仍由原验收记录呈现。本轮只引用前轮已核对且未受改动的工作流行为；对幕僚工具、入口、卡与旧实例续接的受影响行为使用本轮复验。[原外置定义与 A 验收](2026-11-17_path-a-dapr-b2.md)
