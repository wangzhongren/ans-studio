独立验收从桌面使用、角色协作与后续维护所需的可观测结果判断候选，按锁定方案逐项核对原始证据。

验收对象为桌面中显式启用的新路径 B 实例、随包的 Dapr Workflow 与 SQLite 本地运行、可恢复的客户决定及角色交接、外置配置改变新实例走向，以及复用既有活动的测试专用只读流程。路径 A 与旧 B 纳入受影响回归。存量迁移、在途换图、默认上线、集群、多设备同步、可视化编辑器及任意代码插件均在本轮范围之外。

## 覆盖矩阵

| 覆盖组 | 冻结的环境与用例 |
| --- | --- |
| W · Windows x64 | 锁定为完整矩阵平台。原生架构实际候选发行包逐项核对 V1–V8、V10、V11a、V11b；每个故障窗口连续独立复现两次。另完成一次 V9 与一次 V4 的真实 OS 重启。 |
| M · macOS arm64 与 macOS x64 | 两种架构分别用原生环境各完成一次 V9 与一次 V4 的真实 OS 重启。每种架构各用同一持久数据卷、应用数据目录及 Git 仓库保全重启前后事实。 |

每个真实 OS 重启样本独立于故障窗口的双复现，抽验待决卡或原任务、持久 outbox 与在故障期间到期的 durable timer。按平台分别记录构建环境、原生桌面实测环境、持久磁盘及重启后取证入口。构建产物、静态检查、容器探针、重新启动应用进程及不同架构的执行分别只能证明各自覆盖的能力。对应平台无法运行桌面或无法用同一持久卷做真实重启时，将相应项标为证据不足。

各端到端用例使用隔离测试仓库。以 `test/测试/fixed-path-full-chain.test.ts` 的真实 Git 测试仓库形状及 RR34 的实际 B1 → B3 → B4 行为为对照，保留基线 OID、写集及预期 diff，避开 RR34 原目录。一条正常链从候选桌面实际发起 ANS 角色任务与发布流程，留存真实提交和受信客户通道作答。故障复现可使用确定性角色输出，须经真实应用入口、真实 Dapr/SQLite/进程及隔离 Git，注明替身范围和报告经真实模型、实际运行期验证的情况。

## 共同判据

- 正向用例每一项适用的逻辑决定、有效派发、报告收口与 Git 结果各生效一次。已确认业务输入零丢失，未经授权的推进、启动、写入或合并均为零。实际副作用不明时可安全阻塞并展示原因，已查实未执行且前置齐备时必须续跑。
- 所需组件健康、Worker 注册所需版本、前置事实齐备且所需远端已恢复时开始计时，60 秒内可在原界面见到续投结果、下一等待项或明确阻塞原因，人工操作及模型执行用时另计。故障期间已到期的 durable timer 从本地控制面和 Worker 恢复健康计同一期限，允许重复技术唤醒，业务效果生效一次。留存起算证据及实际可见状态时间。
- 审批、派发、回交的持久事实、幂等记录和 outbox 同一 ANS SQLite 事务写入，证据已可由不可变引用和哈希重取方可回执保存。同键同内容返回原结果，异内容冲突。`raiseEvent` 成功仅标记引擎受理，Workflow 消费与后续业务意图原子入账后才关闭 outbox；启动、重连及有界补投沿原键。核对事件的项目、实例、版本、步骤、任务和尝试等相关作用域，合法早到事实待依赖齐备后消费，不一致或未知历史保留最后确认状态并阻塞。
- 用候选 diff、结构检查与实际入口记录核对方案五层调用。Interface 经 Pipeline 呈现 ANS 事实，Worker 解释固定图并经活动调用 Service，授权与证据检查由 Service 执行，持久存储、进程、会话及受控 Git 经 Provider。Pipeline 到 Provider 的公开入口只用于无业务含义的基础设施操作，Model 无操作层依赖。Dapr SQLite 保存历史，ANS SQLite 保存权威业务事实，Scheduler 的持久数据保存提醒；旧格式只作投影。Dapr 管理端点留在宿主侧。界面可查询既有实例定义、步骤、待办、阻塞与证据。
- 本地候选基线为 Dapr Runtime `1.19.1`、`@dapr/dapr` `3.19.0`。验证随包 Scheduler 内嵌 placement；若该形式不可用，方案允许随包管理独立 Placement，需提供实际取舍、进程清单与连接、提醒证据。验证启动区分端口就绪、Worker 注册与可恢复状态，并保留应用 ID、数据目录及控制面身份。依赖缺失、许可不明或方案所列关键可行性条件不成立时，保留原始证据并交策划处理。

## B2 记录与判定

变更包须能定位冻结方案及 B1 版本、候选 commit/diff、任务节点、改动路径和统筹标注的风险档位。测试记录包含项目及基线、三平台包与二进制哈希、配置、环境、执行输入及可复查输出。用同一关联 ID 贯穿注入及健康/恢复时间、UI、ANS 事务和 outbox、Workflow 历史、接收回执、授权或失败原因与 Git 前后状态。证据去除凭据，留存失败与跳过；基线已有失败逐项与同环境冻结基线对照。

B2 逐行记「ID｜方案条目或标准｜需要的证据｜实际原始证据路径及哈希｜候选版本｜产出角色｜实际结果｜验收判断」。必要证据匹配当前候选且满足条目时判 `pass`；有原始证据证明偏离时判 `fail`；缺实测、环境、平台、次数、适用版本或可复查原始证据时判 `insufficient evidence`。`not applicable` 须给出方案依据，适用平台或必做窗口无法执行时仍为证据不足。

全部适用标准取得有效通过才给候选总体验收通过。有不满足项时列明差异、证据及由统筹安排的返工；未能核证时列出补证缺口，候选保持未获通过。候选、输入、依赖或契约变更时重核受影响证据；实质方案变更沿沟通授权流程处理。B2 的验收结论与产品合并、发布授权分别记账。
