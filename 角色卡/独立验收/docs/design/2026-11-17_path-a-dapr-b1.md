## 共同判据与证据

- 隔离测试工作区和 Git 仓库。可用确定性角色脚本及受信测试界面输入，业务全链仍须经真实工具、卡、宿主作用门、Dapr/SQLite 与 Git，按各用例注明真实环节、夹具与注入方式。原生业务控制器、实际 Electron/Renderer、Windows ZIP 与兼容续跑分别标明入口；真实外网、线上模型、完整 OS 重启与 macOS 仅按实际证据记载。
- 同一候选冻结源码提交及实际改动路径、测试代码及输入、包与原生组件哈希、操作系统及架构、项目素材和 Git 基线。按项目、实例、快照、步骤及尝试关联角色父子任务、卡与回执、注入位置和时间、PID、SQLite 事实/outbox 与 Workflow 历史、Git 前后 ref/OID、实际 diff、进程退出和界面状态；保留失败、跳过及同环境基线差异，去除凭据。
- 核对五层调用、注册能力的宿主消费者及实际作用端。新实例的有效节点和独立待办由 Dapr 及经应用验证的 SQLite 事实驱动。旧 JSONL 用于真实业务事实或兼容投影。审批、任务、报告及作用结果与 outbox 按原键同事务提交，Dapr 受理、消费、送达、执行及报告收口各凭本次持久证据辨认。有效业务决定、派发、归档、Git 效果、交付及适用回执各生效一次；旧尝试、越权及跨实例输入不得产生实际作用。结果不明时保留原事实并在面板展示阻塞原因。
- T1/T5 的配置检查采用方案规定的 YAML 1.2、项目路径及资源大小边界、重复键与未知字段校验。启动固定来源、ID、版本、摘要和执行器/活动契约。A11 需经运营真实收口，A12b 使用当前 accepted 候选；显式轻量验收须有受信处置，归档具体限制，交付披露「运行期未验证」。A9 对照真实仓库根、初始分支、`.gitignore` 及基线或任务分支 OID/父关系，本来无 Git 的 A 在该授权步骤前保持无 Git。

## B2 记录口径

B2 逐项记录「ID｜方案标准｜所需证据｜实际原始证据路径/哈希｜候选版本｜产出角色｜结果｜判定」。必要证据可复查、匹配当前候选且满足条目时标 `pass`。确有偏离标 `fail` 并列回到统筹的返工依据。缺实测、入口、故障窗口或候选绑定时标 `insufficient evidence`，同时列出补证缺口。`not applicable` 需给出冻结方案依据。

全部适用条目取得有效通过才可判候选通过。候选、输入、依赖或相关契约变化时复核受影响证据，实质方案变更回沟通。路径 B 既有通过的返工仅按同一证据作用范围引用，本轮验收与产品合并、发布授权分别记录。
