# D3 改完以后，怎样确认有效

用户希望继续正常使用常见只读命令，同时阻止明确的越界写入与执行误判，并避免编辑脚本后丢失执行权限。本标准复用批准的 D3，并按后续明确指令缩小 UI 范围，不增加 D2 要求。当前版本为 **C2（范围修订）**，仅标准就绪，尚未验收修复。

## 依据与范围

- 批准方案：[ANS-PERMISSION-REPAIR D3](../../../项目管理/docs/design/2026-10-21_design_permission-boundary-repairs.md)，已核对 SHA-256：`a81908e2486f88cacb4efe284dc030cd888e11c99619099def30217771b71e77`。
- 后续用户明确授权：“可以，就按 D3 轻量方案，用 ANS 技能安排各角色实施，改完测试一下。”设计正文中的旧实施状态不否认后续同版授权。
- **C2 授权来源**：可信启动端随后转交用户的明确指令“UI 不归你管”“你到时候给出意见让别人修改就行了”。据此，UI 应用/测试修改与 Electron 验证撤出本轮实施及通过范围；AC8 仅要求 README 修正和 UI 修改意见交接，不得声称 UI 已修或已验证。这是用户主动缩小范围，不是为通过测试放宽断言；其余 AC 保持原要求。UI 所有者回报应用/测试尚未改动，仅准备意见文档，后续审验仍需核对实际差异。
- 本上下文固定为独立验收，只写自身 [boundary.md](../../boundary.md) Section 1 与本任务共同许可的文档；不修生产、不改测试、不代跑所有测试、不改他人报告或调度状态。职责见 [feature-map.md](../../feature-map.md)。
- 同期产品/UI 平台化方案和文档不纳入 D3 候选。当前采用可信启动端交接，不虚构 task_ops 凭据、机器预检或放行记录。
- 无选装项。PATH 同名替换、隐藏配置/环境预加载、审批等待期间的程序变化及恶意并发替换仍是已接受风险；已批准 shell 的副作用仍不受 write_file 角色门禁限制。不得引入 D2 的来源信任、哈希、最小环境、全面 Windows 审批或仅 cat 白名单要求，也不得宣称已经实现恶意程序隔离。

## 复用 AC1–AC10

除 AC8 按 C2 缩小范围外，以下各项与 D3 原标准同义，细节以批准方案为准。实际执行由原所有者及独立测试角色提供，验收核查当前候选和原始证据，不以工作者声明替代观察。

| 编号 | 必须观察到的结果 |
| --- | --- |
| AC1 | 根内跨角色目录链接的覆盖/新建被拒；真实目标不在任务 writeSet 也拒绝；未授权目标无变化 |
| AC2 | 普通合法路径、已完整授权的链接别名、合法链接项目根正常；根外链接及目标本身链接继续拒绝；Windows junction 单独记录原生结果 |
| AC3 | 显式相对/绝对/Windows 程序路径、同名脚本后缀不能 basename 命中即免审批；拒绝无哨兵文件，原模式明确批准后才执行 |
| AC4 | 显式 `rg --pre` 两种形式交原审批；`--` 后普通文件名和模式文本不因子串误报；普通 cat/ls/rg/既有只读 git 分类保持原基线 |
| AC5 | advisory、operator-only、readonly-only 及普通链保持现行差异；原 deny/risky 不降级；拒绝、超时、中止、不可用无执行副作用 |
| AC6 | write_file 覆盖及 edit_file 保留 0755/0644/0600 普通权限；严格 umask 在独立子进程验证；新文件保持安全创建策略 |
| AC7 | stat/chmod/fsync/rename/abort 失败如实返回；提交前原文件保持；初判拒绝零副作用，mkdir 后重判失败允许留下合法空目录但不得越界写入 |
| AC8 | README 文案与现行需求确认代批、失败退回及人工路径一致；UI 仅交接修改意见，由其他负责者后续处理。本轮不改 UI 应用/测试、手动卡徽标或实际决策政策，不声称 UI 已修或已验证 |
| AC9 | Pi/Codex/Claude 受影响的公共工具接线回归，不能用三个引擎名字重复调用一个分类桩冒充真实接线验证 |
| AC10 | 没有增加系统来源/文件哈希/最小环境框架，没有全面收紧 Windows 或原只读白名单；剩余风险按 D3 说明保留 |

共享接口核对点：`AtomicWriteOptions.finalMode` 为可选 `0..0o777` 整数，非法值在创建临时文件前拒绝；POSIX 写临时文件后句柄 chmod，再 fsync、关闭、rename。Windows 不承诺 POSIX 权限等价，保持原替换和有界重试行为；未传参数的调用保持原样。新文件继续 0600 创建策略，严格 umask 可按既有行为进一步收窄；不要求保留 owner/ACL/扩展属性或特殊权限位。

## 五个阶段

| 阶段 | 必需证据及对应标准 |
| --- | --- |
| 共享 | 当前 atomic-write 差异、finalMode 合法/非法/未传参数测试、POSIX 顺序与失败保持/清理、严格 umask 及原调用回归、契约文档；覆盖 AC6/AC7/AC10 的共享部分 |
| 门禁 | resolve-write 双路径授权、project/skill 真实根语义，以及 classify-shell 新增 review 和既有分类的单测、文档；覆盖 AC1–AC5/AC10 的门禁部分 |
| 核心 | 基于当前共享和门禁，真实 write_file/edit_file 的写前复核、权限保持、拒绝/失败/中止证据和公共工具回归；覆盖 AC1/AC2/AC6/AC7 的核心部分，不在核心复制角色规则 |
| 文档与 UI 意见交接 | README 差异符合当前行为，UI 意见文档写明建议、依据和后续负责者；覆盖 C2 的 AC8/AC10。UI 应用/测试及 Electron 验证不在本轮通过条件中 |
| 完整集成 | 独立测试角色对同一候选的轻量联调、受影响编排/三个真实适配器及非 UI 路径回归、`npm run typecheck`、`node --test "test/**/*.test.ts"`，映射 AC1–AC10（AC8 依 C2）。既有全量命令带出的 UI 测试结果只如实记录，不代表已完成 UI 修改或 Electron 验证 |

各阶段通过只覆盖该阶段已验证范围，不替代完整集成。单元分类测试不替代真实执行副作用和适配器接线。共享/门禁或相关依赖变化后，受影响调用方的旧证据失效，需由实际执行者补测。失败、跳过和环境受限项逐项记录，保留原始失败与相关重跑结果，不改断言或隐去失败促成通过。

## 平台与候选证据限度

本机为 macOS。各报告至少提供实际 OS/架构、Node/npm 版本、命令、退出码、输入/fixture、执行时间、原始日志和候选身份。HEAD 不能单独识别未提交工作区：还需本轮变更清单及内容摘要/可复核 diff，并说明依赖版本；同期无关改动应分开标识。

macOS 原生执行只证明 macOS；Windows 路径字符串测试只证明分类逻辑。Windows junction、原生替换及相关 Windows 执行路径未测时必须单列“证据不足”，不能用 macOS、模拟或 skipped 记通过。Windows 不要求 POSIX 执行位等价，但仍需 D3 指定的原生回归。

可给出“macOS 已验证范围通过，Windows 原生证据不足”的分项结论；必要 Windows 证据缺失时，完整跨平台结论仍为证据不足，不能静默删除要求。此前缺陷复现、修复前基线及 D1/D2 评审均不算本轮通过。离线 SDK/MCP/loopback 不冒充线上模型；真实线上轮次与完整 OS 隔离不是 D3 新增完成条件。

## 最终结论

- **通过（pass）**：候选与授权范围一致，必要阶段、AC1–AC10、结构检查及文档均有当前有效证据，无未解决失败。通过须注明平台和范围，完整跨平台通过须补齐 D3 要求的 Windows 原生证据。
- **返工（needs-work）**：已有代码、测试或文档证据证明不满足批准标准，或存在未授权范围/规则放宽；指出差异、证据和原所有者，由可信启动端安排修复。
- **证据不足（missing-evidence）**：必要场景、运行、日志、平台或候选身份缺失，或依赖变化令证据过期；写明缺什么及谁提供，不把“没有证明失败”当作通过。

验收报告写在自身 docs/change 或 docs/fix，链接方案、本标准、候选差异、各角色报告/原始日志，逐项给出结论、理由与剩余问题。通过不授权提交、推送、发布或部署。
