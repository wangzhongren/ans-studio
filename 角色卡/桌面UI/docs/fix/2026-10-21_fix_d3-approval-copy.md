# 开启自动判断时，准确说明哪些请求会代批

当前“替我决策”的悬停标题和开启提示漏了需求确认；共享提示仍说判断失败会自动弹手动卡。它们与现有通道行为不一致，可能让客户误解开关作用。

客户最新明确“UI 不归你管”“给出意见让别人修改就行了”，因此原 UI 实施与验证计划已从本任务撤出。本文仅保留 [D3 R5](../../../项目管理/docs/design/2026-10-21_design_permission-boundary-repairs.md) 的文案建议供其他负责人后续处理，不构成本任务的实施安排。所属功能导航为[输入区与自动判断](../../feature-map.md)。

## 交接给其他负责人的修改建议

- `app/renderer/ui-labels.js`：decision 开关的开启/关闭标题补“需求确认”；开启提示说明需求确认只代选 `confirm`，不代选 `revise`。
- 共享提示限定为“适用自动判断且开关开启”的请求：判断未通过或未完成时，shell 不执行，写入与决策退回修正，不因此自动弹手动卡。开关关闭、未接入或不适用时仍走原人工路径；治理判断期间关闭开关，原卡可恢复；轮次中止走取消。
- 手动需求确认卡仍使用“需求确认 · 客户”徽标；成功代批标记仍由实际结果驱动。只修正把需求确认描述为永远由客户本人操作的注释。
- 同步 `test/桌面应用/tool-rows.test.ts`、`test/桌面应用/e2e/uiux-v2.mjs` 中相关文案断言，不修改布局、框架、开关机制或模型政策。

## 后续验证建议与本轮状态

后续负责人若实施上述建议，可运行纯函数窄测和现有 `renderer.test.ts` 回归，再用 `ANS_JUDGE_UI_ONLY=1` 运行离线 Electron 界面检查。后者使用受控 IPC，不调用模型；它证明实际界面呈现，不能代替主进程真实失败分支测试。这些仅是后续验证建议，本任务不执行。

本轮仅完成意见交接；UI 应用代码与测试零修改，UI 验证未执行。无需等待独立验收标准启动 UI 实施，后续修改及验证由其他负责人另行处理。
