## 1. 改了什么

在 [`../project-rules.md`](../project-rules.md) §二「已确认要求」末尾新增**第 10 条**：

> **打印/日志-01：代码/文档工作在必要处添加打印/日志**（客户 2026-10-23 确认，立即生效）

四个字段齐备：

| 字段 | 要点 |
| --- | --- |
| **范围** | 全部角色的代码、测试、脚本，以及生成/校验/迁移/复算类文档工作；立即生效；不追溯重写未受影响的历史代码。 |
| **要求** | 必要处添加打印/日志；不要求每行/每函数/热循环逐项刷屏；不得打印密钥、令牌、真实 `.env`、个人敏感信息；不得用日志伪造成功、掩盖失败或代替测试证据；日志不得改变控制流或业务结果。 |
| **正确办法** | 代码优先用既有 `createDiagnosticLogger`、`log.record` / `log.error` 或既有 CLI/用户可见输出，不另起框架/依赖；在入口/出口、状态迁移、外部 I/O、失败/重试/跳过、批处理开始/结束与跳过原因、证据写入、配置来源选择等必要处记录；热循环用聚合/摘要；用户可见输出与诊断日志分开。文档/脚本在关键步骤打印命令、输入、输出路径、退出码/计数与证据位置；记录引用真实输出，不把摘要当原始证据。 |
| **检查方式** | 代码审查/差异检查必要日志且无秘密/无噪声/无伪造；运行受影响脚本/测试确认输出可复现；行为相关处可在测试中断言日志；不以噪声日志冒充可观察性。 |
