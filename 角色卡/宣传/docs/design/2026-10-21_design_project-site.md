# ANS Studio 项目官网设计

官网要让第一次打开的人在几分钟内知道三件事：ANS Studio 是什么（AI Agent 的自主组织运行时，而不是单个写代码助手）、它靠什么组织多个 Agent（Role-first：角色、边界、派发、验收）、去哪里下载并核对来源。视觉延续桌面应用的石墨工作台，不另做一套品牌。

受众是开发者与工程负责人；语气克制、具体、诚实，只写事实来源能证实的内容，不承诺未实现能力。首轮客户定位（2026-10-21，经协调方转达）：顶层是「An Autonomous Organization Runtime for AI Agents」，其下以 Role-first 为组织原则。

## 设计计划

### 概念

官网是桌面应用的第二窗口：左侧账本栏对应应用的角色导航，角色列表用应用侧栏同款字母块，横线账本行代替圆角卡片网格；唯一的结构符号取自应用图标「括号与横杠」，只出现在品牌位、Role-first 印章和截图四角，不铺满页面。

### 色彩 token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#151512` | 页面底色（石墨，非纯黑） |
| `--panel` | `#1b1b18` | 账本栏、代码面板、页脚 |
| `--raised` | `#23231f` | 示例条、字母块 |
| `--line` | `#33332c` | 横线、边线 |
| `--text` | `#ecece2` | 正文（对底色 15.39:1） |
| `--muted` | `#9e9e92` | 次要文字（对底色 6.76:1） |
| `--mint` | `#b9f2c5` | 当前导航、主按钮、截图角标、肯定状态 |
| `--mint-deep` | `#79d68f` | 边框、roleId、YAML 键、步骤序号 |
| `--amber` | `#e0b169` | 待确认（审批卡）、未签名警示、诚实说明 |
| `--danger` | `#e39a89` | 拒绝状态 |

颜色规则：mint 只表示当前与肯定动作，amber 只表示待确认/未验证，danger 只表示拒绝；三者都承载真实状态，不作装饰。正文对比度实测 ≥ 6.7:1。

### 字体与尺度

- 正文/标题：`"IBM Plex Sans", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif`；Google Fonts 引入 400/500/600，失败时回退系统字体，版面仍成立。
- 数据/标签：`"IBM Plex Mono", ui-monospace, SFMono-Regular, Menlo, monospace`，**只用于真实数据**：roleId、版本号、路径、SHA、命令、YAML、环境变量名。
- H1 `clamp(2.6rem, 5vw, 4.4rem)` / 1.12；H2 `clamp(1.8rem, 3vw, 2.6rem)`；正文 16px / 1.75，栏宽约 62ch。窄屏（≤600px）H1 降一档到 `clamp(1.9rem, 9vw, 2.6rem)`，保证「自主组织运行时」等短语完整不拆行。

桌面内容区最大 1080px、居中，左右留白 40px；账本栏固定 168px。section 间距桌面 120px、移动 68px，用整宽细线与留白组织层级，不套圆角卡片。

### 原则

1. 官网是应用的延伸：字母块、账本行、石墨底与真实截图都来自产品本身。
2. 颜色即状态：mint 当前/肯定、amber 待确认、danger 拒绝。
3. 等宽字体只承载可核对的数据。
4. 只编排一次：加载时 H1 轻微上浮（12px）、截图四角括号从 10px 外收拢到位；尊重 `prefers-reduced-motion`，其余不做入场动画。
5. 诚实是设计的一部分：未签名警示与 shell 无沙箱限制拿到真实视觉重量（琥珀边线说明块），不藏在脚注。

### 对照通用默认的复审

暗色底 + 单一亮色强调本身是常见的生成式默认，但这里不是自由发挥：它来自产品真实界面截图与客户指定方向（石墨工作台、薄荷绿强调、琥珀待确认），所以照做；在自由轴上做了具体选择——账本式横线列表、应用同款字母块、截图四角括号、单枚 Role-first 印章、YAML 状态面板。明确移除：紫蓝渐变、发光、圆角卡片网格、每个 section 的英文小标签、无意义编号、给所有链接加「→」、重复的入场动画。

## 信息架构与内容主线

主线：自主组织运行时 → Role-first → 角色边界 / 门禁 / 独立验收。

| 顺序 | 区块 | 锚点 | 目的 | 事实来源 |
| --- | --- | --- | --- | --- |
| 1 | Hero | `#top` | 定位、英文原句、Role-first 印章、两段导语、CTA、事实行、真实截图 | 客户定位指令；README |
| 2 | 为什么 | `#why` | 不是更聪明的助手；Role-first 三个推论 | README 治理模型与门禁 |

## 可访问性与响应式口径

- 语义：`header/nav/main/section/footer`；一个 h1；h2 每节一个；物品级 h3；列表用 ul/ol；跳转链接「跳至主要内容」。
- 键盘：焦点可见 2px mint、offset 2px；点击目标 ≥44px；导航当前项由 `IntersectionObserver` 加 `aria-current="location"`，无 JS 时导航仍可用。
- 动效：只做一次 Hero 编排；`prefers-reduced-motion` 下关闭动画与平滑滚动。
- 响应式：360px 宽不横向溢出；代码块与示例可横向滚动（窄屏示例改为换行）；桌面 ≥1024 与移动 <1024 两档布局。

## 验收口径

1. 只看事实来源可证实的内容；版本号、下载链接、校验文件与 README/Release 一致；不承诺未实现能力。
2. 桌面 1440 与移动 390/360 截图人工查看：H1/H2 中文短语不断开、印章与英文定位行不拥挤、截图比例合适、角色列表可读、代码块不撑破页面。
3. 外链逐一 HEAD 检查（发布资产 200/302），本地资源存在；结构检查无重复 id、图片有 alt、外链 `rel="noopener"`。
4. 对比度 ≥4.5:1（实测正文 15.39、muted 6.76）；无控制台异常。
5. 纯静态：无构建、无框架、无外部 JS；相对路径保证 `/ans-studio/` 子路径可用。

## 英文页排版差异（2026-10-21 追加）

客户追加英文版后，英文页沿用同一套 token、账本栏、印章、截图角标与 section 结构，只在排版上做语言适配：

- `html[lang="en"]` 下 H1 `letter-spacing:-0.03em`、`line-height:1.06`、`max-width:15em`；正文行高 1.65；H2 行高 1.2、字距 -0.015em。
- 英文 H1 不使用中文页的 nowrap 片段方案，改为按词自然换行 + 平衡；在 `AI agents.` 之间加 `&nbsp;`，防止末行只剩 `agents.`。实测 1440 两行、390/360 三行，`organization` 从不被拆开。
- 角色列表桌面端单独微调列宽（权力列 230px）；移动端沿用统一堆叠布局。
- 语言切换作为小号 mono 标签放在账本栏底部、移动顶栏与页脚，当前语言 mint + `aria-current="true"`；360px 顶栏一行放得下。
- 英文文案按技术产品语气重写而非逐字机翻；事实、链接、版本与中文页逐项一致，写盘示例保留真实中文路径并加一行说明。

## 实现后的自审与修订

首轮实现后按截图自审，修订记录见[变更文档](../change/2026-10-21_change_project-site.md)。要点：修复移动端 grid 轨道被 nowrap 示例撑开的溢出；用不可断行片段修正 H1/H2 的中文拆词；移动端 H1 降一档；角色描述启用 `text-wrap: pretty` 消除孤字；示例在窄屏改为换行；导航高亮改为「阅读带交集高度」判定；客户定位追加后重排首屏层级（英文定位行 → Role-first 印章 → 中文 H1）。
