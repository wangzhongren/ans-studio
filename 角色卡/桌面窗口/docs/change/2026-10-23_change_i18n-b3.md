## 1. 目标与做法

只迁移**应用生成、最终显示给用户**的主进程文本：系统行、派发未受理/去重/投递失败原因、写卡/验收推进反馈、会话历史错误、项目/设置/图片错误、确认卡/恢复回执、看护事实行、demo 文案、恢复页。

做法（不改变业务行为）：

1. `app/desktop/i18n.ts`（B0 文件）新增进程级当前 translator 绑定：
   - `mainT(key, params)`：模块级翻译入口，读取当前 `MainI18n` 实例；
   - `mainLocale()`：当前 locale（恢复页 `lang` 用）；
   - `createMainI18n` 创建/复用的实例成为 `mainT` 的读取目标；`setLocale` 成功后**新生成**文本即用新语言。
   - 这样 `app/main.ts` 直接构造的通道（customer-input / operator-channel / 确认卡）无需新增写集即可同 locale 取词；`main.ts` 未改动。
2. 各文件在**生成点**调用 `mainT("main.*")`（少数跨分区复用 `shared.common.*` / `ui.judge.*` 的既有 key，如 `shared.common.unknownReason`、`ui.judge.flowSuffix`、`ui.events.handbackDeliveryWithRole`）。不复制目录、不复制插值/复数/回退。
3. 动态值全部走 `{param}`；未做字符串拼接/拆句（例外：`{flowId}` 等机器标识后缀沿用既有 key `ui.judge.flowSuffix`；`{paths}` 溢出片段见 §5 缺 key）。
4. **zh-CN 输出逐字不变**：所有 key 的 zh 值即迁移前的字面量（由 PM 冻结目录保证）；`mainT` 默认 zh-CN；旧测试断言零改写（新增断言单独命名）。
