## 2. 施工口径（实现摘要）

### 2.1 内部 `forcedWorkflowMode` 与模式解析

- `SessionOpenRequest` **不变**；新增进程内部接口 `InternalSessionOpenRequest extends SessionOpenRequest`
  （`forcedWorkflowMode?: WorkflowMode`）。`openInternal`/`openInternalUnsafe` 的入参类型改为它（公共
  `open`/`openBackground` 传入原 `SessionOpenRequest` 结构上兼容；IPC `openSession` 只透传三字段）。
- `openInternalUnsafe`：`listingGovernanceModel` 一次读取；`forcedSessionWorkflowMode` 仅在
  `forcedWorkflowMode === "fixed"` 且枚举治理模型为 `trio` 时生效；`requestedSessionMode` 优先它，
  否则既有 `sessionWorkflowModeForTask`/`sessionWorkflowModeForChat`/single=legacy 逻辑逐字不变。
- `LiveSession` 新增 `readonly sessionWorkflowMode`（建会话时定格；唯一创建点 `this.sessions.set`）。
- 设计对齐（v1.3 §3.6/§4.1）：run-role 的 `workflowModeForFlow` 是 per-flow 现场解析；`workflowMode`
  常量是设计允许的单 flow 兼容形态。fixed 派发的目标打开按 B1 设计**不带 taskId**（无 flowId 可解析），
  故由应用以内部 forced 常量把该会话确定为 fixed——与 B6.1 对 fixed 聊天会话的常量注入同一形态。

### 2.2 fixed 目标安全重绑（`openInternalUnsafe`）

- forced fixed 打开时，同项目既有条目若 `sessionWorkflowMode !== "fixed"`：busy 或 `origins.running`
  非空 ⇒ `fixed-session-rebind-blocked：…` fail-closed；否则 `disposeEntry` 安全关闭（旧句柄 dispose、
  队列保留）后按 fixed 新建。用户打开/legacy 打开不触发（无 forced）。
- 若旧条目关闭失败 ⇒ `fixed-session-rebind-blocked：目标旧会话关闭失败（…）`，不新建。

### 2.3 `routeFixedPathDispatch`（fixed 派发）

- 自动打开条件从「目标不存在」扩为「目标不存在 **或** 既有条目非 fixed」；打开请求带
  `forcedWorkflowMode:"fixed"`（仍**不**按 taskId 绑定——fixed 任务作用域属 B3）。
- 打开失败：既有 `dispatch-target-open-failed` 回执；若失败原因为重绑受阻，改回稳定码
  **`fixed-session-rebind-blocked`**（`task.reported failed` 照记，不投递）。

### 2.4 `drainQueueUnsafe`（投递机自动开启）

- 自动开启目标会话前计算 `forcedDeliveryMode`：条目 `taskId` 属 fixed 任务（`isFixedTask`）⇒
  `"fixed"`，legacy 任务 ⇒ 不传。既有条目非 fixed 时把「需要重绑」并入自动开启条件（避免 fixed 任务
  投进既有 legacy 会话）。打开请求仅在固定任务来源时带 `forcedWorkflowMode`；其余逐字不变。

### 2.5 边界重建透传

- `rebuildIfBoundaryStale`/`rebuildIfBoundaryStaleUnsafe` 增加可选 `forcedWorkflowMode`，仅由
  `openInternalUnsafe` 在 forced fixed 打开时透传；内部重开携带同一强制值（重建后的会话仍 fixed）。
  其它调用（settle 扫描 `refreshStaleBoundaries`、手动 `rebuildSession`）不传，行为逐字不变。

### 2.6 `contractCheck`

- B7.1 已实现会话级 `mode` 参数；本批确保 forced fixed 经 `sessionWorkflowMode` 传入 ⇒ 目标 convener
  的 `contract_check` 输出 fixed 视图（无 `run：legacy`/`runId(pinned)`）。新增测试直接断言。

### 2.7 唯一旧测试改动：接线钉同步（如实披露）

- `test/桌面应用/boundary-refresh.test.ts` 的 O-1 接线钉按**原样字符串**钉
  `this.rebuildIfBoundaryStale(key, userInitiated, selectionVersion);`；本批该调用新增第 4 个实参
  （forced 透传），旧字符串不再存在。按「钉的意图不变、被钉代码变化即同步」原则更新为
  `…selectionVersion, forcedSessionWorkflowMode);` 并补充说明（钉的仍是「续接路径保持本次选择版本」，
  新增 fixed 强制模式透传）。其余旧断言零修改。
