## 2. 施工口径（实现摘要）

### 2.1 `openInternalUnsafe`：fixed 会话的任务绑定与安全重绑

- forced fixed 打开时，既有同项目条目的 `sessionWorkflowMode !== "fixed"` **或**
  `assignedTaskId !== req.taskId`（`req.taskId` 非空）⇒ 进入重绑分支：busy/有在跑 origin ⇒
  `fixed-session-rebind-blocked`（不关闭、不投递）；空闲 ⇒ `disposeEntry` 安全关闭后按 fixed 新建。
  O-1 重建续段（`internalReopen=true`）不参与任务重绑（其 taskId 取自被重建条目自身；防与并发新会话互踩）。
- `LiveSession.assignedTaskId` 创建条件扩展为
  `req.taskId && (非内置 || verifier || sessionWorkflowMode === "fixed")`：fixed 任务会话（含内置
  convener/product 等）记录真实任务 id；legacy 旧语义不变（内置仅 verifier 记录）。
- 既有无任务 fixed chat 打开不写 `assignedTaskId`（第 3 条不破坏面）。

### 2.2 `routeFixedPathDispatch`：目标打开携带 taskId

- 目标条目已 fixed **且** `assignedTaskId === taskId` ⇒ 不打开（同一任务续投）。
- 目标未开 / 非 fixed / fixed 但未绑定本次任务，且**不是**「fixed 且忙」⇒
  `openInternal({taskId, forcedWorkflowMode:"fixed"})`；busy/关闭失败 ⇒ 稳定码
  `fixed-session-rebind-blocked`（`worker-task-session-busy` 同向映射），`task.reported failed` 照记、
  不投递；其它打开失败仍 `dispatch-target-open-failed`。
- 目标已 fixed 且忙 ⇒ 受理段不打开（忙时入队不丢），条目入队由 drain 在空闲后重绑投递。
- 非 fixed（legacy 风险面）仍立即打开走 B8.1 fail-closed（绝不把 fixed 任务留在 legacy 队列）。

### 2.3 `drainQueueUnsafe`：自动打开同口径

- 固定 **dispatch** 条目计算 `fixedOpenTaskId = item.taskId`；既有 fixed 条目
  `boundTaskOf(entry) !== fixedOpenTaskId` ⇒ 需要重绑（busy ⇒ 保持排队；空闲 ⇒ 打开时传 taskId+forced）。
  打开请求的 taskId 取 `taskBoundSession ? assignedDeliveryId : fixedOpenTaskId`。
- 回交条目（`kind:"handback"`）不传 taskId（其 `item.taskId`/`handback.taskId` 是子任务，不是目标会话
  的受派任务，误绑会让创建者自己的报告关联到子任务）；B8.2 的 forced fixed 重绑保留。
- legacy 任务（非 workflowId 命名空间）不传 forced/taskId，旧路径逐字不变。

### 2.4 `sendDelivery`：handback intent 携带真实 taskId

- `handbackIntentTaskId = assignment?.taskId ?? origin.taskId ?? （fixed 回交回合时 entry.assignedTaskId）`。
- legacy：`origin.taskId` 由 assignment 赋值（恒等），行为不变；fixed 派发：B8.2 已绑定
  `origin.taskId = handbackTaskId`（task.created 账本事实，无 run/assignment）⇒ intent 带 taskId。
- fixed 回交回合：`requiresHandback=false`、无 assignment/origin 任务 ⇒ 回落会话自身
  `assignedTaskId`。该回合 intent.required=false（无自动回交）；只有模型显式 `submit_report` 才产生关联报告，
  不会自动写 blocked 报告污染任务状态。

### 2.5 报告→收口链（本批不新增写入点，只补齐任务事实）

`submit_report`（run-role `withHandback`）→ handback.taskId → 桌面 `commitHandback` 写
`task.reported(status=done)` → `closeTask accepted` 的 `lastReport.status === "done"` 门通过。
RR5 的 0 条 `task.reported`/全部 `close-report-missing` 断点由此闭合；`handleHandback`/账本写入
实现未改（不改 `src/**`），只补它缺的 taskId 输入。
