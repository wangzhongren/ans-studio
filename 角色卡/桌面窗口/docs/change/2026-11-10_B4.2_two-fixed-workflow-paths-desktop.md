## 二、B4.2 实施内容

### 2.1 `app/desktop/workflow-git.ts`（M）：`TaskGitPort` 真实实现 + `TaskGitShellPort` 绑定

- 新增导出 `TaskGitPort`（请求式真实端口）与两个构造函数：
  - `createDesktopTaskGitPort(): TaskGitPort`——每条命令现场构造 sanitized env（复用 B3 `runGit`：
    不经 shell、清空继承 `GIT_*`、`HOME`/`GIT_CONFIG_GLOBAL` 隔离到 `<projectRoot>/.ans/git-home`、
    `-c core.hooksPath=<empty>`、`GIT_CEILING_DIRECTORIES=<projectRoot>`、输出/时限有界）；
  - `createDesktopTaskGitShellPort(projectRoot): TaskGitShellPort`——绑定项目根为编排 B4.1 注入形态
    （`run-role.ts::TaskGitShellPort` 同形，**只读类型消费**）。
- 方法（与任务条目逐条对应）：
  - `acquireCriticalSection(projectRoot, owner)`：**直接委托 B3 `acquireProjectGitCriticalSection`**
    （同一把项目级锁；占用 ⇒ `undefined`、不排队；释放函数幂等）——发布合并与 shell 提交互斥；
  - `currentBranch({projectRoot})`：真实只读（`symbolic-ref --short` → `rev-parse --abbrev-ref`；
    detached ⇒ `"(detached)"`，与门禁分支核对不符即拒）；
  - `add({projectRoot,paths})`：固定 argv **`git add -- <literal paths…>`**；运输防御拒绝任何 flag
    （`-A/--all/-u/…`）、glob（`*?[]`）、`.`/`./x`、绝对路径/盘符、反斜杠、`..`/`.`/`.git` 段
    （fail-closed，只能更严）；无锁（staged 内容检查属 commit 门）；
  - `inspectStaged({projectRoot})`：固定 **`git diff --cached --name-only -z`**（argv 唯一来源 =
    Service 出口 `TASK_GIT_STAGED_INSPECTION_ARGV`），NUL 解析为**字面路径数组**（丢弃空段）；
    读取失败**抛错**（不伪装空集合）；在调用方（门禁 `runTaskGitCommit`）持有的锁内执行；
  - `commit({projectRoot,message})`：固定 argv **`git commit -m <message>`**；`ShellTaskGitPort.commit`
    适配器只接受逐字 `["git","commit","-m",message]`（`-F -`/`-F file`/`--file`/`--amend`/`-a`/`--all`/
    `-am`/`--author`/`--no-verify`/多参/空 message 一律拒绝且**不执行**）；
  - 失败真实码/fail-closed：add/commit 返回真实 `ShellTaskGitCommandFacts`（保留 exitCode/stderr；
    内部错误/超时带 error）；staged 读取失败抛错，由编排执行路径转失败事实。
- 预算：调用方给出的更小 `timeoutMs`/`outputLimit` 生效；输出硬上限仍是本模块 `GIT_OUTPUT_LIMIT`
  （`runGit` 只增加可选 `outputLimit`，缺省路径逐字不变）。
- **不 push/tag/amend/no-verify/-a/--author/-F**；不新增 `requestReleaseMerge`；未新增依赖。
