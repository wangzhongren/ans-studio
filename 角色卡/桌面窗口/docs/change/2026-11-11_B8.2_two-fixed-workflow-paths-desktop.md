## 0. 结论摘要（先读）

1. **convener 生产派发自动绑定**（`app/desktop/session.ts::routeFixedPathDispatch`）：当来源是运营
   （convener）且 `d.workflowId`/`d.stage` 缺失（或 flowId 为空）时，应用读取 `source.origin.taskId` 的
   `task.created`（`workflowService.inspectAssignedTask`），校验 **open / fixed / chief→convener /
   taskKind=stage-request / workflowId·stage 齐全**且 **workflowId 在 workflows 账本存在**，然后绑定
   workflowId/stage/flowId 用于 workflow 事实、任务创建与 `stage.dispatched`。**不要求模型自报
   workflowId**；显式 workflowId 与父任务不一致 ⇒ `stage-request-invalid`；绑定失败 ⇒
   `workflow-binding-unavailable`（fail-closed，不建任务、不写 trunk/run、不回落 legacy 星形派发）。
   - `routeDispatch` 的 fixed pre-check 对 **convener** 放开「无 workflowId/stage ⇒ `stage-request-required`」
     （幕僚路径不变）；RR3 的 9 次被拒就是这个 pre-check。
   - `flowId` 不是可信事实：绑定路径以父任务账本 flowId 为准（RR3 运营按 legacy 口径记的 `flow
     snake-game` 不阻断合法派发）；显式 `stage` 是本次生产派发的**目标阶段**（如 A7 stage-request 之后派
     A8，与 B5.1 夹具一致），允许与父任务 stage 不同，仅在缺失时按任务书从父任务绑定。
2. **fixed 回交不再走 legacy assignment**（`inspectHandbackAssignment` + 新增
   `inspectFixedHandbackChild`）：`item.kind==="handback"`、目标 convener、child `task.created.workflowId`

## 2. 施工口径（实现摘要）

### 2.1 `routeDispatch` fixed pre-check：只对 convener 放开缺 workflowId/stage

- fixed 聊天会话中，非 stage-request 派发原有两道 pre-check：显式 `workflowId+stage` ⇒ 进
  `routeFixedPathDispatch`；否则 `stage-request-required`（B7.1）。RR3 的运营无法自报 workflowId，
  9 次合法派发全部卡在这里。
- 本批：**来源 = 运营（convener）** 时，即使缺 `workflowId/stage` 也进 `routeFixedPathDispatch`
  （绑定/fail-closed 都在路由内完成）；**幕僚路径逐字不变**（缺少字段仍 `stage-request-required`）。

### 2.2 `routeFixedPathDispatch`：从真实受派任务绑定 workflowId/stage/flowId

- 受派任务事实：`source.origin.taskId` → `workflowService.inspectAssignedTask({actorRoleId: convener})`
  （只认 tasks 账本；不采信自报）。绑定就绪条件：`open===true && stopped!==true && from==="chief" &&
  to===convenerId && taskKind==="stage-request" && workflowId/stage 齐全`。
- 触发绑定：`workflowId===undefined || stage===undefined || flowId===""`。绑定就绪 ⇒ 绑定
  workflowId/stage（stage 仅在缺失时绑定；显式 stage 是本次生产派发的目标阶段，允许与父任务不同）与
  flowId；并用 `readWorkflowLedger` 核验 workflowId **在账本存在**。
- 显式 `workflowId` 与父任务不一致 ⇒ `stage-request-invalid`（不采信模型自报、不回落 legacy）。
- 绑定失败（无受派任务/不可读/非 open fixed stage-request/缺 workflowId·stage·flowId/workflow 不在
  账本）⇒ `workflow-binding-unavailable`；不创建任务、不写 `.ans/trunk`/`.ans/runs`、不回落星形派发。
- 绑定值用于：workflow 事实（账本视图/授权证据）、`task.created`（`flowId/workflowId/stage`）、
  `stage.dispatched`（`recordFixedStageDispatchForTask`）、路径 B/B1/B3 关键门与写集核对（flow 取绑定值）。
- 既有「Q6 assigned-task 证据」对象改为在绑定块内构造（同一事实，不重复读盘）；谓词/授权不变。

### 2.3 fixed 子任务回交（drain）

- `inspectHandbackAssignment`：先读一次 tasks 账本；`child.created.workflowId !== undefined` ⇒ fixed
  分支（不再调用 `resolveDeliveryAssignment`，不产出 `pendingControllerAssignment`）；否则 legacy 原路径
  逐字不变（含混合批次：legacy 选中的 assignment 仍生效）。
- 新增 `inspectFixedHandbackChild`：child 真实存在且带 workflowId；`created.to === handback.roleId`；
  `created.from === recipientRoleId`（convener）；`member.flowId` 给出时须与 `created.flowId` 一致；
  child 未收口；workflow 账本存在、未损坏、未关闭。失败 ⇒ `delivery.blocked
  reasonCode:"fixed-handback-unverifiable"` + 系统行「固定任务回交未投递（安全校验未通过，消息已
  保留）：…」；条目不投递（保留待重试，不误投）。
- 无 legacy run/candidate/assignment 依赖：fixed 全批返回 true 且 `pendingControllerAssignment =
  undefined`（不按 taskId 绑定目标会话；投递目标会话按 B8.1 forced fixed 重绑）。

### 2.4 `sendDelivery`：fixed child 跳过发送前 legacy child-report 解析

- B8.1 披露的第二处阻塞：convener 回交发送前，`sendDelivery` 对 `reportedChildren` 逐一
  `resolveDeliveryAssignment(child-report)`（要求 child `parentTaskRef`），fixed child 无
  `parentTaskRef` ⇒ `delivery-child-source-invalid`，投递失败回队。本批：fixed child（`isFixedTask`）
  跳过该解析（drain 已按账本校验）；legacy child 逐字保留。

### 2.5 fixed 回交目标会话 forced fixed（drain 自动开启）

- `forcedDeliveryMode` 的固定任务判定从 `item.taskId` 扩展为 `item.taskId ?? handback.taskId`
  （回交条目在重启恢复/未登记 `starTaskIds` 时 `item.taskId` 可能缺席，回交载荷仍在）；判定仍以
  tasks 账本 `workflowId` 命名空间为准。既有非 fixed 会话走 B8.1 安全重绑。

### 2.6 fixed 派发投递的 origin 任务绑定（真实链关键补口）

- **发现的真实链断点**（确定性测试没覆盖，B7.1/B8.1 夹具均用手工 `liveSource.taskId` 注入）：B1 的
  `sendDelivery` 对 fixed 派发**跳过** legacy `assigned-task` 解析 ⇒ `origin.taskId` 从未被设置。真实
  运营回合里 `dispatch_task` 的 `source.origin.taskId` 因此为 undefined，B8.2 的自动绑定证据（以及
  B5.1 A9 的 `complete_team_plan` 身份证据）在真机上仍然不可得——RR 会再次得到 `workflow-binding-unavailable`。
- 修复：fixed 派发（`requiresHandback && handbackTaskId` 且 `task.created.workflowId` 存在）投递时，
  从 tasks 账本取真实 `task.created`，把 `origin.taskId` 绑定为该任务 id、`origin.flowIds=[created.flowId]`
  （**无 run/assignment**；不调用 legacy 解析）。legacy 任务仍走原 `resolve` 逐字不变。
- 新增「真实投递链」测试：chief 投递 fixed stage-request 到 convener（真实 session entry/origin，不手工
  注入 taskId）→ 断言 `origin.taskId` = 真实任务 id → 运营在该回合内生产派发自动绑定 workflowId/stage。
  该测试在 HEAD 上失败（origin.taskId 缺失 ⇒ 无绑定证据）。
