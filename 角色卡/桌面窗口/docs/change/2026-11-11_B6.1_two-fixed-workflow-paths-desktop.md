## 2. 施工口径（实现摘要）

### 2.1 `app/desktop/workflow.ts`：`sessionWorkflowModeForChat`

- 位置：`dispatchFlowIdOf` 之后、B3 段之前（`sessionWorkflowModeForTask` 邻近）。
- 规则（每次调用现场只读、**不缓存**；不写盘、不授予写权/派发权）：
  1. `.ans/project.json workflowSchema` 显式 `"two-fixed-paths/v1"` ⇒ `fixed`（显式优先）；
     显式 `"legacy/v1"` 或非法值 ⇒ `legacy`；文件存在但不可读/不可解析 ⇒ `legacy`（fail-closed）。
  2. 缺省：有效 `.ans/trunk/manifest.json`（`trunk/v1` + 正整数 `trunkVersion`；引用的 run 已
     closed/cancelled ⇒ 与编排 `validTrunkPointsToFlow` 同口径视为关闭，不强制 legacy；引用 run
     缺失 ⇒ trunk 仍有效）⇒ `legacy`；任一 `.ans/runs/*/manifest.json` `state ∈ {draft,pinned}`
     ⇒ `legacy`；两者皆无 ⇒ `fixed`（空项目/纯新项目）。
  3. 读失败/坏配置（项目根不可读、trunk/run manifest 存在但不能解析）⇒ `legacy`（不猜 fixed）。
- 与编排单一实现的关系：有 flowId 的 per-flow 判定仍只委托编排 `workflowMode`
  （`resolveWorkflowMode`/`resolveFixedPathMode` 未改）；本 helper 只解决**无 flowId 的聊天入口**
  初始模式。首条 fixed stage-request 仍由 `ensureFixedPathStarted` 写回并按编排 per-flow 复核。

### 2.2 `app/desktop/session.ts`：聊天入口 + fixed 常量注入

- `openInternalUnsafe` 的 `requestedSessionMode`：`governanceModel==="trio"` 时
  `taskId !== undefined ? sessionWorkflowModeForTask(...) : sessionWorkflowModeForChat(...)`；
  single/su 仍 `"legacy"`；有 taskId 的行为逐字不变。
- `openObservedRoleSession` 入参新增 `...(sessionWorkflowMode === "fixed" ? { workflowMode: sessionWorkflowMode } : {})`
  与既有 `workflowModeForFlow` 并存：run-role 的 `workflowMode` 常量优先级最高 ⇒ fixed 聊天（含无
  taskId）注入 fixed 模块 context/`chief-workflow-v2.md`/fixed 工具面；legacy/single 不传该键
  （常量 legacy 会吞掉混合项目 per-flow 判定，故不做无条件传入），旧注入面逐字不变。
- 投递目标自动打开（`routeFixedPathDispatch` 之后的 `openInternal`，无 taskId）注释同步：首个
  stage-request 已先写回 `workflowSchema` ⇒ 目标会话经聊天入口解析为 fixed（原 B5 注记的
  「自动以 legacy 注入打开」缺口随之修复）。

### 2.3 首个 stage-request 启动顺序（核验，无顺序修改）

`routeDispatch` 既有 B3 逻辑：`resolveFixedPathMode` 为 legacy 且来源为幕僚、`taskKind==="stage-request"`、
`workflowPath` 存在、非 stop、启用闸未开 ⇒ 先 `ensureFixedPathStarted`（原子写
`workflowSchema:"two-fixed-paths/v1"`，显式 legacy 不覆盖；失败 fail-closed）再按复核模式路由。
新测试证明空项目（无 `.ans/project.json`）首个 stage-request 即走 fixed（workflow.started、只读任务、
无 runId、不写 `.ans/runs`），且 legacy 在飞 run 的 flow 不被覆盖。**本批未改路由顺序**。
