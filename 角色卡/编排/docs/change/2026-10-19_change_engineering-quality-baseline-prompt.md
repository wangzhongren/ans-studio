# 2026-10-19 变更：治理会话提示词注入工程质量基线

## 来源

客户 2026-10-19 批准产品改动（原话：「可以，按你说的改」）：

- 在治理会话提示词中加入**工程质量基线**；
- 要求验收前**真实启动应用演示**；未真实运行不得建议验收通过；
- 门禁引擎角色把同一基线写进五张内置治理角色卡（Lead / Draft / Crew / Steward / Proof），
  编排侧负责把基线注入**治理会话提示**（single/su 与 trio 两套），使模型在意图、提案、流程、验收
  各阶段都受约束。

基线全文（与客户原文逐字一致；门禁引擎角色卡侧同一份文案由其常量承载）：

```
工程质量基线（默认生产级；客户明确选原型档才可放宽）：
- 正确性：验收标准逐条可演示；无 TODO/占位/假数据；边界与非法输入有明确行为。
- 健壮性：输入校验与上限、错误码一致、失败不破坏已有数据；持久化原子写与重启恢复；并发/重入有明确策略。
- 安全：认证/授权即使简化也要写清边界；防注入/XSS/路径穿越/CSRF；不记录密钥与敏感数据；零第三方依赖时说明理由。
- 可维护性：模块边界清晰、命名一致、只在约束处注释；README 含启动、架构、API、权限、状态机、已知限制与权衡。
- 可观测性：关键失败可诊断（结构化日志/错误信息），不静默吞错。
- 性能与容量：分页/上限/超时明确；不无限增长；给出已知容量边界。
- 前端：加载/空/错误态齐备；键盘可用、标签与对比度等基本可访问性；窄屏可用。
- 测试：单元+集成+端到端矩阵；权限与非法路径必须有负例；测试独立于实现；不得为保绿弱化断言。
- 交付：验收前必须真实启动应用并演示（启动命令、访问地址或截图/录屏）；未真实运行不得建议验收通过。
```

## 规则（编排侧口径）

1. **逐字复制，不跨层导入**：基线常量在本层复制一份（`ENGINEERING_QUALITY_BASELINE`），注释与门禁引擎
   `src/common/门禁引擎/governance-roles.ts` 的角色卡文案互指；不得导入其他角色私有 common。
   改文案时两处必须同步。
2. **两套治理提示都追加基线**：`buildGovernPrompt` 的 single/su 三个返回分支与 trio 返回均追加；
   trio 顺序为「角色纪律 → 质量基线 → shell 审批档」。
3. **阶段约束显式化**：
   - Lead（liaison）意图阶段：确认质量档位（默认生产级；客户明确选原型档才可放宽），
     并在意图文件 `acceptance` 中写明档位与放宽项，不得自行降档；
   - Draft（proposal）提案：必须含「工程质量基线」与「证据计划」（逐条落实/验证、真实启动演示）；
     证据计划缺失不得建议 accept；
   - Steward（schedule）派发/流程：流程单与派发任务携带质量与演示要求；未真实运行的交付不得写
     「已完成」或「可验收」；
   - Proof（verification）验收：逐项核对基线并给出证据；交付未被真实启动并演示时不得建议 accept，
     只能建议退回或补充证据；仅有测试输出或代码阅读不算演示。
   - single/su 由 `ENGINEERING_QUALITY_STAGE_REQUIREMENTS` 一句覆盖同一阶段要求。
4. **只改提示词，不改工具/门禁判定**：`run-role.ts` 不参与治理会话提示组装（经核查：
   `openGovernanceSession` 仅把提示透传，默认提示唯一组装点是 `govern-session.ts::buildGovernPrompt`），
   本批未改 `run-role.ts`，未动任何工具注册、写入门禁、派发/验收判定。

## 残余风险

- **提示词是行为约束，不是机械门禁**：基线只写入提示词，模型仍可能不遵守；真正的验收卡由
  Proof 核对 + 客户/判断 agent 决定，本批未新增任何自动验证基线完整性的门禁。
- **桌面 su 聊天不经过本提示**：桌面聊天直接走 `openRoleSession` + 用户消息（`session.ts:1820` 注释），
  不调用 `buildGovernPrompt`；桌面侧的基线覆盖依赖门禁引擎五张角色卡（内置角色 `cardText`）。
  CLI `ans govern` 与任何经 `runGovernSession` 的前端才使用本提示。
- **两处文案漂移**：编排常量与门禁引擎角色卡常量是两份物理副本（分层禁止跨角色导入私有 common），
  只能靠注释与评审同步；建议后续由测试角色加跨文件逐字比对（本批未越界新增）。
- **既有断言强度**：新增断言钉住关键字与关键句，不断言整段逐字文本；基线内部条目被删改时，
  只有标题句与「未真实运行…」句会被钉住。
