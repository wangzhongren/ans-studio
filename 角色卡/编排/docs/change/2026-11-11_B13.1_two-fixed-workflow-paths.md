## 二、实现

### 2.1 `prepareIntent`：A3 卡呈现前置 fail-closed（`src/common/编排/workflow-service.ts`）

- 活动 workflow 缺失 ⇒ `workflow-not-found`（A3 卡无法绑定，不发卡）。
- workflow 已关闭 ⇒ `workflow-closed`。
- **A3 在办**（当前阶段 A3，状态 requested/dispatched/in-progress）⇒ 仍返回意图证据（B12.1 幂等判定 / pending-recovery 复核用），但不重复写 `stage.requested`。
- 其余情况：当前阶段 blocked ⇒ `stage-transition-invalid`；当前阶段不是 **A2 completed**（或不能推进 A3）⇒ `stage-transition-invalid`，消息含 `当前 A2(requested)；要求 A2 completed`。**不写任何 workflow 事件、不返回可发卡证据**。
- 细节：blocked 判定按**当前阶段 status**（`view.stages[view.stage].status === "blocked"`），不按历史 `view.blocked` 字段——投影的 `stage.blocked` 不会被 `stage.requested/completed` 清除，RR8 恢复路径（A2 blocked→request→completed）后旧 code 残留不得误拦 A3。
- A2 completed ⇒ 补记 `stage.requested A3`（沿用原幂等键 `stage-request:<wf>:A3:1`）后返回证据。

### 2.2 `closeTask`：阶段完成与阻塞恢复（同文件）

- **完成判定（accepted）**：
  - 阶段内**不得有未收口兄弟任务**（open sibling 仍阻塞完成，避免完成时仍有任务可改产物；stage-request 任务不参与，v1.3 §4.2 说明）。
  - **A11/B3**（v1.3：全部选中实现任务 accepted）要求其余已收口任务均 accepted；`rework` 视为被新 attempt 取代、不再阻塞（修复 RR8 式死锁与 A11 返工死锁）；`rejected` 仍阻塞（缺一次 accepted 重派）。
  - **A2/A5/A12a/A12b/B1**：本 accepted 任务 + 应用证据即可完成（v1.3 §4.5：创建者 task.closed accepted + 文档/hash 可算 ⇒ stage.completed），不再要求历史兄弟任务全部 accepted。
- **阻塞判定**：只有阶段**仍在办**（`view.stage === stage` 且 status ∈ requested/dispatched/in-progress/blocked）才写 `stage.blocked`；阶段已完成/已推进后迟到的旧兄弟任务 rework/rejected 收口只写 `task.closed`，不再追加 blocked（否则投影会因 blocked 阶段 ≠ 当前阶段判 `workflow-corrupt`）。
