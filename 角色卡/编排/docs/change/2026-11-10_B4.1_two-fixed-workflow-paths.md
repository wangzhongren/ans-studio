### 2.1 `src/common/编排/shell-gate.ts`（M）：任务级 Git 分类 + 审计 + 提交门执行器（AC-21/T-09）

- **分类器注入（加法）**：`CreateShellGateOptions.classifyShellDetailed?: ClassifyShellDetailedFn` +
  `taskGitScope?: TaskGitScope`（`ShellGateBuildDeps`/`buildShellGate` 同透传）。给出明细分类器时
  **优先于** 2 参 `classifyShell`，并以 `{ taskGitScope }` 作为第三参调用；两者都未注入才落既有
  `no-classifier` fail-closed。**2 参旧调用逐字不变**（v5 规则层无 scope ⇒ `git add`/`git commit` 恒拒）。
- **分类明细加法**：`ShellClassifyDetail` 增 `code?`/`taskGit?`（门禁引擎 `ShellVerdict` 结构可注入；
  旧读者忽略）。run-role 生产通道把 `classifyShellDetailed` 包进既有 `classifyShell` 位（见 2.3）。
- **审计加法**：分类明细的 `taskGit` 经**白名单投影**（有界字符串/路径数组、argvDigest sha256）暂存
  （按请求对象的 `WeakMap`），审计行追加 `taskGit`——**允许与拒绝都记**；既有字段
  （`command/argv/cwd/conclusion/branch/by/conditions/execution/entry/...`）不减少、不改写。
  非法 `taskGit` 形状 ⇒ 该行不追加（不放大任意注入对象进审计）。
- **任务级 Git 提交执行器（新增导出）**：`createTaskGitCommitRunner({scope, port})` 把注入端口绑定到
  门禁引擎 `runTaskGitCommit`：scope/argv/分支 → **取项目级临界区**（占用 ⇒ `git-critical-section-busy`，
  不排队）→ **同一锁内**固定 argv `TASK_GIT_STAGED_INSPECTION_ARGV`（`git diff --cached --name-only -z`）
  检查 staged ⊆ writeSet → **同一锁内**固定 commit argv → `finally` 释放。**不得在锁外先检查后提交**。
- **只读档构造期守卫（新增 #8）**：`readonlyOnly === true` 同时注入 `classifyShellDetailed`/`taskGitScope`
  ⇒ 抛错拒绝装配（v5 任务级 Git 写不得越过 `readonly-deny`；只读档只映射 (c) 白名单）。
- 本闸**只做分类与审计**；`commit` 的实际执行由执行路径（2.3 的 `ReadonlyGitCapability`）在 spawn 前
  调用上述执行器（任务分工见 §二-2.3 与 B4 记录 §五-4）。
