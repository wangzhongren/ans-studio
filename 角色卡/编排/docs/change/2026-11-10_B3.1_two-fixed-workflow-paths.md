## 6. 限制与披露

1. **双写幂等**：fixed A3 的 `prepareIntent`/`finalizeIntent` 同时存在于 run-role（本批）与桌面 B3
   `withRequestLifecycle`（既有）。二者均幂等（`stage-request:<wf>:A3:1` / `stage-complete:<wf>:A3:<requestId>`），
   但卡 preview 可能出现**重复 marker**（run-role 与桌面各追加一次；纯展示、不影响校验）。桌面 B3.1
   可自行决定是否去掉本层重复追加（非阻塞）。
2. **A10 在办标记归属**：本批在 run-role 呈卡前写 `stage.requested A10`（补齐状态机缺口）；桌面 B3
   既有 `recordFixedCardWorkflowResolution` 消费它完成 `stage.completed A10`。若桌面 B3.1 另行实现该标记，
   必须复用同一幂等键，避免第二次 `stage.requested A10` 被判非法转移。
3. **CLI/无应用通道**：fixed A3 的 `request.resolved` 写入方是应用通道（桌面 `withRequestLifecycle`）。
   无 request 事件的通道（CLI）⇒ `finalizeIntent` 失败并如实 pending-recovery（与 legacy 冻结失败同语义），
   不静默通过、不伪造决定。
4. **fixed 任命卡不套用 legacy D3 规则**：env-bootstrap 标准角色/`nominator` 模块 preflight 只在 legacy
   分支执行；fixed 结构口径与桌面 B3 `prepareFixedAppointmentCardRequest` 一致（选项/多选/名单顺序）。
