# 2026-10-19 变更：shell 判断提示加入读取纪律（定点抽查，预算耗尽如实 manual）

## 问题

真机中，Proof 复核连续运行 shell 时，判断 agent 多次自行读取项目文件，最终报「读取预算已用尽」，整条命令回落手动确认。判断本身需要的往往只是「这条命令是否直接服务当前任务」，而模型把读取用于「了解项目」，把有限预算（调用次数/单文件 64KiB/总量 192KiB）消耗在与必要性无关的文件上。

运行时核心正在把读取预算做成可配置（`ANS_SHELL_JUDGE_MAX_*`），但编排侧的系统提示仍只写了「工具会被拒/截断」，没有告诉判断 agent **如何节省读取**。本批只改提示词：规则层、审批语义、工具面（仍恰为 `judge_read_file` / `judge_list_dir` / `report_shell_judgement`）均不变。

## 改动

`src/common/编排/shell-judge-prompt.ts`（系统提示，稳定单一来源）：

1. **工具描述补范围参数**：`judge_read_file` 一行注明可用 `offset/limit`（字节）或 `startLine/endLine`（行）定点抽查，两种模式二选一（运行时核心已支持，此处只做提示）。
2. **新增【读取纪律——先判命令，再定点取证】**：
   - 判断依据首先是命令原文、规范化 argv、cwd、来源档位与当前轮任务文本；读取只在必要性缺证据时进行，不要为了「了解项目」通读源码；
   - 先 `judge_list_dir` 了解结构（只列一层），只读与「这条命令是否必要」直接相关的文件；不做全项目扫描；
   - 大文件用 `judge_read_file` 的范围参数**定点抽查**，不整文件反复读；
   - 不读 `data/**`、`*.log` 日志、构建产物（`dist/`、`build/`、`coverage/`、`node_modules/` 等）、会话/审计目录；除非命令本身直接操作它们且必须核对内容；
   - 同一文件不要重复读取；已读过的同一路径视为已知，不要换范围重复灌入；
   - 命令是本地服务的 curl/测试脚本时，优先依据命令、cwd、argv 和角色任务上下文判断；不要为了「了解项目」通读服务源码或测试源码；
   - 读取预算耗尽仍无法判断时，如实交回 `manual`（reason 写明预算耗尽），不得猜测未读取的内容，更不得据此 `allow`。

既有 rubric、deny 档特殊规则、不可信数据警告、输出契约、手动/拒绝语义逐字未动；`shell-judge.ts` 的读取损伤降级（budget → `manual/budget`）与防循环逻辑未动。

## 边界与残余

- 只写 `src/common/编排/shell-judge-prompt.ts`、`test/编排/shell-judge-read-discipline.test.ts` 与本角色文档；未碰 `app/**`、其他角色文件、运行时核心、适配器与 git 历史。
- 提示只能引导，不能强制：判断 agent 仍可能超读；真正的硬约束是运行时核心的读取预算与「读取损伤 → allow 降 manual」。本批不改变该兜底。
- 预算可配置项（`ANS_SHELL_JUDGE_MAX_*`）在运行时核心落地后，本提示无需再改（提示不写具体数值，避免与可配置默认值漂移）。
