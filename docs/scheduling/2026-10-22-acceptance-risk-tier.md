## 一、任务目标与风险档位

### 1.1 目标

把「独立验收必须先判断风险档位（T0–T3）」写成项目正式约束：在 `角色卡/项目管理/docs/project-rules.md` §二「已确认要求」新增第 9 条，并在「变更记录」追加 2026-10-22 条目。规则生效后，统筹交验收的每个变更包都要标注档位；独立验收先核对档位是否与改动相符并记录，再决定证据与检查强度。

### 1.2 风险档位：T3（治理文档变更）

依据技能 `references/testing.md`「Risk-Based Verification and Change Packages」：

- T3 包含 **governance or permission change**（治理或权限变更）；
- 该参考明确 **"Governance or permission changes are T3, never T0, even when the edited files are documentation."**

本任务修改的是全项目工程法案，属于项目共同治理约束；即使只改文档、没有代码面，也必须按 **T3** 标注，不得为省检查压到 T0。**本任务自身没有适用回归可跑**（不改代码、测试或构建，无代码面）；验收按 T3 记录档位与全量回归 N/A 理由，不虚构测试。

## 三、五维判断与决策

| 维度 | 判断 | 依据 |
| --- | --- | --- |
| 1. 责任独立性 | 无新增独立责任 | 工程法案维护是现有项目管理 worker 的既有职责；验收判断是内置独立验收的职责，两者本就分离 |
| 2. 范围归属 | 现有 owner 精确覆盖 | `角色卡/项目管理/boundary.md` Section 1 单文件条目 + `boundary.yaml` 同条；`docs/acceptance/` 是内置验收默认范围；无缺口、无重叠 |
| 3. 契约影响 | 无 | 不改公开契约、共享抽象、数据模型或接口；规则引用技能 `testing.md` 的既有档位定义 |
| 4. 证据独立性 | 已满足 | 独立验收在独立上下文判定；实施者不自验；无代码面，不需要独立测试角色 |
| 5. 协调成本 | 最低 | 一个 worker + 一个内置验收，顺序执行；新增角色/人事/测试角色只增加成本 |

**决策表结果：不变，派给现有角色。** 无新角色、无边界修改、无拆分/合并；角色不变仍按闸门 2 确认参与角色、范围和写集。

### 考虑过的选项

- **A（采用）**：现有项目管理 worker 改工程法案 + 内置独立验收判定。最小改动，符合闸门 0 已确认落点。
- **B**：改 `角色卡/独立验收/role-card.md`。否决：触发角色定义变更，需人事改卡与额外的闸门 2 角色变更；闸门 0 已确认落点为工程法案。
- **C**：新增专门角色。否决：一次性治理文档修改属临时工作；决策表要求不建角色，协调成本大于收益。
- **D**：由现有 `角色卡/独立验收` worker 承担判定。否决：会与内置独立验收形成同一候选的双重验收；且该卡写入范围是 `角色卡/独立验收/docs/`，与本任务指定的 `docs/acceptance/` 不一致；其是否迁移是闸门 0 选择 A 下另行的迁移决策，不在本任务自动执行。
