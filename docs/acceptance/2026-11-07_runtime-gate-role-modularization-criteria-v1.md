## 4. 判定规则

- 每条只用 `pass / fail / insufficient evidence / not applicable`。
- **pass**：当前阶段候选上，该条目的全部观察有完整、可复算的原始证据，候选/契约/写集/环境一致，且阶段前置满足。
- **fail**：原始证据表明该条目不满足（含门禁语义被放宽、unknown 冒充 observed、应用中介证据进入写/发布门、Codex 严格路径条件改变、跨角色 import、共享逻辑复制、一次性替换、切换未验证即删旧实现、死代码扫描范围外误删、删断言/加 skip/放宽、候选与证据不符）。
- **insufficient evidence**：缺候选/哈希、缺原始输出、命令/环境/退出/计数不全、证据过期/跨阶段混证、关键门/账本/证据被 mock、真实运行预算/中止未记录、扫描范围未限定、删除清单缺失、终态 unknown 未如实记录等。
- **not applicable**：仅限已有明确范围依据的条目，且必须在 B2 引用依据（例如：`typecheck:renderer` 在未触及渲染层时；X-S 共享抽取单元在 E0 确认不迁移时；真实 Pi/Codex 模型运行按 Q11/团队计划 §8.3 默认不跑时；O1/O2 等选装未实施时）。**N/A 不等于 pass，也不得用 N/A 规避适用要求。**
- 不得按“工具退出 0”“团队自述”“模型自评”直接判 pass；不得以局部绿、watchdog 结束、空列表/closed/abort 猜停稳；不得拼接不同候选/环境/阶段的绿色结果。
- 任一适用条目 fail 或 insufficient evidence，则阶段出口不通过；整体结论按 B2 报告的范围给 pass/rework/insufficient evidence。
